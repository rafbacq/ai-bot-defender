# `app/` — the control-center web app

The operator console for the whole system (branded **Duke WATCH** in the UI):
FastAPI + Jinja2 templates + Tailwind, served on `http://localhost:8000` by
`docker-compose.app.yml` (or `make app-dev` on the host).

## Layout

| Path | Role |
|---|---|
| `main.py` | All HTTP routes. The docstring at the top is a route index. |
| `config.py` | Paths, env-derived settings. |
| `services/` | Business logic, one module per concern: `sites` (deploy/stop/delete), `template_gen`, `request_log` + `fingerprint_service` + `graph_intel` (Crawler Analytics), `querying_service` + `auto_query_adapter` + `provenance_service` (LLM Forensics), `selfplay_service`, `monitoring_service`, `auth_service` + `totp_service`, `run_manager` + `task_service` + `job_catalog` (background jobs), `keys_service`, `logdb`, `stats`. |
| `templates/` | Server-rendered Jinja2 pages. `base.html` carries the nav; `analytics.html` (`/logs`) and `forensics.html` (`/query`) are the two merged pages. |
| `static/` | `css/app.css` (hand-written) + `css/tailwind.css` (generated by `make frontend-css` — do not edit). |
| `requirements*.txt` | Layered image deps — see "Dependency layout" in [docs/DEVELOPMENT.md](../docs/DEVELOPMENT.md). Keep `requirements.txt` byte-stable. |

## Things to know before editing

- The container runs **Docker-out-of-Docker** with the repo bind-mounted at the
  same absolute path inside and out, so it can run `docker compose` and
  `ansible-playbook` against the host daemon. Code edits need no rebuild;
  Dockerfile/requirements changes need `make app-build`.
- Call `templates.TemplateResponse(request, "name.html", {ctx})` — request
  first. The legacy argument order silently 500s.
- `services/sites.py`'s shared ruamel `YAML()` is **not thread-safe**; always
  go through `_yaml_load`/`_yaml_dump` (they hold `_yaml_lock`).
- Long-running actions run on server-side workers and are polled by the
  browser; see "Background jobs" in [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md).
- Authentication and the admin panel are documented in
  [docs/AUTHENTICATION.md](../docs/AUTHENTICATION.md).
