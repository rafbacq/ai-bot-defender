HOW TO READ THIS DOCUMENT
-------------------------
This is a teaching document. The goal is that after reading it you can open ANY
file in this repository and explain what every block of code does, why it exists,
how it interacts with the rest of the system, and what would break if you changed
it. It is organized in PARTS, one per architectural layer, plus cross-cutting
"deep dive" sections that trace a single request or a single SQL query end to end.

Within each file the explanation is ordered top-to-bottom, matching the source, so
you can read the file and this document side by side.

Terminology used throughout:
  - "honeypot" / "site"     a single deployed Flask website that serves canaries.
  - "canary" / "canary set" the 10 fabricated facts (var1..var10) served to a
                            visitor; a leaked canary set is the detection signal.
  - "visitor" / "endpoint"  a unique source identity. The honeypot keys visitors by
                            the device cookie (__abd_fp / fp_id) when present, else by
                            (User-Agent, ASN); the crawler-graph keys them by IP.
  - "campaign"              a cluster of IPs the crawler-graph believes is one actor.
  - "logdb"                 the central Postgres in the proxy stack (all_visits etc).
  - "the four fingerprint layers":
        Layer 1  browser JS    (canvas/WebGL/audio/fonts/automation) -> browser_fingerprints
        Layer 2  TCP/IP SYN    (TTL/window -> OS guess)              -> tcp_fingerprints
        Layer 2  TLS ClientHello (JA3/JA4)                           -> tls_handshakes
        Layer 2b HTTP headers  (JA4H, computed from stored headers)
        Layer 3  cross-layer consistency (the contradiction engine)

 PART 0 — SYSTEM ARCHITECTURE & THE END-TO-END REQUEST LIFECYCLE
================================================================================

0.1  WHAT THE SYSTEM IS
-----------------------
AI Bot Defender is a research platform for studying and defending against AI
scraper bots (the crawlers LLM providers use to harvest web content). The core
defensive idea is a honeypot website seeded with canary tokens: each unique
visitor is served a page containing uniquely generated fake facts (names, cities,
institutions, years). If those fabricated tokens later surface inside an LLM's
output, you have evidence that a specific scraper ingested the page.

The system is built to run MANY independent honeypot sites at once, each a
self-contained Docker Compose stack, all sitting behind one local nginx reverse
proxy that does host-based routing and centralized cross-site request logging.

There are two fundamentally different questions the platform answers, and they are
implemented by two independent subsystems that you should never conflate:

  (A) "Did a specific LLM ingest my page?"   -> the querying/ pipeline.
      It scrapes a honeypot page, probes target LLMs with adversarial prompts,
      extracts entities from their answers, and measures Jaccard overlap with the
      page's stored canary tokens. High overlap = the model regurgitated content
      it could only have if it trained on (or browsed to) the page.

  (B) "Who is crawling me, and are they hiding what they are?" -> crawler_graph/.
      It fuses four fingerprint layers per visitor, clusters IPs into campaigns,
      and flags campaigns that disguise themselves (undeclared infra on browser
      UAs, agentic browsers, device fingerprints reused across rotating proxies,
      kernels that contradict the claimed OS).

0.2  THE SEVEN COOPERATING LAYERS
---------------------------------
  website/            The Flask honeypot. One route, GET /. Assigns + serves
                      canaries, logs every visit to a per-site Postgres.
  ansible/            Renders a per-site Docker Compose stack + a per-site nginx
                      server block from templates, brings the stack up, reloads
                      nginx. Merges per-site overrides over global defaults and
                      validates port uniqueness.
  proxy/              A single nginx (the only exposed entry point), three FastAPI
                      collectors (request mirror, JS-fingerprint beacon, Zeek
                      shipper), a Zeek passive-capture sidecar, and the central
                      logdb Postgres.
  app/               The FastAPI + Jinja2 + Tailwind web UI (five top-nav pages).
                      Drives deployment, reads the logs, runs querying + intel.
  querying/          The LLM detection pipeline + Direction 6b provenance
                      (timeline dating, membership inference, RAG disambiguation).
  crawler_graph/     The campaign-clustering intelligence engine + the GraphSAGE
                      GNN provider-attribution model.
  template_generator/ The data-preparation, LoRA-training, and page-authoring code.
                      Its CLI writes beneath template_generator/; the app integration
                      deliberately copies successful HTML into website/templates/.

0.3  THE MULTI-SITE DEPLOYMENT MODEL
------------------------------------
Each site has a site_id (e.g. site-001). The deploy flow is:

  configs/sites/<id>.yaml         (per-site overrides, written by the web app)
        + ansible/group_vars/all.yml   (global defaults)
        |
        v  ansible-playbook site.yml -e site_id=<id>   (merges overrides on top)
        |
        +-> renders website/sites/<id>/docker-compose.yml   (from a .j2 template)
        +-> renders proxy/conf.d/<id>.conf                  (from a .j2 template)
        |
        v  docker compose up -d --build   (one isolated stack per site)
        +  docker exec proxy-nginx nginx -s reload   (pick up the new route)

Because each site is a separate stack, website.port and database.host_port MUST be
unique per site. The playbook actively validates this and aborts on a collision —
it is the single most common source of deploy failures.

0.4  THE TWO LOGGING PATHS (run in parallel)
--------------------------------------------
  1. nginx access_log (JSON "siteaccess" format, includes the scheme field)
        -> /var/log/nginx/dukecodeplus.access.log inside the nginx_logs volume.
     Unmatched/scan traffic goes to unmatched.access.log instead.
  2. nginx mirror /_mirror -> collector:8000 -> logdb table all_visits
        (site, client_ip, client_port, user_agent, method, uri, headers jsonb, ts),
        tagged per site via the X-Site header. ONLY matched (real-site) requests
        are mirrored — the catch-all server neither proxies nor mirrors.

0.5  THE END-TO-END REQUEST LIFECYCLE (high level; PART 10 traces it line by line)
---------------------------------------------------------------------------------
A bot makes one HTTPS GET to a honeypot hostname. Step by step:

  1. TCP SYN arrives at the host on :443. The Zeek sidecar (sharing nginx's
     network namespace) sees the raw SYN and logs TTL/window/MSS/etc to tcp_syn.log.
  2. TLS handshake. The bot sends a ClientHello. Zeek sees the raw ClientHello
     BEFORE nginx terminates TLS and logs JA3/JA4 to ssl.log. nginx selects the
     wildcard cert by SNI and completes the handshake.
  3. nginx routes by Host header. If the Host matches a per-site server block, the
     request enters that block. If not, it falls to the default catch-all server,
     which returns 444 (drop) and neither proxies nor mirrors. This is what keeps
     scan noise out of all_visits and out of the honeypots entirely.
  4. The per-site block does two things:
       a. mirror /_mirror -> collector -> INSERT into logdb.all_visits (with
          X-Site = canonical hostname, X-Client-Port = source port).
       b. proxy_pass http://<site_id>-web:8080 -> the Flask honeypot. nginx
          OVERWRITES X-Forwarded-For with the real client IP (never appends).
  5. Flask server.py:update_page runs:
       - resolves client IP (first XFF entry), hashes it, derives netaddr, ASN.
       - parses the UA.
       - ALWAYS inserts a new_visits row.
       - looks up new_agents_vars by the device cookie (__abd_fp / fp_id) when the
         browser sent one, else by (user_agent, asn):
           seen before -> reuse stored var1..var10, view_count += 1 (a device keeps
             ONE canary set across UA/IP/ASN rotation).
           new + genmode -> generate a globally-unique canary set, store it (with fp_id).
           new + nogen   -> serve "Null", store nothing.
       - renders scraper{N}.html with the 10 vars.
  6. The HTML returns to the bot. Every currently checked-in scraper1..5 template
     contains <script src="/js/fp.js" defer>. (See PART 22 for the current generator
     omission that can break this invariant for a newly installed flavor.) If the
     visitor runs JS (a browser / agentic browser), fp.js computes the
     Layer-1 fingerprint and POSTs it to /__fpbeacon, which nginx routes to the
     fp-collector -> logdb.browser_fingerprints. A non-JS scraper never beacons,
     and that ABSENCE is itself a signal the analytics layer reads.
  7. Asynchronously, the tls-shipper tails ssl.log + tcp_syn.log and inserts into
     logdb.tls_handshakes and logdb.tcp_fingerprints (keyed by the (ip, port)
     4-tuple so each handshake/SYN joins the requests its connection carried).

Everything downstream (analytics, campaigns, provenance) reads logdb. The querying
pipeline reads the per-site DB (new_agents_vars) for ground-truth canaries.


================================================================================
 PART 1 — THE HONEYPOT WEBSITE  (website/)
================================================================================

This is the thing bots actually hit. Each deployed site is its own Docker stack:
a "web" Flask container + a "db" Postgres container. The whole detection premise
lives here: stable-per-visitor, unique-across-visitors canary tokens.

--------------------------------------------------------------------------------
 1.1  website/server.py  — the Flask honeypot (THE detection core)
--------------------------------------------------------------------------------
Single file, single route (GET /). Read it in five blocks.

BLOCK A — imports & module setup (lines ~1-36)
  - Standard Flask + SQLAlchemy 2 + psycopg2 imports.
  - Lines 6-12 import openai and construct OpenAI(api_key='null'). THIS IS DEAD
    SCAFFOLDING. Nothing in the request path uses the openai client. It is leftover
    from an earlier prototype; openai is still pinned in requirements.txt. If you
    are auditing the file and wondering where the "AI" call is — there isn't one;
    the honeypot is pure Flask + Faker + Postgres.
  - Faker is created as fake = Faker("en_US") and then EXTENDED with two providers:
        fake.add_provider(faker_edu.Provider)   -> gives institution_name()
        fake.add_provider(FoodProvider)          -> gives dish()/ingredient()/fruit()
    These are the only providers available to canary expressions beyond base Faker.
    If a canary expression in all.yml calls a provider that isn't loaded here, the
    eval() in gen_vars will raise.
  - app = Flask(__name__, static_folder='static', static_url_path='')
    The static_url_path='' is LOAD-BEARING: it makes /js/fp.js resolve to
    static/js/fp.js at the site root. scraper1.html references the fingerprint
    script as "/js/fp.js"; if static_url_path were the default "/static", that
    reference would 404 and Layer-1 fingerprinting would silently never happen.

BLOCK B — configuration & the SCRAPER_VERSION indirection (lines ~38-59)
  - DB_USER / DB_PASS come from env (default "null").
  - SCRAPER_VERSION = int(os.environ.get("SCRAPER_VERSION", 1)).
    This single integer selects a whole "flavor" in lockstep across THREE places:
        website/varLists/scraper{N}.txt    (the 10 canary expressions)
        website/templates/scraper{N}.html  (the page rendered to visitors)
        the Postgres database name scraper{N}-db
    It must NEVER be a hardcoded literal. The Ansible configure role even rewrites
    this exact line in server.py with a `replace` task to guarantee the env-var
    form survives — so if you hardcode it, your value is silently reverted on the
    next deploy. The commented "#SCRAPER_VERSION = 1" on the line above is a relic.
  - DATABASE_URI has two branches:
        if PORT is set (Cloud Run): a Cloud SQL unix-socket DSN.
        else (Docker/local): postgresql+psycopg2://USER:PASS@DB_HOST:5432/scraperN-db
    The Docker branch is the one that runs. DB_HOST is "db" inside the site stack
    (the compose service name); the comment "most cases this should be 5432" refers
    to the port, not the host.
  - engine = create_engine(DATABASE_URI); Session = sessionmaker(bind=engine).
    The commented-out sqlite engine below is the old local-dev path.

BLOCK C — the two ORM tables (lines ~65-104)
  class UserAgent  -> table "new_agents_vars"
    One row per unique visitor. Columns: id, browser_family, user_agent, view_count,
    var1..var10, asn, hashed_ip, last_visited, ip_netaddr, fp_id (the __abd_fp device
    cookie; added by an additive ALTER TABLE ADD COLUMN IF NOT EXISTS at startup).
    THIS is the table that makes canaries stable per visitor — a returning device
    (matched by fp_id, else by (user_agent, asn)) reuses its stored var1..var10. It is
    also the ground-truth table the querying pipeline reads (ground_truth.load_site_rows).
  class Visits  -> table "new_visits"
    Append-only log of EVERY request. Columns: id, browser_family, user_agent,
    browser_version, os_family, os_version, device_family, is_mobile, is_tablet,
    is_pc, asn, ip_netaddr, hashed_ip, timestamp (defaults to datetime.utcnow).
    This is the per-site raw visit log; provenance.crawl_times reads it to derive
    each visitor's first/last "mint" time.
  Base.metadata.create_all(engine) on import auto-creates both tables on boot.
  IMPORTANT consequence: importing server.py opens a DB connection and creates
  tables. That is why the test suite does NOT import server.py directly — it
  re-implements update_page's contract in-memory (see PART 8) and calls the real
  generators/parser instead.

BLOCK D — the canary machinery (lines ~106-170)
  gen_vars(var1=..., ..., var10=...)
    Takes 10 STRING expressions, runs str(eval(expr)) on each with `fake` in scope,
    returns a list of 10 stringified fake facts. The defaults in the signature are
    illustrative only; in practice set_vars passes the real expressions from the
    varList. The eval() is deliberate and trusted — the expressions come from
    all.yml (rendered into the varList), never from a client. The print(fake_data)
    is debug output.
  get_client_ip()
    Returns the FIRST X-Forwarded-For entry if present (split on comma, take [0],
    strip), else request.remote_addr. SECURITY-LOAD-BEARING: it trusts the first
    XFF entry, which is only safe because nginx OVERWRITES XFF with $remote_addr
    (never appends $proxy_add_x_forwarded_for). If nginx appended, a bot could send
    its own X-Forwarded-For: <victim-ip> and the honeypot would attribute the
    canary set to the victim's IP.
  set_vars(session, max_attempts=10000)
    1. Reads the first 10 lines of varLists/scraper{N}.txt (the generated
       expression list).
    2. Loops up to max_attempts: gen_vars(*var_list) -> a candidate 10-tuple, then
       queries new_agents_vars filtering on the exact var1..var10 tuple. If no row
       matches, the set is globally unique -> break.
    3. On a collision it enters a loop that regenerates ONE var at a time and
       rechecks. However, `break` exits only this INNER var loop; there is no flag or
       outer `break`. Even if the partially changed tuple becomes unique, the next
       outer iteration immediately discards it and calls gen_vars for a new full tuple.
       Therefore the partial-regeneration block currently adds queries/work but cannot
       be the tuple returned by the normal success path. Only a whole freshly generated
       tuple that was unique on its first check exits the outer loop.
    4. If it exhausts attempts, logs a warning and calls gen_vars one last time WITHOUT
       checking that last tuple, accepting a possible duplicate.
    The point is GLOBAL UNIQUENESS of canary sets, so a leaked set maps to exactly
    one visitor row.

BLOCK E — the request handler update_page(session, genmode, full_ua=False) (171-326)
  This is the entire honeypot behavior. Step by step:
  1. user_agent = request.headers.get('User-Agent'); client_ip = get_client_ip().
  2. hashed_ip = sha256(client_ip) hex; ip_netaddr = IP minus last segment
     (IPv6: drop last hextet via ':'.join(split(':')[:-1]); IPv4: '.'.join(
     split('.')[:-1]) -> the /24). This mirrors crawler_graph.enrich.netblock.
  3. ASN lookup: IPWhois(client_ip).lookup_rdap() -> res.get('asn'). Wrapped in
     try/except; a lookup failure leaves asn=None and prints the error. (For
     private/loopback IPs RDAP fails, so local testing produces asn=None.)
  4. UA parse via parse_user_agent (the helper module). On success it fills
     browser_family/version, os_family/version, device_family, is_mobile/tablet/pc
     (stringified). On failure browser_family falls back to the raw UA string.
  5. ALWAYS construct a Visits row and session.add + commit. Every request is
     logged to new_visits regardless of genmode or seen-before status.
  6. DEVICE-FIRST canary lookup (stable canaries across disguises):
       a. fp_cookie = request.cookies.get('__abd_fp'). fp.js stores the composite
          device fp_id in this cookie once it runs, so a returning browser carries
          it even after it rotates its User-Agent, exit IP (a browser VPN), or ASN.
       b. entry = query(UserAgent).filter_by(fp_id=fp_cookie).first() when the
          cookie is present — this recognizes the SAME physical device regardless of
          the identity it currently claims, and serves it the SAME canary set.
       c. Fallback: if no device row matched, entry = query.filter_by(
          user_agent=user_agent, asn=asn).first() (the classic keying). The very
          first visit had no cookie (fp.js sets it only after it runs), so that row's
          fp_id is null; the first time we then see the cookie we BACKFILL it onto
          that row, binding the device to its canary set for later rotations.
       - If entry (SEEN BEFORE): copy its var1..var10 into locals, increment
         view_count, refresh asn/hashed_ip/ip_netaddr/last_visited, commit. The
         canaries are reused -> stable per device/visitor.
       - Else NEW visitor:
           if genmode: var1..var10 = set_vars(session) (a fresh unique set), build a
             new UserAgent row (fp_id = fp_cookie, may be null), add + commit.
           if not genmode: set every var to the string "Null" and store nothing.
     Why: because one physical device now keeps ONE canary set across every identity
     it wears, a single canary set surfacing under several User-Agents/ASNs is the
     DISGUISE signal (and a leaked set attributes to one device, not N fragments).
     Non-JS scrapers never set the cookie, so they keep the pure (user_agent, asn)
     keying — unchanged. The new_agents_vars.fp_id column is added by an additive
     ALTER TABLE ... ADD COLUMN IF NOT EXISTS at startup (create_all never ALTERs an
     existing table). (The large commented block that always re-inserted a fresh row
     is an earlier approach; ignore it.)
  7. session.close(); return render_template(f"scraper{N}.html", user_agent=...,
     seen_before=..., var1=..., ..., var10=...).
  Note genmode is passed in from the route; full_ua is unused vestigial.

BLOCK F — the route + main (lines ~328-341)
  @app.route('/', methods=['GET']) def index():
    genmode defaults True; becomes False if sys.argv[1] == "nogen" (i.e. the
    container was started as `python server.py nogen`, which the compose template
    injects when website.genmode is false). Opens a Session and calls update_page.
  __main__: app.run(host="0.0.0.0", port=8080, debug=False).
  There is exactly ONE route. There is no /admin, no API, no POST. The honeypot's
  entire surface is "GET / returns a page with 10 canary slots filled in".

--------------------------------------------------------------------------------
 1.3  website/templates/scraper1.html  — the canary-bearing page
--------------------------------------------------------------------------------
A fake Wikipedia-style biography of "Jennifer Balef". What to notice:
  - Line ~6: <script src="/js/fp.js" defer></script>. THIS is what embeds the
    Layer-1 browser fingerprinter on every honeypot page. Remove it and Layer-1
    fingerprinting disappears for that flavor.
  - <meta name="robots" content="index, follow"> deliberately invites crawlers.
  - The 10 {{ varN }} Jinja slots are woven into natural prose so the page reads
    like a real article AND so a leaked canary appears in a plausible context:
        var2 = birth city (reused for childhood/graduation so it recurs naturally)
        var3 = parent name; var4 = a city she moved to; var5 = her institution
              (reused as university + employer + venue); var6 = current residence;
        var7..var10 = titles in the "List of Notable Works" list.
    Reusing a var several times is intentional: it makes the fact look load-bearing
    to a scraper and increases the chance the model reproduces it.
  - Some text (e.g. "1902", "1924") is STATIC, not a canary. Those are not detection
    tokens; only the {{ varN }} slots are. The template generator (PART 7) goes to
    great lengths to convert such leaked static numbers into [[NUM]] placeholders so
    generated pages don't bake static numbers in — but this hand-written scraper1
    page simply has a few static years that are not used for detection.
  CURRENT CHECKED-IN FLAVORS (important when explaining the repository as it is now):
    scraper2.html is currently byte-for-byte the same page shape as scraper1.html.
    scraper3.html..scraper5.html are short generated, town-style pages with the town
    subject in var1 and overview/geography/population/landmark sections. They still
    load /js/fp.js and still expose only the standard var1..var10 Jinja interface.
  The configure role copies scraper1 -> scraperN only when scraperN does NOT already
  exist (`force: false`). It therefore scaffolds a missing flavor but never replaces
  an installed/generated one. Do not describe every scraperN as a copy of scraper1.

  CURRENT VARLIST CAVEAT: scraper1.txt..scraper5.txt presently contain the same ten
  global expressions rendered from all.yml. That contract is syntactically valid,
  but the generated town pages use some slots in numeric-looking contexts while the
  global list produces names/cities/institutions/surnames. The standalone generator
  does emit a type-aware scraper_gen_N.txt beside each HTML file, but the web install
  path copies only HTML and the next deployment overwrites scraperN.txt from all.yml.
  Consequently type-aware prose can become semantically awkward after deployment.
  This is a current integration limitation, not behavior to hand-wave away.

--------------------------------------------------------------------------------
 1.4  website/static/js/fp.js  — Layer-1 browser fingerprinter (~550 lines)
--------------------------------------------------------------------------------
A complete, dependency-free, industry-grade browser fingerprinter wrapped in a
single IIFE. It NEVER throws into the page (every surface is wrapped in safe()),
is fire-and-forget, and POSTs one JSON beacon to /__fpbeacon. The payload schema it
emits is the CONTRACT shared with proxy/fp-collector/app.py and
crawler_graph.ingest.enrich.attach_browser_fingerprints — change a field name here
and you must change it in both of those.

Design constants (top):
  BEACON_PATH = "/__fpbeacon"; SETTLE_MS = 1200 (grab a fingerprint even if the
  visitor never interacts).

cyrb53(str, seed)  (lines ~35-47)
  A compact, fast, DETERMINISTIC 53-bit string hash. Used to digest the
  high-entropy buffers (canvas pixels, audio samples, font sets) into stable hex
  client-side. SubtleCrypto is async/unavailable in some contexts and an exact
  device-keying hash only needs determinism, so a hand-rolled hash is the right
  tool. Two interleaved 32-bit state words mixed with Math.imul.

safe(fn, dflt)  — try fn(), return dflt on any throw. The reason a failure on one
  surface still yields a partial fingerprint.

canvasFingerprint()  (lines ~53-80)
  Creates a 280x60 canvas, probes the even-odd winding rule (distinguishes
  fill-rule implementations: rect+rect then isPointInPath(...,"evenodd")), draws
  styled text + an emoji + a unicode string in two fonts, then a linear gradient
  arc with globalCompositeOperation="multiply" (exercises more of the raster
  pipeline), and hashes toDataURL(). The output is a function of the GPU + driver +
  OS text-rasterization stack.

webglFingerprint()  (lines ~82-138)
  Gets a webgl context, reads UNMASKED vendor/renderer via the
  WEBGL_debug_renderer_info extension (falls back to the masked VENDOR/RENDERER),
  reads ~16 GL parameters (MAX_TEXTURE_SIZE, MAX_VIEWPORT_DIMS, etc — array values
  are sliced to plain arrays), the sorted extension list, AND a shader micro-
  benchmark: it compiles a fragment shader with a 128-iteration sin/cos loop, draws
  it 60 times, gl.finish(), and records the elapsed ms (shaderMs). That timing is
  characteristic of the GPU micro-architecture. Everything is hashed into webgl_hash;
  vendor/renderer/params/extensions/shaderMs are also returned raw (renderer feeds
  the VM-cohort detector downstream).

webgpuFingerprint(out, done)  (lines ~140-166)
  Async. If navigator.gpu exists, requestAdapter() -> adapter.info (vendor/
  architecture/device/description), features, numeric limits. A 600ms setTimeout
  guarantees it resolves (with null) so it can never block the beacon.

audioFingerprint(done)  (lines ~168-203)
  Builds a fixed OfflineAudioContext graph: a 10kHz triangle oscillator -> a
  DynamicsCompressor with every parameter pinned (threshold/knee/ratio/attack/
  release) -> destination. startRendering(), then on oncomplete it sums abs() of the
  rendered samples (audio_sample) and hashes a slice (samples 4500-5000) of the
  float output (audio_hash). A 500ms safety-net timeout. The output depends only on
  the audio DSP stack, so it is stable per device/browser build.

fontFingerprint()  (lines ~205-240)
  Classic width/height-delta font detection: render a probe string at 72px in three
  base families (monospace/sans-serif/serif), record the baseline metrics, then for
  each of ~40 probe fonts set "'Font',base" and see if the metrics change vs the
  base — a change means the font is installed. Returns the detected font list + a
  hash of it.

screenInfo()  (lines ~242-260)
  width/height/avail*/devicePixelRatio/colorDepth/pixelDepth/inner*/outer*. Computes
  chromeW/chromeH = outer minus inner, which leaks toolbar/devtools/extension chrome
  height — a tell for headless (no chrome) vs real browsers.

navigatorInfo()  (lines ~262-285)
  ua, platform, language(s), hardwareConcurrency, deviceMemory, maxTouchPoints,
  touch, vendor, cookieEnabled, pdfViewerEnabled, doNotTrack, timezone (+offset),
  plugins/mimeTypes counts.

uaClientHints(done)  (lines ~287-314)
  Async high-entropy UA Client Hints (architecture/bitness/model/platform/
  platformVersion/uaFullVersion/fullVersionList/wow64) with a 400ms timeout. Folded
  into navigator.uaCH at assembly.

automationTells(webglRenderer)  (lines ~316-345) + scoreAutomation (360-366)
  The headless/bot detectors, each a boolean:
    webdriver (navigator.webdriver===true), cdc (Selenium/CDP injected globals via
    a regex over window keys + the known $cdc_ / __webdriver_evaluate document
    props), headlessUA (/HeadlessChrome|PhantomJS|Electron/), toStringTampered
    (stealth plugins rewrite native fns and lose "[native code]"),
    permissionsAnomaly (filled async: Notification.permission==="denied" while the
    permissions query state is "prompt" — classic headless Chrome), noPlugins,
    noMimeTypes, languagesEmpty, chromeMissing (Chrome UA but no window.chrome),
    swRenderer (SwiftShader/llvmpipe/Software in the WebGL renderer string),
    zeroHardware (hardwareConcurrency===0 or deviceMemory===0).
  scoreAutomation sums the true ones into an integer score. That score is what the
  consistency engine reads to decide "is_automated".

Behavioral biometrics  (lines ~368-455)
  A `behavior` object accumulates mouse moves/distance/turn-angles, click times,
  scroll events + maxScroll, and keystroke dwell/flight (keydown timestamp -> keyup
  delta = dwell; gap between successive keyups = flight). Helpers mean/stdev/entropy.
  entropy() is the Shannon entropy of turn-angles binned into 16 buckets (humans are
  irregular -> high entropy; scripts are tidy -> low). behaviorSummary() emits
  mouseEvents, mouseDistance, mousePathEntropy, meanTurnAngle, moveIntervalCv (the
  coefficient of variation of inter-move timing), click stats, scroll stats, keystroke
  stats, interacted (any input at all), and the SYNTHETIC flag:
    synthetic = true if there is a lot of motion but the timing CV is TOO LOW
    (moveStd/moveMean < 0.05 over >25 moves, or dwell CV < 0.04 over >6 keys).
    This catches injected/scripted "humanization" that is too regular to be human.

Assembly + send  (lines ~457-549)
  Event listeners for mousemove/click/scroll/keydown/keyup are attached passively.
  buildStatic(done): computes canvas/webgl/fonts/screen/nav/tells synchronously,
  then resolves the FOUR async surfaces (audio, webgpu, ua-CH, permissionAnomaly)
  via a pending=4 counter, then finalize() computes tells.score, attaches uaCH, and
  computes the composite fp_id = cyrb53 of [canvas, webgl, audio, fonts, platform,
  hardwareConcurrency, deviceMemory, timezone, screen w/h/dpr, languages]. fp_id is
  the STRONGEST device-stitching key (edge weight 7 in the graph) — it survives IP
  changes, cleared cookies, and proxy rotation.
  IMPORTANT: each async surface must call the pending counter's step() exactly ONCE.
  permissionAnomaly resolves from BOTH the permissions.query promise AND a 300ms
  safety setTimeout, so it carries the same once-only `settled` guard the other three
  use; without it the counter was decremented ~5x instead of 4, firing finalize()
  early (before webgpu's 600ms requestAdapter resolved) and silently dropping WebGPU.
  finalize() then also drops the device cookie: document.cookie = "__abd_fp="+fpId
  (path=/, max-age 1y, SameSite=Lax). That is what lets server.py serve this device
  the SAME canary set after it rotates UA/IP/ASN (a non-JS scraper never sets it).
  payload(phase): shallow-copies STATIC, adds phase/pv_id/ts_client/url/referrer/
  behavior. PV_ID is a random id generated once per page load (crypto.getRandomValues,
  Date.now+random fallback) shared by EVERY beacon this pageview emits — it is how the
  request-log join picks the newest beacon of the right pageview (it lands in the
  fp-collector's `raw` jsonb; no dedicated column).
  sendBeacon(phase, useNavBeacon): JSON.stringify the payload; if useNavBeacon and
  navigator.sendBeacon exists, send via sendBeacon (survives page unload), else
  fetch() with keepalive.
  start(): after SETTLE_MS send a "load" beacon; on visibilitychange->hidden or
  pagehide, flush an "unload" beacon via sendBeacon (carries accumulated behavior).
  The unload flush is RE-ARMABLE, not one-shot: `flushedAt` records the interaction
  total (mouse+clicks+scroll+keys) at the last flush, and a later hide sends an
  UPDATED cumulative beacon iff that total changed — so a visitor who tabs away,
  comes back, and keeps interacting keeps reporting (the old `flushed` boolean sent
  only the FIRST tab-away's snapshot and silently lost everything after), while
  tabbing in/out with no new interaction emits nothing (no duplicate rows). A plain
  scraper that does not run JS never reaches start() -> never beacons -> the server
  side reads that absence as a signal.

================================================================================
 PART 2 — DEPLOYMENT AUTOMATION  (ansible/)
================================================================================

The deployer turns a per-site YAML + global defaults into (a) a rendered Docker
Compose stack and (b) a rendered nginx server block, then brings the stack up and
RELOADS (never restarts) nginx. It is local-only (inventory targets localhost with
a local connection — no SSH).

--------------------------------------------------------------------------------
 2.1  ansible/site.yml  — the playbook (the merge + the port-collision guard)
--------------------------------------------------------------------------------
hosts: localhost, gather_facts: true. vars: site_config_path points at
configs/sites/<site_id>.yaml.

pre_tasks (run before any role):
  1. "Require site_id" — assert site_id is defined and non-empty. fail_msg tells you
     to pass -e site_id=<id>.
  2. "Load per-site overrides" — include_vars the site YAML as the variable
     `site_cfg`.
  3. "Merge site overrides over defaults" — set_fact:
        scraper_version = site_cfg.scraper_version | default(scraper_version) | int
        website  = website  | combine(site_cfg.website  | default({}))
        database = database | combine(site_cfg.database | default({}))
        proxy    = proxy    | combine(site_cfg.proxy    | default({}))
     combine() is a shallow dict merge with the override winning. So a per-site YAML
     that only sets website.port leaves website.genmode at the global default.
  4. "Coerce genmode to bool" — website = website | combine({'genmode': (
     website.genmode | string | lower == 'true')}). Necessary because the web app
     writes genmode as the STRING "true"/"false" into the per-site YAML, and the
     compose template needs a real bool to decide whether to inject the nogen command.
  5. "Sanity-check canary_tokens length" — assert canary_tokens|length >= 10 (one per
     var1..var10; extra entries are ignored, fewer than 10 fails).
  6. PORT-COLLISION GUARD (the load-bearing part, lines ~38-92):
        - find every OTHER configs/sites/*.yaml (excluding this site).
        - slurp each (base64), then map: content -> b64decode -> from_yaml ->
          attribute('website') -> attribute('port'), reject('none'), map('int').
          Same for database.host_port. This yields used_web_ports / used_db_ports.
        - assert (website.port|int) not in used_web_ports, else fail with the list
          of already-claimed ports. Same for database.host_port.
     This is why "unique ports per site" is enforced mechanically, not by convention.
     It is the single most common deploy failure and the playbook refuses to proceed.

roles (in order): prereqs (only when ansible_facts.os_family == 'Darwin'),
then configure, then deploy.

--------------------------------------------------------------------------------
 2.2  ansible/group_vars/all.yml  — THE variable contract
--------------------------------------------------------------------------------
Global defaults merged under every site. Keys:
  project_root: "{{ playbook_dir }}/.." ; website_dir: "{{ project_root }}/website".
  scraper_version: 1.
  website: { port: 8080, genmode: true }.
  database: { user: user, password: password, host_port: 5432 }.
  proxy: { enabled: true, base_domain: dukecodeplus.example,
           local_base_domain: dukecodeplus.localhost, container: proxy-nginx,
           conf_dir: "{{ project_root }}/proxy/conf.d" }.
  canary_tokens: a list of 10 Python/Faker expressions — the SOURCE OF TRUTH for the
     canaries. The first 10 are rendered into website/varLists/scraper{N}.txt. The
     comment block lists the providers available (base Faker + faker_edu
     institution_name + faker_food dish/ingredient/fruit + date_of_birth(...).year).
  To change canaries you edit THIS list and re-run the playbook — never edit the
  generated varList by hand.

--------------------------------------------------------------------------------
 2.3  ansible/inventory.yml
--------------------------------------------------------------------------------
all.hosts.localhost with ansible_connection: local and
ansible_python_interpreter: "{{ ansible_playbook_python }}". No remote hosts; this
is a local-only build.

--------------------------------------------------------------------------------
 2.4  ansible/roles/configure/tasks/main.yml  — render the site's artifacts
--------------------------------------------------------------------------------
Tasks in order:
  1. Ensure website_dir/varLists exists.
  2. Render canary_vars.txt.j2 -> varLists/scraper{N}.txt (the 10 expressions).
  3. "Ensure an HTML template exists for scraper{N}": copy scraper1.html ->
     scraper{N}.html with force: false (NEVER clobbers an existing flavor) and
     only when scraper_version != 1. So bumping to a new flavor scaffolds a working
     page you then customize.
  4. Ensure website/sites/<site_id>/ exists.
  5. Render docker-compose.yml.j2 -> website/sites/<site_id>/docker-compose.yml.
  6. "Ensure server.py reads SCRAPER_VERSION from env" — a `replace` task with
     regexp '^SCRAPER_VERSION = \d+\s*$' -> the env-var form. THIS is the self-heal
     that makes a hardcoded SCRAPER_VERSION impossible to keep.
  7. Ensure proxy.conf_dir exists (when proxy.enabled).
  8. Render site.conf.j2 -> proxy/conf.d/<site_id>.conf (when proxy.enabled), and
     NOTIFY the handler "Validate and reload nginx".

--------------------------------------------------------------------------------
 2.5  ansible/roles/configure/handlers/main.yml  — the nginx reload
--------------------------------------------------------------------------------
"Validate and reload nginx" runs, via docker exec proxy-nginx, a loop of:
  nginx -t   (validate the merged config)
  nginx -s reload  (graceful reload — adding a site NEVER drops the others)
changed_when: true, failed_when: false. The failed_when:false is deliberate: if you
deploy a site BEFORE `make proxy` brought the proxy up, the docker exec fails but
the playbook still succeeds — the route just isn't live until the proxy is up.
Reload, not restart, is load-bearing: a restart would drop every site's connections;
a reload picks up the new conf.d file while keeping existing sites serving.

--------------------------------------------------------------------------------
 2.6  ansible/roles/configure/templates/docker-compose.yml.j2  — the per-site stack
--------------------------------------------------------------------------------
Renders website/sites/<site_id>/docker-compose.yml. Key points:
  name: {{ site_id }}  -> Compose auto-namespaces all containers/volumes/networks by
    site, so site-001 and site-002 never collide.
  service db: postgres:16, POSTGRES_DB: scraper{N}-db, host_port:5432 mapping, a
    pgdata volume, and a healthcheck (psql 'select 1'). NOTE: Postgres applies
    POSTGRES_USER/PASSWORD/DB only on FIRST init of an empty data dir — changing
    creds later requires recreating the volume (reset_db), else the healthcheck fails.
  service web: build context ../.. (the repo root, so it builds website/Dockerfile
    against the whole repo). ports: "127.0.0.1:{{ website.port }}:8080" — bound to
    LOOPBACK ONLY (the raw port is for local debugging; reach the site through the
    proxy). env DB_USER/DB_PASS/DB_HOST=db/SCRAPER_VERSION. If website.genmode is
    false, command: ["python","server.py","nogen"]. networks: joins its own default
    network (to talk to db) AND the external proxy_net with an ALIAS {{ site_id }}-web
    (the bare service name "web" is ambiguous across stacks on a shared network, so
    nginx addresses it by this unique alias). depends_on db healthy.
  networks.proxy_net: external: true (must already exist; the deploy role ensures it).

--------------------------------------------------------------------------------
 2.7  ansible/roles/configure/templates/site.conf.j2  — the per-site nginx block
--------------------------------------------------------------------------------
Renders proxy/conf.d/<site_id>.conf, one server {} per site. Key points:
  listen 80; listen 443 ssl;  -> the SAME site answers over both HTTP and HTTPS.
    NEVER default_server (the catch-all in nginx.conf is the sole default). Serving
    :80 too keeps crawlers that only speak plain HTTP (or don't follow redirects)
    reaching the honeypot. The comment documents how to switch to redirect-to-HTTPS.
  server_name {{ proxy.server_name | default(site_id ~ '.' ~ proxy.base_domain) }}
              {{ site_id }}.{{ proxy.local_base_domain }};
    -> the canonical hostname PLUS a browser-friendly *.localhost alias (browsers
    resolve *.localhost to loopback automatically).
  set $site_name <canonical hostname>;  -> the mirror tags requests with
    X-Site $site_name, so even requests arriving via the .localhost alias are
    recorded under the CANONICAL hostname in all_visits.site. This is what keeps
    all_visits.site trustworthy.
  location = /__fpbeacon  (EXACT match): proxies the Layer-1 fingerprint beacon to
    fp-collector:8000. Sets Host/X-Site/X-Real-IP/X-Client-Port, OVERWRITES XFF,
    sets X-Forwarded-Proto. Uses a variable upstream ($fp_upstream) + the http{}
    resolver so a reload never fails when the collector is momentarily down. It does
    NOT mirror and NEVER reaches the Flask backend — it is a direct write path to
    logdb.browser_fingerprints. Being exact-match, it intercepts only that one path;
    everything else falls to location /.
  location /  (the honeypot): mirror /_mirror; mirror_request_body off; set $upstream
    {{ site_id }}-web; proxy_set_header Host/X-Real-IP; X-Forwarded-For $remote_addr
    (OVERWRITE — anti-spoof); X-Forwarded-Proto $scheme; proxy_pass
    http://$upstream:8080$request_uri. The variable upstream + resolver means a
    reload never fails just because this site's container is down (resolved at
    request time).
  include /etc/nginx/snippets/mirror.conf;  -> pulls in the shared /_mirror target.

--------------------------------------------------------------------------------
 2.8  ansible/roles/configure/templates/canary_vars.txt.j2
--------------------------------------------------------------------------------
{% for expr in canary_tokens[:10] %}{{ expr }}{% endfor %}. Emits the first 10
canary expressions one per line. This is why website/varLists/*.txt is a generated
artifact you must not hand-edit.

--------------------------------------------------------------------------------
 2.9  ansible/roles/deploy/tasks/main.yml  — bring the stack up
--------------------------------------------------------------------------------
  1. "Ensure the shared external proxy_net network exists" — docker network create
     proxy_net; changed_when rc==0; failed_when rc!=0 AND 'already exists' not in
     stderr. Idempotent, so the bare `ansible-playbook` path works on a fresh machine
     without `make ensure-net`.
  2. "Tear down stack and remove DB volume when reset_db" — when reset_db|bool:
     docker compose down -v in the site dir (failed_when:false). This WIPES the
     pgdata volume so Postgres re-initializes with new credentials. Needed because
     creds are baked at volume-init only.
  3. "Build and (re)start containers" — docker compose up -d --build in the site dir.
     changed_when is a heuristic over stderr ('Creating'/'Recreate'/'Started'/
     'Building').
  4. "Show running containers" — docker compose ps (changed_when:false).
  5. Print the service URL (through the proxy + the direct debug port).

--------------------------------------------------------------------------------
 2.10  ansible/roles/prereqs/tasks/main.yml  (macOS only)
--------------------------------------------------------------------------------
Gated on os_family=='Darwin' in site.yml. Checks `which brew` (asserts Homebrew
present), installs docker CLI + docker-compose plugin via brew if missing, and runs
`docker info` to verify the daemon is reachable (failed_when rc!=0). On Linux/WSL
this role is skipped entirely.


================================================================================
 PART 3 — REVERSE PROXY, CENTRAL LOGGING & PASSIVE CAPTURE  (proxy/ + compose)
================================================================================

One nginx is the ONLY locally exposed entry point and the source of all cross-site
data. Three FastAPI collectors and a Zeek sidecar feed the central logdb Postgres.

--------------------------------------------------------------------------------
 3.1  proxy/nginx.conf  — base config (security-load-bearing decisions live here)
--------------------------------------------------------------------------------
Inside http{}:
  resolver 127.0.0.11 valid=10s ipv6=off;  -> Docker embedded DNS. Combined with the
    variable-upstream proxy_pass in the per-site blocks, this lets `nginx -s reload`
    succeed even when a backend container is momentarily down (names resolve at
    request time, not config-load time).
  TLS: ssl_certificate /etc/nginx/certs/wildcard.crt (+ key) set at http SCOPE so
    EVERY server block inherits it (the catch-all and each per-site block). One
    self-signed WILDCARD cert (*.dukecodeplus.example / *.dukecodeplus.localhost)
    serves every site because site hostnames are subdomains of the base domains.
    nginx selects this cert by TLS SNI during the handshake, then routes by Host —
    name-based virtual hosting over HTTPS. ssl_protocols TLSv1.2/1.3; http2 on.
  log_format siteaccess (escape=json): one JSON line per request with time, site
    ($host), scheme (http vs https — so you can see which crawlers used TLS),
    client_ip ($remote_addr), client_port ($remote_port), xff, method, uri, status,
    bytes, user_agent, request_time, upstream. access_log -> dukecodeplus.access.log.
  THE DEFAULT CATCH-ALL SERVER (the most important block in the file):
    server { listen 80 default_server; listen 443 ssl default_server; server_name _;
             access_log .../unmatched.access.log siteaccess; return 444; }
    Any request whose Host/SNI does NOT match a configured site lands here:
    raw-IP scans, spoofed/junk Host values, no-Host requests. It returns 444 (drops
    the connection, no body, minimal disclosure to scanners) and — crucially —
    NEITHER PROXIES NOR MIRRORS. Two guarantees follow:
      (1) Unmatched/junk traffic never reaches a real site's Flask backend, so no
          canary tokens are ever assigned to a raw-IP scanner.
      (2) Every request that DOES reach a per-site block has a Host matching that
          site's server_name, so all_visits.site can never be an arbitrary client
          value. The central log stays trustworthy.
    It is default_server on BOTH ports so unknown-SNI HTTPS probes are caught too
    (the TLS handshake still completes with the inherited wildcard cert before the
    444 — unavoidable for TLS — but nothing is proxied or mirrored). Scan traffic is
    still recorded, separately, in unmatched.access.log. DO NOT remove this block or
    mark a per-site block default_server — either reintroduces canary misattribution.
  include /etc/nginx/conf.d/*.conf;  -> the Ansible-rendered per-site blocks.

--------------------------------------------------------------------------------
 3.2  proxy/snippets/mirror.conf  — the shared /_mirror subrequest target
--------------------------------------------------------------------------------
location = /_mirror { internal; ... }. Issued by each per-site `location /` via
`mirror /_mirror`. It replays the body-less GET as an internal subrequest to
collector:8000 and sets the headers the collector reads:
  X-Site $site_name   (the CANONICAL hostname, even via the .localhost alias)
  X-Real-IP $remote_addr
  X-Client-Port $remote_port  (the 4-tuple join key for TLS/TCP fingerprints)
  X-Forwarded-For $remote_addr (OVERWRITE, anti-spoof)
Best-effort + non-blocking: proxy_connect_timeout 200ms, proxy_read_timeout 500ms,
proxy_next_upstream off. A slow or down collector can NEVER stall the real response
(nginx has already begun returning the page to the client). $collector is a variable
so a reload never fails when the collector is down.

--------------------------------------------------------------------------------
 3.3  proxy/gen-cert.sh + the certgen service
--------------------------------------------------------------------------------
A one-shot alpine init container. If wildcard.crt/key already exist (-s), it leaves
them in place (idempotent — restarts keep the same cert and the same browser-trust
decision). Otherwise it installs openssl on demand and generates a self-signed
RSA-2048 wildcard cert valid 3650 days with subjectAltName covering
*.BASE_DOMAIN, BASE_DOMAIN, *.LOCAL_BASE_DOMAIN, LOCAL_BASE_DOMAIN. nginx
depends_on certgen with condition: service_completed_successfully, so the cert
ALWAYS exists before nginx starts. BASE_DOMAIN/LOCAL_BASE_DOMAIN come from the
certgen service env in docker-compose.proxy.yml and MUST match proxy.base_domain /
proxy.local_base_domain in all.yml, or clients see a name mismatch. The cert is
self-signed (one-time browser warning, harmless to bots/curl -k). The key never
leaves proxy/certs/ (git-ignored).

--------------------------------------------------------------------------------
 3.4  proxy/collector/app.py  — the central request collector (FastAPI + psycopg2)
--------------------------------------------------------------------------------
Receives nginx's mirror, writes one row per request to all_visits, returns 204 ASAP.
Read it in blocks:
  CREATE_TABLE: all_visits (id serial pk, ts timestamptz default now(), site, client_ip,
    client_port int, user_agent, method, uri, headers jsonb).
  MIGRATE = "ALTER TABLE all_visits ADD COLUMN IF NOT EXISTS client_port int" — an
    ADDITIVE migration for stacks created before client_port existed (CREATE TABLE
    IF NOT EXISTS never alters an existing table, so the ALTER is required to migrate
    an already-deployed proxy stack). client_port is needed to join requests to their
    TLS/TCP fingerprints by 4-tuple.
  Connection management: a single module-global _conn, get_conn() (re)connects with
    autocommit=True, reset_conn() drops it so the next request reconnects cleanly.
  lifespan: on startup, retry init_db() up to 30 times (1s apart) to tolerate a cold-
    start race where logdb isn't ready yet — never crash.
  collect(): an api_route accepting GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS on any
    path. Reads X-Site, X-Real-IP (or X-Forwarded-For), X-Client-Port (coerced to int
    or None), User-Agent, the URI (+ query), and ALL headers as a dict. INSERTs the
    row with psycopg2.extras.Json(headers). The ENTIRE body is wrapped in try/except:
    on ANY error it prints and resets the connection and STILL returns 204 — the
    fire-and-forget contract. The mirror failing must never affect the real client.

--------------------------------------------------------------------------------
 3.5  proxy/fp-collector/app.py  — Layer-1 fingerprint collector
--------------------------------------------------------------------------------
Receives the fp.js beacon at /__fpbeacon, writes one row to browser_fingerprints.
  CREATE_TABLE: a WIDE table — id, ts, site, client_ip, client_port, user_agent,
    phase, fp_id, canvas_hash, canvas_winding bool, webgl_hash/vendor/renderer,
    webgl_shader_ms double, audio_hash, audio_sample double, font_hash, fonts jsonb,
    screen jsonb, navigator jsonb, automation jsonb, behavior jsonb, webgpu jsonb,
    raw jsonb (the entire payload). Plus THREE indexes: (client_ip, client_port, ts),
    (fp_id), and (client_ip, user_agent, ts) — the last one (browser_fp_ip_ua) supports
    request_log's windowed (client_ip, user_agent) enrichment join.
  MAX_BODY (default 64KB): rejects oversized payloads so a malicious client cannot
    push huge blobs into logdb. A real fingerprint is a few KB.
  collect(): POST/OPTIONS on any path. Reads the body (bails to 204 if empty or over
    MAX_BODY), json.loads it (bails if not a dict). Reads X-Site/X-Real-IP/
    X-Client-Port/User-Agent from the headers nginx set. Maps the JSON payload fields
    to the row tuple — note the schema here MUST match the field names fp.js emits.
    canvas_winding is only stored if it is a real bool. _num/_int coerce best-effort.
    INSERTs with Json(...) for the jsonb columns and Json(fp) for raw. Same
    fire-and-forget/never-block contract as the request collector (the beacon is async
    fetch keepalive / sendBeacon, and any DB error is swallowed + connection reset).

--------------------------------------------------------------------------------
 3.6  proxy/tls-capture/scripts/local.zeek  — Zeek capture config
--------------------------------------------------------------------------------
  @load base/protocols/ssl  -> the SSL analyzer.
  @load packages            -> any zkg-installed JA3/JA4 packages (they add ja3/ja4/...
                               fields to SSL::Info automatically when present).
  @load ./tcp-fingerprint   -> the SYN fingerprint module, loaded AFTER SSL and in its
                               own module so a problem there can't disturb ssl.log.
  redef LogAscii::use_json = T  -> one JSON object per line (easy to tail/parse).
  redef Log::default_rotation_interval = 1 hr  -> hourly rotation; the shipper follows it.
  redef ignore_checksums = T  -> avoids dropping packets on container veth pairs with
                               TX offload (otherwise Zeek discards "bad-checksum" packets).

--------------------------------------------------------------------------------
 3.7  proxy/tls-capture/scripts/tcp-fingerprint.zeek  — Layer-2 SYN capture
--------------------------------------------------------------------------------
module TCPFP. Declares a Log stream and an Info record with the SYN fields
(ts, uid, orig_h/p, resp_h/p, ttl, win_size, win_scale, mss, sack_ok, df, syn_size).
event connection_SYN_packet(c, pkt): fires ONLY on SYN packets (negligible overhead
vs a per-packet handler). Guards:
  if !pkt$is_orig: return   -> only the CLIENT's SYN carries the visitor's OS; the
    server SYN-ACK is our own kernel.
  if resp_p != 80 && resp_p != 443: return  -> only inbound to the ports nginx SERVES.
    This drops nginx's OWN egress SYNs to the collectors (:8000) and backends (:8080),
    which carry the proxy host's kernel and would pollute the OS inference.
Then it writes the SYN's kernel-set TCP/IP fields to tcp_syn.log. The header comment
documents the host-topology caveat: behind a userland docker-proxy the captured SYN
may be the forwarder's, not the client's (the same caveat as the TLS-IP match). The
kernel-set values (TTL/window/MSS) survive proxies/VPNs that only rewrite source IP —
this is the "the kernel betrays the spoofed OS" signal.

--------------------------------------------------------------------------------
 3.8  proxy/tls-capture/scripts/entrypoint.sh
--------------------------------------------------------------------------------
Auto-detects the capture interface: CAPTURE_IFACE override, else the interface
holding the default route (awk over /proc/net/route for 00000000), else the first
non-lo interface, else eth0. Then `exec zeek -i <iface> local.zeek`. Because the
container shares nginx's network namespace (network_mode service:nginx in compose),
its interfaces ARE nginx's, so it sees inbound :443 traffic. The comment reminds you
to verify once that Zeek's src IP equals nginx's $remote_addr.

--------------------------------------------------------------------------------
 3.9  proxy/tls-shipper/app.py  — Zeek-logs -> logdb shipper (Layer-2 compute)
--------------------------------------------------------------------------------
Tails two JSON logs on TWO threads with TWO connections (a psycopg2 connection is
not safe to share across threads). This is also where the OS inference + JA4T are
COMPUTED in Python (Zeek just logs the raw SYN fields).

  ssl.log  -> tls_handshakes (ja3/ja3s/ja4/ja4s/sni/version/cipher), 4-tuple-keyed.
              tls_row_from maps id.orig_h/id.orig_p -> src_ip/src_port etc.
  tcp_syn.log -> tcp_fingerprints. tcp_row_from maps the SYN fields and calls:
    infer_os(ttl, win, wscale, mss): p0f-style. Normalize the observed TTL UP to the
      nearest initial value in (32,64,128,255): 128/32 -> "Windows", 255 -> "Network/
      BSD", 64 -> unix-like. For the crowded 64 bucket (Linux/Android/macOS/iOS all
      start at 64) it uses the SYN window + window-scale: win==65535 && ws in (5,6)
      -> "Apple"; ws>=7 -> "Linux"; a set of known Linux window sizes -> "Linux";
      default -> "Linux". Returns a clean token the consistency engine matches against
      the UA-claimed OS.
    build_ja4t(win, mss, wscale, sack_ok, df): a JA4T-STYLE signature
      "win_mss_wscale_flags" (flags = sackok bit + df bit). True JA4T also hashes the
      TCP options ORDERING, which Zeek's SYN_packet record doesn't surface; the
      kernel-set values it does give already form a spoof-resistant per-stack signature.
  Shipper class: get_conn/reset_conn/init_db/wait_for_db (retry 60x), insert_entry
    (maps + executes, resets on error), and tail() — the robust follower: opens the
    file at SEEK_END (only new records), records the inode; on each new line json.loads
    + insert; on EOF sleeps POLL_SECONDS and checks for ROTATION (inode changed) or
    TRUNCATION (size < tell) and reopens. Wrapped so it never dies on a bad line or a
    logdb hiccup.
  main(): starts both Shipper threads as daemons and joins them.

dict as the template name and 500s. If you add a page and it 500s with a weird
template-not-found, this is why.

_LAST_GEN) cache the result/error of a POST so it survives the POST -> 303 redirect
-> GET render. FastAPI/PRG (post-redirect-get) loses POST state otherwise.

--------------------------------------------------------------------------------
 4.6  app/services/request_log.py  — read-only all_visits access (THE analytics core)
--------------------------------------------------------------------------------
This module reads the central log by SHELLING `docker compose -f
docker-compose.proxy.yml exec -T logdb psql ...` with -X -q -t -A (no psqlrc, quiet,
tuples-only, unaligned) and ON_ERROR_STOP=1, and parsing a SINGLE json_build_object
result. There is no Python DB driver in this path — it reuses the Docker CLI the app
already has. PART 11 walks the SQL clause by clause; the structure:
  _sql_literal(value): escapes a string by doubling single quotes and wrapping in
    quotes — the ONLY user input that reaches the SQL is the search/site/method, and
    it goes through this.
  _run_json_query(sql): runs the psql command (timeout 20s); maps common failures to
    friendly RequestLogError messages ("proxy DB not running -> make proxy",
    "all_visits not ready", etc); json.loads the single output line.
  _BASE_COLS: "a.id, a.ts, a.site, a.client_ip, a.user_agent, a.method, a.uri,
    a.headers" — all_visits aliased `a` so the enriched query can disambiguate from
    the joined browser_fingerprints `b`.
  _conditions(site, method, search, include_fp): builds the WHERE clause. site/method
    add "a.site = '...'" / "a.method = '...'". search adds a case-insensitive
    POSITION(... IN LOWER(CONCAT_WS(' ', <fields>))) > 0, where <fields> is the
    request columns and, when include_fp, ALSO b.fp_id/b.canvas_hash/b.webgl_renderer
    — so you can search by a device's fingerprint and find the requests it made.
  _plain_sql(where, page_size, offset): the un-enriched query (CSV export + the
    fallback). A CTE `filtered` selects _BASE_COLS WHERE <where>; `page_rows` orders
    by ts DESC, id DESC and LIMIT/OFFSET; the final SELECT returns one json_build_object
    with total, last_24h, unique_sites, latest_ts, and rows (json_agg of the page).
  _enriched_sql(where, page_size, offset, with_tcp): THE headline query. `filtered`
    selects _BASE_COLS plus the joined fingerprint columns. TWO stacked LATERALs pick,
    for each request, the ONE browser fingerprint that actually belongs to it. First a
    `pv` lateral identifies the request's OWN pageview:
        SELECT bf0.raw ->> 'pv_id' AS pv_id FROM browser_fingerprints bf0
        WHERE bf0.client_ip = a.client_ip AND bf0.user_agent = a.user_agent
          AND bf0.raw ->> 'pv_id' IS NOT NULL AND bf0.ts BETWEEN a.ts +/- W minutes
        ORDER BY (bf0.ts >= a.ts) DESC, abs(extract(epoch FROM (bf0.ts - a.ts))) ASC
        LIMIT 1
    (a pageview's beacons always FOLLOW its page GET, so prefer beacons at/after the
    request — nearest-in-absolute-time could grab the PREVIOUS page's unload beacon,
    which fires the instant that page was left, milliseconds before the new GET).
    Then the `b` lateral picks the beacon:
        WHERE bf.client_ip = a.client_ip AND bf.user_agent = a.user_agent
          AND bf.ts BETWEEN a.ts +/- W minutes
        ORDER BY COALESCE(bf.raw ->> 'pv_id' = pv.pv_id, FALSE) DESC,   -- own pageview first
                 (bf.phase = 'unload') DESC,                             -- prefer unload
                 CASE WHEN bf.raw ->> 'pv_id' = pv.pv_id THEN bf.ts END DESC,  -- latest cumulative
                 abs(extract(epoch FROM (bf.ts - a.ts))) ASC, bf.ts DESC -- legacy fallback
        LIMIT 1
    i.e. same IP AND same exact User-Agent, within a +/- W-minute window
    (FP_JOIN_WINDOW_MIN, default 30), preferring the request's own pageview's LATEST
    cumulative `unload` beacon. pv_id is read from the collector's `raw` jsonb (fp.js
    stamps it into every beacon of one page load) — NO schema change, and rows from
    before pv_id existed simply return NULL and fall back to the older
    nearest-unload-in-window semantics. Because fp.js's unload beacon re-arms
    (cumulative totals, re-sent on each hide with new interaction), the newest
    same-pv unload row is the pageview's fullest interaction record — this is what
    makes the row's biometrics UPDATE when the visitor tabs away, returns, and keeps
    interacting. The UA-equality is LOAD-BEARING: fp.js sends
    the same User-Agent header as the page GET that spawned it, so (client_ip,
    user_agent) ties a request to its OWN device. Keying on client_ip ALONE (the old
    behavior) glued one visitor's latest fingerprint onto EVERY request sharing that
    IP — and behind a NAT or the local Docker hop, many distinct visitors collapse
    onto one address, so curl/internal probes/declared bots that never ran JS all
    inherited the operator browser's verdict and lit up as spurious VM/AUTO/INCONSISTENT.
    The +/-W window stops a request inheriting an UNRELATED session's device from
    hours/days away behind the shared hop; `(phase='unload') DESC` matters because the
    `load` beacon (~1.2s in) has ZERO behavior — nearest-time alone always picked it,
    which is why interaction once read as 0 clicks.
    A FURTHER LEFT JOIN LATERAL adds the per-IP latest TCP/OS inference (tcp_os, ja4t)
    — kept per-IP because a SYN has no UA and is only trusted for public IPs anyway.
    The tcp join is optional (with_tcp) and all degrade when the tables don't exist.
    (Index browser_fp_ip_ua (client_ip, user_agent, ts) supports both fp laterals.)
  fetch_requests(...): clamps page (>=1) and page_size (25..500). enrich=False ->
    _plain_sql. enrich=True -> _enriched_sql(with_tcp=True), with graceful fallbacks:
    if the error mentions tcp_fingerprints missing -> retry with_tcp=False; if
    browser_fingerprints missing -> fall back to _plain_sql entirely. Then for EVERY
    row it sets fp_present = (has fp_id/canvas_hash) and verdict =
    fingerprint_service.verdict_for(row) (the SAME cross-layer consistency engine the
    campaign analysis uses) — computed for non-beacon rows TOO, so a browser-UA request
    that never ran JS finally surfaces the `browser_no_js` signal ("No JS · browser")
    instead of a blank cell. The /logs route then folds a per-row `disguised` flag for
    devices seen under multiple identities (see fingerprint_service.disguise_summary).
  fetch_filter_options(): one query returning {sites: [...], methods: [...]} (distinct
    non-empty values) for the dropdowns.
  total_request_count(): COUNT(*) of all_visits (None on error) — for landing stats.
  site_status_map(): the set of active_proxy_sites() (live routes).
  requests_to_csv(rows): DictWriter over id/ts/site/client_ip/method/uri/user_agent/
    headers (headers JSON-encoded). The CSV export path.

--------------------------------------------------------------------------------
 4.7  app/services/fingerprint_service.py  — browser_fingerprints + the shared verdict
--------------------------------------------------------------------------------
Same psql-shell pattern as request_log. Tries to import
crawler_graph.analysis.consistency as _consistency (the cross-layer engine) and
degrades to "no verdict" if it can't.
  _select_sql(where, page_size, offset, with_tcp): selects the fingerprint columns,
    LEFT JOIN LATERAL the latest tcp_fingerprints OS inference for the same IP. The
    final json_build_object adds unique_devices = COUNT(DISTINCT fp_id).
  fetch_fingerprints(...): a filtered page of fingerprints, each annotated with
    _verdict_for. (Used by the older standalone fingerprints view, now folded into /logs.)
  _verdict_for(row) (public alias verdict_for): builds an ENDPOINT-SHAPED record from
    a row — client_ip, ua_top=user_agent, tcp_os=[tcp_os] (if not "unknown"),
    webgl_renderers=[webgl_renderer], automation_tells (the True ones), n_requests=1 —
    and runs consistency.score_endpoint(rec). It now DETECTS fp presence from the row
    itself (has_fp = fp_id/canvas_hash present) instead of assuming it: has_browser_
    fingerprint=has_fp, is_browser from the UA (known_crawlers.is_browser_ua), and the
    JS-only fields (js_platform, behavior_synthetic/interacted) are gated on has_fp. So
    the SAME function serves both a real fingerprint row AND a bare request row — a
    browser-UA request with no beacon now fires the `browser_no_js` rule. Automation is
    left for the engine to weigh from the tells (strong vs. weak, below) rather than
    pre-flagged from the raw score. THIS is why the per-request verdict in the request
    log EXACTLY matches the per-campaign analysis. request_log imports verdict_for here.
  disguise_summary(limit=50): NEW read-only aggregate over browser_fingerprints grouped
    by fp_id — a single physical device leaves the same fp_id on every beacon, so if its
    beacons span >=DISGUISE_MIN_UAS distinct User-Agents OR >=DISGUISE_MIN_NETBLOCKS
    distinct /24 netblocks it is wearing more than one identity (UA spoofing / IP-VPN
    rotation). Returns {total_devices, disguised, devices:[{fp_id, beacons, n_ua, n_ip,
    n_net, uas, ips, sites, first/last_ts}]}. This is the canary disguise signal viewed
    through the device layer: the honeypot serves one device one canary set, so a device
    still showing up under many identities is the disguise. The /logs page uses it for
    the "Disguised devices" panel and to tag matching request rows. (In the local Docker
    build every visitor shares the userland-proxy hop, so netblocks collapse to one and
    the operator's own browser is never flagged; a real rotating crawler spans several.)
  fetch_sites(): distinct sites present in browser_fingerprints (for the filter).
  summary_counts(): {fingerprints, unique_devices, tcp_fingerprints} best-effort
    (None when unavailable) — for the KPI strip + landing stats.

--------------------------------------------------------------------------------

================================================================================
 PART 5 — THE LLM QUERYING PIPELINE  (querying/)
================================================================================

An importable Python PACKAGE (run from the repo root as `python -m querying.main`,
or imported by the app). It answers question (A): "did a target LLM reproduce this
honeypot's canary tokens?" The whole thing is offline-safe — the two mock providers
make every step demonstrable with no API keys. The 6b sub-layer (model_timeline,
provenance, membership, rag_disambiguation) answers "WHEN did it ingest, and was it
training or live retrieval?"

The contracts to preserve (the rest of the pipeline relies on these):
  - matcher scores only LIST-VALUED extractor fields against var1..var10.
  - parser returns at least main_idea (+ top_anchors); generate_probes needs main_idea.
  - llm_responses returns {model: [{"question","answer"} | {"question","error"}]}.
  - a run record (store.py) is the unit the web app reads for history + stats.

--------------------------------------------------------------------------------
 5.1  querying/config.py  — paths, providers, defaults (env-overridable)
--------------------------------------------------------------------------------
PACKAGE_DIR/PROJECT_ROOT. THE .env QUIRK (lines ~26-36): it manually loads
querying/.env and PROJECT_ROOT/.env via dotenv_values and fills in any var that is
unset OR EMPTY, while letting a genuinely-set shell value win. WHY: the app container
declares OPENROUTER_API_KEY: ${OPENROUTER_API_KEY:-} etc, so compose injects an EMPTY
value that is still "present" in os.environ — and python-dotenv's default
load_dotenv(override=False) refuses to replace an already-present var, so a key sitting
in querying/.env would be silently ignored (this is exactly the "API key is not set"
bug in the UI). This manual fill fixes it. If python-dotenv isn't installed it's a
no-op (env must come from the shell).
  RUNS_DIR = querying/runs (persisted run JSON). SAMPLE_GROUND_TRUTH = jeniffer.csv.
  MAX_PROBES = 3 (questions per run). HIGH_RISK_THRESHOLD = 0.3 (Jaccard >= this is a
    confirmed leak).
  TARGET_PROVIDER / EXTRACTOR_PROVIDER (mock|openrouter|anthropic / mock|openai|
    anthropic). The OpenRouter + Anthropic + OpenAI keys/base URLs. ANTHROPIC_MODEL
    defaults to claude-fable-5 (the latest, most capable Claude).
  6b: PROVENANCE_DIR = querying/provenance. MEMBERSHIP_BACKEND (mock|hf|openai),
    MEMBERSHIP_MODEL (gpt2), MEMBERSHIP_K (0.2), MEMBERSHIP_ALPHA (0.01).
  DEFAULT_TARGET_MODELS = [mock/scraper-sim, mock/honest-llm, openrouter/openai/
    gpt-oss-120b:free, anthropic/claude-fable-5]. The mock entries always work offline;
    the others need the matching provider + key. The comment warns that OpenRouter's
    free-tier slugs rotate and are transiently rate-limited.

--------------------------------------------------------------------------------
 5.2  querying/pipeline.py  — the orchestrator
--------------------------------------------------------------------------------
QueryRequest dataclass: target_url, models, host_header, verify_tls, site_id, csv_path,
db_name, db_user, project_root, max_questions, seed, persist, extra. The full set of
inputs for one run.
  _load_ground_truth(req): if site_id+db_name+db_user -> ground_truth.load_site_rows
    (the live per-site DB), else load_csv_rows(csv_path or SAMPLE_GROUND_TRUTH).
    Returns (rows, source_label).
  run_query(req): builds a run dict (run_id = timestamp+random hex, started_at,
    status="running", and slots for everything). Then in a try:
    1. record = parser(target_url, host_header, verify) — scrape the page. This is a
       REAL visit, so for a local site it ALSO causes the honeypot to assign + store a
       canary set for the probe's UA. If main_idea is missing it raises (proxy down /
       site not deployed).
    2. role_prompt, questions = generate_probes(record, max_questions, seed).
    3. rows, source = _load_ground_truth(req). (Loaded AFTER scraping so our own
       just-assigned set is present for local sites.)
    4. leak = pick_leak_candidates(rows, prefer_user_agent=PROBE_USER_AGENT) — the
       canary set the mock scraper-sim will leak. context = {subject, leak_candidates}.
    5. answers_by_model = llm_responses(models, (role_prompt, questions), context).
    6. For each model: collect its answers (skip errors), join them, extract_info ->
       structured evidence, then matcher(extracted, row) over EVERY ground-truth row,
       keeping the BEST jaccard_score. leaked = best >= HIGH_RISK_THRESHOLD. Append a
       per-model result (answer, extracted, best_match, leaked) or an error result.
    7. summary = {models_tested, matches_found, best_score, ground_truth_rows,
       threshold}; status="completed".
    Catches GroundTruthError specially (friendly message) and any other Exception
    (records type+message). save_run(run) unless persist=False. Returns the run.

--------------------------------------------------------------------------------
 5.3  querying/parser.py  — scrape a page -> structured record
--------------------------------------------------------------------------------
spaCy is OPTIONAL and lazily loaded (_get_nlp caches the model or None; loading is
expensive). parser(target_url, host_header, verify, timeout=10):
  - one requests.get with User-Agent "AIBotDefender-Probe/1.0" and an optional Host
    override (to reach a honeypot via the proxy at 127.0.0.1), verify=False for the
    self-signed cert. On RequestException -> returns {} (the pipeline then raises a
    friendly "couldn't scrape" error).
  - BeautifulSoup the response. clean_text strips script/style and collapses whitespace.
  - record = get_variables(text) (entity lists). main_idea = get_main_idea(soup) (the
    most salient PERSON/ORG/LOC from title+h1 via spaCy) OR _title_subject(soup) (a
    heuristic that strips "About"/"Profile of"/"Biography of"/"The" from the title/h1).
    top_anchors = get_headings(soup) (h1-h6 text). So the pipeline still works without
    spaCy — it derives the subject from the page title/headings.
  get_variables(text): with spaCy, buckets entities into PLURAL-KEYED lists
    (people/cities/locations/institutions/organizations/works/unique_phrases),
    skipping numerics and short strings, dedup preserving order. Without spaCy, returns
    empty lists (the pipeline uses main_idea + top_anchors alone). The plural keys are
    the contract the extractor/matcher expect.

--------------------------------------------------------------------------------
 5.4  querying/prompt_generator.py  — adversarial probes
--------------------------------------------------------------------------------
ROLE_PROMPTS: four framings (archival_retrieval / knowledge_base / database_migration
/ research_assistant), each instructing the model to recover structured info about the
subject and to say "unknown" rather than speculate (so a non-ingesting model produces
no canaries). ELICITATION_TIERS: per-framing question templates formatted with
{main_idea}. generate_probes(record, max_questions, seed): seeded random.Random picks
ONE role prompt and SAMPLES max_questions from the flattened question pool. Raises if
main_idea is missing. seed makes selection reproducible (so two runs are comparable).

--------------------------------------------------------------------------------
 5.5  querying/llm_client.py  — query target models (provider by id prefix)
--------------------------------------------------------------------------------
Routing is by the model id PREFIX. A dependency-light httpx client.
  _mock_answer(model, role_prompt, question, context):
    honest-llm -> a generic "I don't have verified records and won't fabricate" answer
      (no canaries -> the matcher reports no leak).
    scraper-sim (the default mock) -> simulates a model that INGESTED the page: it
      shuffles the context.leak_candidates (the site's canary set), drops "null" values,
      and weaves the first 8 into a bulleted "documented information" answer. The matcher
      then reports a HIGH jaccard -> this is what a positive detection looks like end to
      end, with no network.
  _openrouter_answer: POST {base}/chat/completions with the system role prompt + the
    user question. Retries up to 3 times on 429/500/502/503/504 (honoring Retry-After,
    capped at 10s). Raises RuntimeError with the PROVIDER'S OWN error message
    (_provider_error_detail digs {"error":{"message":...}} out of the body — far more
    useful than a bare status; e.g. an OpenRouter 404 names the correct replacement slug).
  _anthropic_answer(..., browsing=False): POST the Messages API with the role prompt as
    `system`. If browsing=True it adds the server-side web_search tool (used by RAG
    disambiguation — a canary the model reproduces ONLY with browsing on was retrieved
    live, not memorized). Joins the text blocks of the response.
  _answer_one(model, ...): dispatches mock/openrouter/anthropic by prefix; a bare id
    falls back to the configured TARGET_PROVIDER.
  llm_responses(test_suite, prompt_package, context, timeout=60, options): for each
    model, for each question, calls _answer_one ISOLATED in try/except — a single failed
    question no longer aborts the rest. Returns {model: [{question,answer}|{question,error}]}.
    options (e.g. {"browsing":True}) is forwarded to each call; None keeps default behavior.

--------------------------------------------------------------------------------
 5.6  querying/extractor.py  — normalize an answer into structured evidence
--------------------------------------------------------------------------------
A SEPARATE role from the target model (the "extractor"), selected by
config.EXTRACTOR_PROVIDER. CATEGORIES = people/locations/organizations/works/
unique_phrases. Always returns LISTS (never semicolon strings) so evidence is never
silently dropped (the matcher only scores list-valued fields).
  _mock_extract(answer): heuristic — pull bullet lines (^[-*•]\s+) into values; if none,
    split on ;/newline into short chunks; dedup; put everything into unique_phrases.
  _llm_extract_json(answer): anthropic or an OpenAI-compatible chat endpoint asked for a
    strict JSON object of the five list keys (the OpenAI path uses

--------------------------------------------------------------------------------
 5.7  querying/matcher.py  — the detection metric (exact-set Jaccard)
--------------------------------------------------------------------------------
VAR_COLUMNS = var1..var10. matcher(extractor_output, row_dict) = compare_row(
flatten_extractor(...), row_dict).
  flatten_extractor: collect lowercase, trimmed items from ALL list-valued categories
    into a set.
  flatten_row: collect lowercase, trimmed var1..var10 from the row into a set (skipping
    "null").
  compare_row: jaccard = |intersection| / |union| (0 if union empty). Returns
    {bot (the row's user_agent), matches (sorted intersection), jaccard_score (rounded)}.
  This exact-set Jaccard is THE detection signal. >= 0.3 (HIGH_RISK_THRESHOLD) = leak.

 5.13  querying/provenance.py  — crawl-to-train dating (6b)
--------------------------------------------------------------------------------
Answers "did model X train on my page, and WHEN?" by probing successive model versions
and bounding ingestion from WHICH versions reproduce a canary set.
  _site_psql_json / crawl_times(project_root, site_id, db_name, db_user): reads the
    per-site new_visits log via `docker compose exec db psql`, grouping by
    (user_agent, asn) to get min(timestamp) (first_seen = the canary MINT/crawl time),
    max (last_seen), and count. No schema change — it just reads the existing log.
  probe_models(role_prompt, questions, rows, models, context, threshold): for each
    model, query -> extract -> for each canary row, matcher; record which row KEYS
    (UA|ASN) it leaked (jaccard >= threshold) + the best score. Errors are captured.
  infer_windows(leak_by_model, crawl, models): for each leaked canary-set key:
    leaking = models that leaked it; non_leaking = models that ran but didn't.
    real_cutoff(model) ignores the mocks (they carry no real cutoff). earliest_leak =
    the OLDEST cutoff among leaking real models. The ingestion window is
    (latest non-leaking cutoff below earliest_leak, earliest_leak], intersected with
    [crawl_date, ∞) — i.e. lower bound = max(crawl_date, that non-leaking cutoff),
    upper bound = earliest_leak. The crawl-to-train LATENCY upper bound =
    earliest_leak - crawl_date (days). bounded_by_real_models flags whether any real
    model actually bounded it (vs mock-only).
  run_provenance(...): scrape -> probes -> load rows + crawl_times (local) or CSV
    (custom, no crawl) -> probe_models -> infer_windows. Persists a report with the
    timeline, leak_by_model, the windows, the raw crawlers (mint times), and a summary.
    Has its own CLI (python -m querying.provenance). save_report/list_reports/load_report.

--------------------------------------------------------------------------------
 5.14  querying/membership.py  — Min-K% / Min-K%++ membership inference (6b)
--------------------------------------------------------------------------------
Detects whether content was in training WITHOUT needing regurgitation, using the
per-token log-probability signal and a controlled null (served vs never-served
watermark docs). References Shi et al. (Min-K%), Zhang et al. (Min-K%++), Maini et al.
  Statistics:
    min_k_percent(token_logprobs, k): mean of the LOWEST k% token log-probs (higher =>
      more member-like — a member text has fewer "surprising" low-prob tokens).
    min_k_percent_pp(logprobs, mu, sigma, k): Min-K%++ — z-normalize each token log-prob
      by that position's vocab mean/std, then average the lowest k%. Needs full next-token
      distributions (the HF backend).
    score_from_stats: prefer Min-K%++ when mu/sigma are available, else Min-K%.
    _auc(served, control) = P(served > control) (0.5 = no separation).
    mann_whitney_p(served, control): one-sided p that served > control — scipy if present,
      else a normal approximation with tie/continuity handling.
    membership_test: returns n/means/auc/p_value and is_member = (p < ALPHA and auc > 0.5).
  generate_watermarks(n, seed): n "served" + n "control" watermark sentences, each with a
    unique 12-char nonce so it cannot occur naturally on the web. Served docs are meant to
    be embedded in honeypot pages; control docs are generated identically but NEVER served
    — the statistical null.
  Backends: MockScorer (deterministic; a "memorized" set gets high log-probs, others low —
    so the whole statistic + test plumbing runs with no model), LocalHFScorer (a real HF
    causal LM: full logits -> true Min-K%++ via log_softmax per position), OpenAILogprobScorer
    (a Completions endpoint with echo+logprobs -> chosen-token log-probs -> Min-K% only).
    get_scorer chooses by MEMBERSHIP_BACKEND.
  run_membership(served, control, scorer, k): score both sets, run membership_test, attach
    the raw scores + k + the statistic actually used. This is what the UI demo invokes (with
    a MockScorer seeded to memorize the served set, so served tests as member, control doesn't).

--------------------------------------------------------------------------------
 5.15  querying/rag_disambiguation.py  — memorization vs live retrieval (6b)
--------------------------------------------------------------------------------
A model can "know" a canary because it TRAINED on it or because it BROWSED to it at
query time (RAG). This separates them:
  _logdb_json / _live_fetches(site, since_iso): query the central all_visits for requests
    to `site` since the query started that are NOT our own probe UA. A non-probe request
    arriving DURING the query window is the fingerprint of the model browsing to the page
    live (retrieval), not memory.
  disambiguate_model(model, ...): query with browsing OFF (leak_off) and ON (leak_on),
    check live fetches, and classify:
      leak_off -> "memorized (training ingestion)" (confidence HIGH if page_removed,
        since there's nothing left to fetch — decisive);
      leak_on and not leak_off -> "retrieved (live RAG)" (HIGH if a live fetch was seen);
      else "no evidence".
  run_rag_experiment(...): scrape (tolerating a removed page — uses a placeholder subject),
    load rows (site DB or CSV), build the leak context, disambiguate each model, persist a
    report (reusing provenance._runs_dir). Has its own CLI with --page-removed. The
    serve-once-then-remove step is operational (take the page down via the Site Configurator
    first); this module implements the query-side logic + the all_visits correlation.

================================================================================
 PART 6 — CRAWLER-GRAPH INTELLIGENCE  (crawler_graph/)
================================================================================

Answers question (B): "who is crawling me, and are they disguising themselves?" It
fuses the four fingerprint layers per visitor, builds an identity graph, clusters it
into campaigns, runs the cross-layer consistency engine, and (optionally) trains a
GraphSAGE GNN to attribute providers. The central thesis (from the reference doc):
modern fingerprinting hunts for INTERNAL CONTRADICTION, not rarity — a genuine device
is self-consistent across browser/network/OS layers; bots betray themselves with
improbable combinations (a Chrome UA rendering through a Firefox pipeline, an iOS
handshake on a Linux kernel).

--------------------------------------------------------------------------------
 6.1  crawler_graph/config.py  — the tunables (read this first; everything keys off it)
--------------------------------------------------------------------------------
logdb access: the DOCKER-EXEC path by default (shells `docker compose exec logdb psql`
like request_log), OR a DIRECT psycopg2 connection when LOGDB_HOST is set (used inside
the app container, attached to proxy_net, where "logdb" resolves).
  MAX_VISITS = 50000; SINCE_HOURS = 0 (no lower bound).
  EDGE_WEIGHTS — how strongly a SHARED attribute implies "same actor" (these are the
    community-detection edge weights). The ranking is the whole intelligence model:
      fpid    7   composite device id (strongest — same physical machine)
      canvas  6   shared canvas hash (device)
      webglfp 6   shared WebGL hash (device)
      ja      5   shared JA3/JA4 (same TLS client stack)
      audio   5   shared AudioContext hash (device)
      ua      3   shared EXACT User-Agent
      net     3   shared /24 (or v6 /64)
      font    3   shared installed-font set
      ja4h    3   shared HTTP-header signature
      asn     1   shared ASN (weakest — millions of unrelated hosts share one)
    The device-fingerprint hubs (canvas/webgl/audio/font/fpid) are weighted as strongly
    as (or stronger than) a TLS fingerprint because a shared device hash means the SAME
    physical machine even across IP changes, cleared cookies, and proxy rotation. ja4h is
    the HTTP-header signature (weaker, like a shared exact UA).
  ATTR_HUB_CAP = 400 — drop attribute hubs touching more than this many IPs (a giant
    shared ASN is noise, not a campaign); 0 disables.
  DISGUISE_MIN_SHARE = 0.5. SYSTEMATIC_MIN_REQ_PER_IP = 8 (mean requests/IP above which a
    cohort reads as systematic crawling vs casual browsing — separates a stealth crawler
    from an agentic-browser population).
  VM_RENDERER_MARKERS — substrings that mark a virtual display adapter / software
    rasterizer / common cloud GPU (swiftshader, llvmpipe, microsoft basic render, mesa
    offscreen, ANGLE-software, vmware, virtualbox, qemu, apple paravirtual, nvidia grid,
    tesla t4/v100, etc). Matched case-insensitively. DELIBERATELY NARROW: the broad
    substrings "software"/"gallium"/"virgl"/"google angle (google, vulkan" were removed
    because they also appear in legitimate Chrome-on-Linux / Android ANGLE-Vulkan and
    Mesa renderer strings (a false-positive source). Genuine software rasterizers are
    still caught by the specific names here AND by the fp.js swRenderer tell.
  STRONG_AUTOMATION_TELLS = {webdriver, cdc, headlessua, tostringtampered} +
    WEAK_AUTOMATION_MIN = 2. A STRONG tell (things a real browser never trips) marks a
    visitor automated on its own; WEAK tells (noPlugins/noMimeTypes/chromeMissing/
    swRenderer/zeroHardware/languagesEmpty/permissionsAnomaly — each individually true
    for real privacy browsers / VMs / WebViews) require >=2 before calling automation.
    This replaces the old "any single tell (score>=1) => automated", the AUTO
    false-positive source. (consistency.automated_from_tells implements it.)
  DISGUISE_MIN_UAS = 2, DISGUISE_MIN_NETBLOCKS = 2 — a device (by fp_id) is flagged
    disguised when its beacons span >= this many distinct User-Agents or /24 netblocks.
  CONSISTENCY_WEIGHTS — the cross-layer contradiction scores: os_ua_vs_tcp 3 (the
    headline "kernel betrays a spoofed OS"), os_js_vs_tcp 3, os_ua_vs_js 2, vm_cohort 2,
    automation 2, synthetic_behavior 1, browser_no_js 1.
  INCONSISTENCY_FLAG_SCORE = 3 (total score at/above this = an inconsistency).
  TRUST_TCP_FROM_PRIVATE = 0 (OFF by default). WHY OFF: the local build NATs every
    visitor through the Docker userland proxy, so the captured SYN is the PROXY HOST'S
    kernel (every visitor reads "Linux") — trusting it would flag a real Windows/macOS
    browser as an OS spoof. Set to 1 only for a genuine same-LAN / source-preserving-DNAT
    deployment. (This is the single most important "why doesn't it flag my own browser"
    knob.)
  Artifact paths: ASN_CACHE, CAMPAIGNS_JSON, GRAPH_VIZ (png), GRAPH_VIZ_HTML
    (interactive), GNN_MODEL (.pt), GNN_PREDS (.json), CRAWLER_RANGES (optional published
    CIDRs).

--------------------------------------------------------------------------------
 6.2  crawler_graph/pipeline.py  — run_intel (the orchestrator)
--------------------------------------------------------------------------------
run_intel(visits=None, handshakes=None, browser_fps=None, tcp_fps=None, limit,
since_hours, resolve_asn, use_gnn, method, write, render): if a data arg is None it
loads it from logdb (each wrapped so a missing table -> []); if provided, uses it as-is
(the offline selftest + tests inject synthetic data). Then:
  1. enrich.join_fingerprints(visits, handshakes)        (Layer-2 TLS by 4-tuple)
  2. enrich.join_tcp_fingerprints(visits, tcp_fps)        (Layer-2 TCP/OS by 4-tuple/IP)
  3. enrich.enrich_visits(visits, resolve_asn)            (ASN/netblock/UA flags/ja4h)
  4. endpoints = enrich.aggregate_endpoints(visits)       (one record per IP)
  5. enrich.attach_browser_fingerprints(endpoints, browser_fps)  (Layer-1 by IP)
  6. consistency.annotate(endpoints)                      (Layer-3 contradiction engine)
  7. full_graph = graph.build_graph(endpoints)            (bipartite IP+attr graph)
  8. membership, method_used = community.detect_communities(full_graph)
  9. ip_graph = graph.project_to_ip_graph(full_graph)     (weighted IP-IP for the GNN)
  10. if use_gnn: features.build_arrays(ip_graph, endpoints) -> gnn.train_classifier;
      persist predictions + model (best-effort).
  11. camps = campaigns.build_campaigns(full_graph, membership, endpoints, gnn_preds)
  12. assemble meta (counts, modularity, the gnn summary, contradiction/VM counts,
      duration), result = {meta, findings, campaigns}.
  13. if write: report.write_campaigns + (if render) report.render_graph (PNG) +
      report.render_interactive (HTML).
_gnn_meta(...) packages the GNN training run (requested/used/reason/method/classes/
accuracies/n_attributed) for the report.

 6.3  crawler_graph/ingest/db.py  — read logdb (migration-resilient)
--------------------------------------------------------------------------------
_docker_exec_json (shell psql) or _direct_json (psycopg2, when LOGDB_HOST). Each fetch
selects a single json_agg and degrades:
  fetch_visits: tries WITH client_port; on "client_port does not exist" retries WITHOUT
    it (so the cheap graph works on an un-migrated DB). Always includes headers (for JA4H).
  fetch_handshakes: [] if tls_handshakes doesn't exist; retries with a minimal column set

--------------------------------------------------------------------------------
 6.4  crawler_graph/ingest/enrich.py  — the heart of the four-layer fusion
--------------------------------------------------------------------------------
asn_for_ip(ip): ipwhois RDAP lookup, CACHED to output/asn_cache.json so repeated runs
don't re-hit RDAP. (None,None) on failure.
netblock(ip): IPv4 /24 (drop last octet) or IPv6 first-4-hextets — matches server.py.
join_fingerprints(visits, handshakes): index handshakes by (src_ip, src_port); for each
  visit with a client_port, pick the handshake with the GREATEST ts <= the request ts
  (handles port reuse) and attach ja3/ja4/sni. One TLS connection (one ClientHello, one
  fingerprint) maps to the MANY requests it carried (HTTP/2 multiplexing / keep-alive).
join_tcp_fingerprints(visits, tcp_fps): same 4-tuple "latest at or before" join for
  tcp_os + ja4t, with an IP-only fallback (a SYN may have arrived on a sibling connection).
compute_ja4h(headers, method): a JA4H-style HTTP-header signature from the ALREADY-STORED
  request headers (no new capture). Excludes the proxy's injected headers (_PROXY_HEADERS:
  x-site, x-real-ip, x-client-port, x-forwarded-*, connection, host). Encodes: method[:2]
  + header-name count + cookie-present + referer-present + the first accept-language token
  (4 chars) + a sha256[:12] of the ordered header-name list (excluding cookie/referer per
  JA4H convention). It's lossy behind nginx but the header SET + count + lang still differ
  sharply between real browsers and automation libs (python-requests/Go/curl send a tiny
  distinctive header set). None when there are no client headers.
enrich_visits(visits, resolve_asn): per visit add netblock, asn/asn_descr (RDAP if
  resolve_asn else the pre-attached value), provider_ua (known_crawlers.provider_for_ua),
  is_browser, is_automated, ja4h. Saves the ASN cache once at the end.
_timing_features(timestamps): from sorted timestamps -> mean_gap, std_gap, span_s, and
  BURSTINESS B = (std-mean)/(std+mean) in [-1,1] (+1 very bursty, 0 Poisson, -1 perfectly
  regular/metronomic). A metronomic sustained cohort reads as automated infra.
_entropy(counter): Shannon entropy (used for path/UA/hour diversity).
aggregate_endpoints(visits): GROUP BY client_ip -> one ENDPOINT record per IP with:
  n_requests, the UA counter + ua_top + n_user_agents, sites, n_paths, path_entropy,
  ua_entropy, hour_entropy, the ja3/ja4/ja4h SETS, tcp_os set (minus "unknown"), ja4t set,
  has_fingerprint (ja3 or ja4), providers_ua set, is_declared_crawler, is_browser,
  is_automated, first_ts/last_ts, and the timing features. THESE endpoints are the graph
  nodes and the GNN feature rows.
attach_browser_fingerprints(endpoints, browser_fps): fold Layer-1 fingerprints onto the
  per-IP endpoints BY IP (the fp.js beacon arrives on a SEPARATE connection from the page
  load, so it can't be 4-tuple-joined — same physical visitor, same source IP). Adds the
  device-correlation keys (canvas/webgl_fp/audio/font/fpid sets), webgl_renderers,
  js_platform (navigator.platform), the MERGED automation tells + max automation_score,
  behavior_synthetic/interacted, has_browser_fingerprint, and n_device_keys. Every endpoint
  gets the fields DEFAULTED (so the graph + GNN read them uniformly even for non-JS IPs).

 6.5  crawler_graph/ingest/known_crawlers.py  — declared-crawler ground truth
--------------------------------------------------------------------------------
CRAWLER_UA_PATTERNS: ~20 regex -> provider (GPTBot/OAI-SearchBot/ChatGPT-User->OpenAI,
ClaudeBot/anthropic-ai/Claude-*->Anthropic, PerplexityBot->Perplexity, Googlebot/
Google-Extended->Google, Bingbot->Microsoft/Bing, Applebot, Amazonbot, Bytespider->
ByteDance, CCBot->CommonCrawl, Meta-*->Meta, etc). First match wins.
  provider_for_ua / is_declared_crawler.
  BROWSER_UA_RE: "looks like a real browser engine". is_browser_ua = matches browser RE
    AND is not a declared bot — the population where agentic AI browsers hide (only TLS/JA
    fingerprints, not the UA, can separate them).
  AGENT_UA_HINTS: Headless/Electron/puppeteer/playwright/python-requests/Go-http-client/

  Optional published-IP-range verification: load_ranges(crawler_ranges.json) -> {provider:

--------------------------------------------------------------------------------
 6.6  crawler_graph/graphing/builder.py  — the identity graph
--------------------------------------------------------------------------------
build_graph(endpoints): a BIPARTITE graph with two node kinds:
  - "ip" nodes (one per client IP, the actors), carrying the endpoint features.
  - "attr" nodes (one per shared attribute VALUE: a JA4 hash, an exact UA, a /24, an ASN,
    a canvas/webgl/audio/font/fpid hash, a ja4h). 
  Pass 1 collects attr -> set(ips) memberships (JA4, or JA3 if no JA4; every UA; netblock;
  ASN; and each device key + ja4h). Pass 2 adds an attr hub ONLY if >=2 IPs share it
  (a singleton links nothing) and <= ATTR_HUB_CAP IPs (a giant hub is noise), then connects
  each member IP to the hub with the attribute's EDGE_WEIGHT. The attr-hub design keeps edge
  construction LINEAR (not O(IPs^2)) and naturally ties together a disguised fleet that
  rotates IPs/ASNs but reuses one TLS stack or one device fingerprint (the shared hub holds
  them together even when nothing else does).
project_to_ip_graph(graph): collapse to a weighted IP-IP graph — two IPs sharing an attr
  hub get an edge whose weight is the SUM over shared hubs of each hub's weight (so two IPs
  sharing a JA4 AND a /24 are strongly tied). This homogeneous graph is what the GraphSAGE
  GNN and the visualization consume.
graph_summary: ip_nodes / attr_nodes / edges / connected components.

--------------------------------------------------------------------------------
 6.7  crawler_graph/graphing/community.py  — community detection
--------------------------------------------------------------------------------
detect_communities(graph, method): tries Louvain (python-louvain, best_partition, seeded
42), then Leiden (leidenalg + igraph, seeded 42), then networkx greedy_modularity — so it
works with ZERO optional deps. Returns {node: community_id} for ALL nodes (attr hubs too,
filtered out by the caller) + the method used. modularity(graph, membership): the partition
quality score (groups only nodes present in the graph). community_sizes counts IP nodes per
community (ignoring hubs).

--------------------------------------------------------------------------------
 6.8  crawler_graph/graphing/campaigns.py  — communities -> campaigns + findings
--------------------------------------------------------------------------------
build_campaigns(graph, membership, endpoints, gnn_preds, ranges): group IP nodes by
community, summarize each, sort by (n_requests, n_ips) desc, assign campaign_id by rank.
_summarize(cid, recs, gnn_preds, ranges) is where the flags are computed:
  Aggregates per community: ASNs, netblocks, ja3/ja4 sets, UA counter, declared-provider
  counter, GNN-vote counter, n_requests, sites, browser/automated/fingerprinted IP counts,
  ja4h set, tcp_os counter, device canvas/webgl/fpid sets, browser-FP IP count, VM/automation/
  contradiction IP counts (from each rec's consistency verdict), the inconsistency reasons,
  first/last seen, mean burstiness.
  shared_fp = there's a fingerprint AND <= max(1, round(0.25*n_ips)) distinct ones dominate
    the cohort (ONE TLS stack across otherwise-disparate IPs).
  multi_asn = >1 ASN. systematic = mean_req_per_ip >= SYSTEMATIC_MIN_REQ_PER_IP.
  range_violations: declared-crawler UAs whose IP falls outside the provider's published
    ranges.
  DISGUISE REASONS (the actual research signal — any one raises disguise_suspected):
    (a) range_violations present (impersonation / undeclared infra);
    (b) shared_fp AND multi_asn AND no declared providers AND (systematic or automated) —
        one TLS fingerprint across multiple ASNs at crawl volume on browser/automation UAs
        with no bot UA (the stealth-crawling signature);
    (c) a GNN provider on a cohort with no declared bot UA but browser/automation IPs;
    (d) shared_device (one canvas OR webgl OR fp_id value dominating, checked PER KEY TYPE
        so a device legitimately having both a canvas and an fp_id doesn't over-count) AND
        multi_asn — the same physical machine rotating IPs/proxies;
    (e) contradiction_ips > 0 — cross-layer contradictions present.
  AGENTIC: not disguised AND browser_share>=0.5 AND shared_fp AND no declared providers AND
    automated_ips==0 AND not systematic — a coherent real-browser fingerprint on browser UAs
    at CASUAL volume (the agentic-AI-browser population). Disguise takes precedence when both
    could apply.
  _label(declared, gnn_provider, disguise_reasons, agentic): declared-and-unflagged ->
    "X (declared)" HIGH; disguised -> "Suspected undeclared / disguised — X" MEDIUM; agentic
    -> "Suspected agentic browser" MEDIUM; gnn-only -> "X (GNN-attributed)" LOW; else
    "Unattributed campaign" LOW.
  The returned campaign dict carries EVERYTHING the _campaigns.html template renders (label,
  confidence, ips/requests, asns, declared/gnn providers, ja4/ja3, shared_fingerprint,
  mean_req_per_ip, systematic, first/last seen, mean_burstiness, top UAs, sites, browser/
  automated/fingerprinted counts, disguise_suspected + reasons, agentic_suspected,
  range_violations, ja4h, tcp_os breakdown, browser_fingerprinted_ips, device_fingerprints,
  shared_device_fingerprint, vm/automation/contradiction counts, inconsistency_reasons,
  vm_cohort_suspected, contradiction_suspected, sample_ips).
findings(campaigns): the headline lists (n_campaigns/disguised/agentic/vm_cohort/
  contradiction + the actual campaign lists) for the page.

--------------------------------------------------------------------------------
 6.9  crawler_graph/analysis/consistency.py  — the cross-layer contradiction engine
--------------------------------------------------------------------------------
The reference doc's central thesis, implemented per endpoint. Deliberately CONSERVATIVE to
bound false positives on privacy-hardened real users.
  os_from_ua(ua): coarse OS family from the UA. Android/ChromeOS map to "Linux" (they ARE
    Linux kernels) so an Android UA on a Linux SYN is CONSISTENT (no false contradiction).
  os_from_platform(platform): OS family from JS navigator.platform (a separate spoof surface).
  tcp_os_is_trustworthy(rec): TRUE only when the client IP is routable PUBLIC (or
    TRUST_TCP_FROM_PRIVATE). Behind a local NAT / Docker userland-proxy the SYN is the proxy
    host's kernel, so the OS inference is meaningless for spoof detection — every visitor reads
    as the proxy's kernel. This is why the engine OBSERVES the TCP OS for local visitors but
    never lets it ACCUSE them.
  dominant_tcp_os(rec): the unambiguous SYN-derived OS, dropping "Network/BSD" and only
    returning a family when EXACTLY ONE meaningful value is present (multiple distinct OSes
    from one IP usually means NAT (many devices), which must not be misread as a contradiction).
  _vm_cohort(rec): the offending renderer string if a webgl_renderer matches a
    VM_RENDERER_MARKER, or "software renderer" if the swRenderer automation tell is set.
  _behavior_class(rec, automation): no-js / synthetic / automated / human / passive.
  score_endpoint(rec): emits concrete contradictions + a weighted score:
    - tcp_trusted AND ua_os != tcp_os -> "UA claims X but the TCP/IP stack looks like Y
      (kernel betrays a spoofed OS)" (+3). THE headline signal.
    - tcp_trusted AND js_os != tcp_os -> navigator.platform vs the kernel (+3).
    - ua_os != js_os -> UA vs navigator.platform (+2).
    - vm renderer -> +2.
    - automation (automated_from_tells(tells): a STRONG tell, or >=2 WEAK tells; OR the
      UA-derived is_automated for declared crawlers) -> "automation tells present (...)"
      (+2). NOTE: no longer "score>=1" — that flipped real privacy/VM/WebView users to
      automated on one benign tell.
    - behavior_synthetic -> "synthetically humanized" (+1).
    - browser UA that fetched the page but never ran JS (no fingerprint beacon) -> +1.
    Returns {contradictions, score, inconsistent (score>=INCONSISTENCY_FLAG_SCORE),
    vm_cohort, automation, behavior_class, claimed_os, js_os, tcp_os, tcp_os_trusted}.
  annotate(endpoints): attach a consistency verdict to every endpoint IN PLACE. THIS is the
    exact function fingerprint_service.verdict_for calls per request (on a one-request
    endpoint-shaped record), so per-request and per-campaign verdicts match.

--------------------------------------------------------------------------------
 6.10  crawler_graph/ml/features.py  — node feature engineering (no torch)
--------------------------------------------------------------------------------
FEATURE_NAMES: a 22-dim vector — log_n_requests/sites/paths, path/ua/hour entropy,
n_user_agents, has_fingerprint, is_browser, is_automated, burstiness, log_mean_gap,
log_span_s, then the Layer-1/2/3 additions: has_browser_fp, log_n_device_keys,
automation_score, inconsistency_score (the consistency engine's score), vm_cohort,
tcp_os_windows/apple/linux (one-hot), behavior_synthetic. node_vector(rec) maps an endpoint
to these floats (log1p for counts). build_arrays(ip_graph, endpoints): returns nodes (the
IP row order), x (feature matrix), edge_index (2xE, both directions for the undirected graph),
edge_weight, y (integer provider labels, -1 unlabeled), labels (the provider vocab), and
train_mask (True only when the endpoint has EXACTLY ONE declared provider — high-precision
seeds). The model predicts providers for the UNLABELED IPs, and a confident prediction on a
browser/automation IP is a disguise signal.

--------------------------------------------------------------------------------
 6.11  crawler_graph/ml/gnn.py  — the GraphSAGE classifier
--------------------------------------------------------------------------------
torch + torch_geometric imported LAZILY inside functions (importing the module/package never
requires them; torch_available() gates callers). They're baked into the app image so the GNN
trains in-process from the /logs page.
  _build_model: a 2-layer SAGEConv encoder (in_dim->hidden->hidden, ReLU + 0.3 dropout) + a
    linear classification head.
  _to_tensors: standardizes features column-wise (mean/std, clamp_min 1e-6) for stable training.
  _split_labeled: a STRATIFIED train/val split over the labeled nodes (each class keeps >=1 in
    train; classes with >=3 contribute ~val_frac to val) so the model can report
    GENERALIZATION (val accuracy), not just fit.
  train_classifier(arrays, ...): GUARDS first —
    no labels -> skip; <2 provider classes -> skip (a single-class model is degenerate: it
    predicts that one provider for everyone at confidence ~1.0 and would spray bogus disguise
    flags — it needs >=2 classes to learn anything that separates infrastructure); too few
    labeled nodes -> skip; no torch -> skip. Each skip returns {predictions:{}, reason:...} so
    callers fall back to community-only attribution. Otherwise: train epochs of cross-entropy
    on the train mask, evaluate val accuracy each epoch, KEEP THE BEST-VAL CHECKPOINT, then
    predict a provider + confidence for EVERY IP. Returns the predictions + labels + n_labeled
    + n_val + final_loss + train_acc + val_acc + method, plus non-serializable _model/_mean/_std
    handles for save_model.
  save_model / load_and_predict: round-trip the weights + label map + feature normalization
    (so a reloaded model gives identical predictions). save_predictions strips the "_" handles
    and writes gnn_predictions.json. train_embeddings: an unsupervised GraphSAGE encoder with a
    neighbor-contrastive loss (positive = connected pairs close, negative = random pairs apart)
    for KMeans/HDBSCAN campaign discovery when labels are scarce.
  THE POINT: message passing propagates a provider label across graph STRUCTURE to covert,
  UA-less nodes that merely share a provider's ASN — attributing disguised infrastructure the
  UA alone cannot surface. The selftest's _gnn_check proves exactly this (covert cohorts wearing
  a browser UA but sharing a declared provider's ASN are attributed to that provider).

--------------------------------------------------------------------------------
 6.12  crawler_graph/reporting.py  — persist + visualize
--------------------------------------------------------------------------------
write_campaigns/read_campaigns: the campaigns.json the /logs page reads (generated_at + meta
+ findings + campaigns).
_grouped_layout(graph, membership): a CUSTOM community-aware layout. A global spring layout is
the wrong tool — the campaigns are cross-linked through shared /24/ASN/UA hubs, so a global
layout collapses them into one indistinct blob and flings any disconnected component off-screen.
Instead: (1) lay out each community's induced subgraph LOCALLY and scale it to radius ~sqrt(size)
(uniform node density across clusters); (2) pack the cluster CENTRES with a short circle-seeded
force relaxation (mutual repulsion when two disks would overlap + gentle gravity toward the
centroid) so clusters spread into their own regions yet stay a compact cloud; (3) drop each node
at its centre + local offset; normalize to [-1,1]^2. Deterministic (seeded), fast at this size.
render_graph(ip_graph, membership): a matplotlib PNG. Caps to the top max_nodes by degree for
legibility. Splits edges into INTRA-cluster (drawn faint, showing cohesion) vs genuinely STRONG
cross-cluster BRIDGES (weight >= _BRIDGE_MIN_WEIGHT=5.0, drawn bold in the alert colour). Weak
single-attribute cross-links (a shared generic UA/ASN — nearly every cross-cluster edge) are NOT
drawn (the community detector already discounted them; drawing thousands buries the clusters in
a hairball). Nodes colored by community (tab20).
render_interactive(ip_graph, membership, campaigns): a SELF-CONTAINED HTML graph (no CDNs/libs).
_campaign_color uses a golden-angle hue sweep so consecutive campaigns land far apart on the hue
wheel (every cluster an obviously different colour). SVG nodes (radius ~ sqrt(n_requests)) colored
per campaign; intra-cluster edges faint, strong bridges bold (same rule as the PNG). _rundown_html
builds the per-cluster hover card (flag chips + IPs/requests/ASNs/JA4/browser-FP counts + providers
+ ASNs + top UA + sample IPs + the first inconsistency reason). A clickable legend isolates a
campaign's nodes (the embedded JS dims the rest). The whole thing is wrapped in try/except so
rendering NEVER fails a run.

 6.14  crawler_graph/tests/test_pipeline.py  — the offline selftest (executable proof)
--------------------------------------------------------------------------------
_synth_visits() synthesizes SIX labeled populations in the exact row shapes the ingest layer
consumes: (1) honest GPTBot (one ASN, declared UA, systematic) + (1b) honest ClaudeBot (a 2nd
declared class for the GNN); (2) human browsers (varied UAs, UNIQUE device fingerprints, fully
consistent UA/JS/TCP, scattered ASNs, low volume — must NEVER flag); (3) a DISGUISED stealth
fleet (Windows UA + Win32 across MANY ASNs sharing ONE JA4 at crawl volume, with a Linux SYN
contradicting the Windows UA); (4) an AGENTIC browser cohort (shared JA4, casual volume, fully
self-consistent Apple UA+MacIntel+Apple SYN); (5) a PROXY-ROTATOR (one canvas+fp_id across 4
ASNs — the ONLY tie is the device fingerprint); (6) a VM/headless cohort (SwiftShader renderer).

honest crawlers attributed & UNFLAGGED, stealth -> disguise + contradiction, agentic -> agentic
(not systematic), the rotator's 4 IPs STITCHED into ONE campaign via the device fingerprint
(asserts len(stitched)==1 and shared_device_fingerprint), VM cohort flagged. _run_gnn_check
synthesizes covert cohorts (browser UA but sharing a declared provider's ASN) and asserts the

with 0 mismatch. This file is the executable proof the entire intelligence layer works without
a database or any keys.

================================================================================
 PART 7 — THE TEMPLATE GENERATOR  (template_generator/)
================================================================================

The standalone ML pipeline LoRA-fine-tunes Qwen3-1.7B to author new honeypot pages.
prepare_data.py and train.py read the sibling corpora and write under
template_generator/. generate_templates.py also writes its direct CLI output under
the requested output directory. The INTEGRATED web workflow is intentionally not
self-contained: app/services/template_gen.py runs the generator in a temporary
directory, then copies each successful HTML file into website/templates/scraperN.html
and records history in configs/history/generations.jsonl. It does not install the
generated .txt varlist. In the container, torch/transformers/peft are baked into the
app image and TEMPLATE_GEN_PYTHON merely selects the subprocess interpreter; on a
host-only run a separate environment may still be needed. The standalone pipeline
is prepare_data.py -> data/sft.jsonl; train.py -> models/qwen3-1.7b-townlora/;
generate_templates.py -> generated_templates/scraper_gen_*.{html,txt}.

--------------------------------------------------------------------------------
 7.1  template_generator/prepare_data.py  — build the SFT dataset
--------------------------------------------------------------------------------
Builds data/sft.jsonl from two corpora, normalized to the same two placeholder tokens
[[NAME]] and [[NUM]] paired with a writing instruction:
  cleaned_intros/  — Wikipedia-style town INTROS already masked as <var_name>/<var_num>
    (with bracket/spacing noise). normalize_intro collapses those markers to
    [[NAME]]/[[NUM]] and tidies.
  wikipedia_towns_text/ — FULL raw articles with NO placeholders, masked HERE with spaCy
    NER (NAME_LABELS -> [[NAME]], NUM_LABELS -> [[NUM]]). This teaches the longer, multi-
    section prose real pages are made of.
  Heavy hygiene (the part that matters for keeping canaries meaningful):
    fix_mojibake (repairs UTF-8-decoded-as-cp1252 artifacts), clean_wiki (strips IPA
    pronunciations, [citation], "(listen)", lat/long COORDinates, bare degree marks),
    mask_numbers (POP_NAME_RE forces a population-as-name mistag to [[NUM]];
    LITERAL_NUM_RE masks any leaked literal number), names_from_filename +
    mask_leaked_names (SCRUBS the article's OWN subject name — derived from the filename,
    e.g. "Gig_Harbor_Washington" -> town + state — which NER sometimes misses, so no real
    place name survives into a target), DISAMBIG_RE (skips "X may refer to" pages),
    SKIP_HEADINGS (drops References/External links/etc), HEADING_RE (splits sections).
  split_sections yields (kind, body) for the intro + each non-meta section; section_kind
    maps headings to history/geography/demographics/generic. to_paragraphs splits bodies.
    mask_with_spacy / _mask_docs apply the NER masking (right-to-left so char offsets stay
    valid) over a batched nlp.pipe stream, then scrub leaked names/numbers. chunk_examples/
    emit group masked paragraphs into target-word-range examples with enough placeholders.
  Instructions: INTRO_INSTRUCTIONS + SECTION_INSTRUCTIONS (a little variety per section kind
    so the model generalizes the task). spaCy is OPTIONAL: without it the Wikipedia corpus is
    skipped with a warning and the dataset is built from cleaned_intros alone (always produces
    a usable sft.jsonl). Output: {"instruction": <task>, "target": <placeholder prose>} per line.

--------------------------------------------------------------------------------
 7.2  template_generator/train.py  — LoRA fine-tune Qwen3-1.7B
--------------------------------------------------------------------------------
A HAND-ROLLED training loop (no Trainer/accelerate), tuned for Apple Silicon (MPS) /
limited RAM: gradient checkpointing, batch size 1 + gradient accumulation, attention-only
LoRA adapters (the 1.7B base stays FROZEN), fp32 by default for stable optimization on MPS.
  apply_chat: renders the Qwen chat template to text (disabling "thinking") then re-encodes
    (transformers 5.x tokenize=True returns an Encoding object, not the int list collate needs).
  build_example: tokenize one (instruction -> target) pair and MASK the prompt tokens in the
    labels with -100 (train only on the assistant's target, not the instruction).
  JsonlSFT Dataset + collate (left/right pad to the batch max, pad labels with -100, build
    the attention mask).
  main: pick device (mps/cuda/cpu) + dtype; load the tokenizer (pad=eos if needed) + base
    model; build the LoraConfig (r/alpha, target_modules = q/k/v/o, or +gate/up/down for "all");
    get_peft_model; enable gradient checkpointing + input grads; if fp16 keep the trainable
    params in fp32 (no CUDA loss scaler on MPS). Held-out val split (val_frac). AdamW over only
    the trainable params; a cosine schedule with warmup over total_steps. The training loop does
    grad-accum (loss/grad_accum backward, step every grad_accum micro-batches, clip grad norm 1.0),
    prints loss/lr per optimizer step, runs validation every eval_every, and saves the ADAPTER ONLY
    (model.save_pretrained + tok.save_pretrained) at the end (+ optional step checkpoints). The base
    model is downloaded from HF into the cache and never modified.

--------------------------------------------------------------------------------
 7.3  template_generator/generate_templates.py  — author pages from the model
--------------------------------------------------------------------------------
Per template: prompt the model ONCE PER SECTION (SECTION_SPECS: overview/history/geography/
demographics) so the page is multi-section prose like a real article, keeping later sections
about the SAME town by feeding back the already-written intro. Then ASSEMBLE the prose into a
canary-slotted HTML page. The assembly is the clever part — three things that keep canaries
meaningful:
  (a) MASK LEAKED LITERALS: the 1.7B model often writes a real number/coordinate instead of its
      [[NUM]] placeholder. mask_literals strips coordinates + degree marks and converts every
      literal number to [[NUM]] (so it routes to a numeric canary slot instead of baking a static
      number into the page — a static number is useless as a per-visitor canary AND a memorization
      tell). fix_mojibake + tidy clean the prose.
  (b) TYPE-AWARE SLOT MAPPING (TypedVarCycler): the model emits generic [[NAME]] for towns,
      counties, people, institutions alike. classify_name uses surrounding-word CUES (PERSON_CUES
      "named after"/"founder"/"mayor"; ORG_CUES "university"/"company"/"railroad"; AFTER_PERSON_CUE
      "[[NAME]] was the original mayor") to type each [[NAME]] as place/person/org, and classify_num
      types each [[NUM]] as year/percent/count. Each placeholder is routed to a {{ varN }} whose
      Faker expression matches that type, so the grammar reads (no "founded in {{ surname }}"). The
      town's own name stays {{ var1 }} (a sentence-initial place becomes the subject). build_slots
      maps the 10 typed slots to Faker expressions (NAME_TEMPLATE place/person/org cycle +
      NUM_TEMPLATE count/year/percent); var_expressions writes them to the .txt varList in the
      scraper1.txt format.
  (c) DENSITY TRIMMING (trim_section): the census/demographics paragraph is a 30-number stat dump;
      with only ~4 numeric slots the same four numbers would repeat dozens of times (an obvious
      "generated" tell). It keeps whole sentences until the per-section placeholder budget
      (--max-section-placeholders) is hit.
  STRUCTURAL VARIETY: assemble_template shuffles the non-intro sections, occasionally drops one
    (never below 2 content sections), picks heading SYNONYMS (HEADING_SYNONYMS), varies paragraph
    grouping (2-4 sentences), and appends a randomized "Notable Landmarks" list — so many generated
    pages aren't the byte-identical skeleton.
  OUTPUTS to generated_templates/: scraper_gen_<i>.html (the deployable page with {{ var1 }}..
    {{ var10 }} slots), scraper_gen_<i>.txt (its 10-line Faker varList), raw_<i>.txt (the raw
    per-section model output, the input --reprocess reads back).
  --reprocess rebuilds the .html/.txt from existing raw_*.txt WITHOUT loading the model (iterate on
    assembly logic CPU-only). --base-only few-shot-prompts the un-fine-tuned base model for a
    before/after comparison. torch/transformers/peft are imported LAZILY inside the model path so
    --reprocess and -h work without them.

  CURRENT IMPLEMENTATION WARNING: assemble_template() does not emit the
  `<script src="/js/fp.js" defer></script>` tag even though all five checked-in templates contain
  it and the generator module calls its output “deployable.” app/services/template_gen.py validates
  only that scraper_gen_*.html files exist; it does not validate the script or slot coverage before
  copying them. Therefore a newly generated-and-installed flavor can silently lose Layer-1 browser
  fingerprinting. The static contract test checks stored website/templates, not generator output, so
  it does not catch this before installation. Treat “deployable” here as intended, not fully validated.

A convenience wrapper that runs prepare_data -> train -> generate end to end
(run_windows.ps1 is the Windows/NVIDIA equivalent).


================================================================================
 PART 8 — THE TEST SUITE  (testsuite/)
================================================================================

An OFFLINE, DETERMINISTIC pytest suite: no Docker daemon, no Postgres, no API keys, no
network. The external seams (the host Docker CLI, the logdb/site psql calls, the Ansible
playbook, the model providers) are monkeypatched, and traffic is synthesized in-process.
It exercises the project's OWN code (the canary generators, the UA parser, the crawler-graph
clustering + the real GraphSAGE GNN, the consistency engine, querying/provenance, the proxy
collectors, the FastAPI routes). It is FAST REGRESSION COVERAGE — it does NOT replace the
live-deploy verification loop (it stubs Docker/nginx/Postgres, so it can't catch routing/TLS/
real-DB-write regressions).

--------------------------------------------------------------------------------
 8.1  testsuite/run_tests.py  — the runner
--------------------------------------------------------------------------------
A configurable wrapper over pytest. FEATURES is the single source of truth: a map of
feature-name -> (test file, pytest marker, description) for 12 features (honeypot,
fingerprinting, clustering, gnn, querying, provenance, logging, analytics, sites, generator,
webapp, contracts). A ResultCollector pytest plugin (pytest_collection_modifyitems captures
each test's docstring; pytest_runtest_logreport captures outcome/duration/skip-reason/failure;
pytest_sessionfinish captures the exit status) builds a payload grouped BY FEATURE. write_reports
emits reports/latest.{json,html}; print_summary prints a per-feature OK/FAIL table + explicit
failures + skip reasons. CLI: positional feature names or -f/--feature; --list; --bots N (scale
the synthetic stress traffic via BOT_DEFENDER_BOTS); --gnn auto|require|skip (skip if torch absent
/ fail if absent / never run); -k forwards a keyword; everything after `--` is raw pytest passthrough
(it splits on the first `--` itself because argparse REMAINDER + nargs=* mis-routes flags). It sets
PROJECT_ROOT and runs pytest.main with the collector plugin. `make test-suite` runs it.

--------------------------------------------------------------------------------
 8.2  testsuite/tests/conftest.py  — fixtures + the test doubles
--------------------------------------------------------------------------------
REPO_ROOT = two levels up (NOT symlink-resolved — the WSL/Docker bind-mount hash path can
rotate, so every layer must agree on the path the suite was invoked through). Puts the repo root
on sys.path and sets PROJECT_ROOT. Fixtures:
  repo_root; website_on_path (puts website/ on sys.path so its top-level modules import like
    server.py does: `from user_agent_info import parse_user_agent`); isolated_app_config (the key
    one — monkeypatches EVERY app.config path onto a throwaway tmp tree with a minimal all.yml, so
    the sites + generator services read/write config, render templates, and append history without
    ever touching the real project).
  Test doubles: DummyCursor/DummyConn (a psycopg2-shaped connection that RECORDS every execute(sql,
    params) for assertions — used to test the proxy collectors without a real DB), FakeURL/FakeRequest
    (a minimal Starlette-Request stand-in for the collector handlers). load_module_from_path imports a
    standalone .py (e.g. proxy/collector/app.py) by absolute path.

--------------------------------------------------------------------------------
 8.3  testsuite/tests/synthetic.py  — the labeled synthetic traffic generator
--------------------------------------------------------------------------------
bot_population(scale, seed, site) returns (visits, handshakes, browser_fps, tcp_fps, labels) in
the EXACT row shapes the real ingest layer consumes (all_visits / tls_handshakes /
browser_fingerprints / tcp_fingerprints + ground-truth label sets). It builds the populations the
system must tell apart: declared crawlers (OpenAI/Anthropic/Google/Perplexity/Amazon — two big ones
give the GNN >=2 classes), humans (unique fingerprints, self-consistent — must never flag), a
disguised stealth fleet (Windows UA + Linux SYN across many ASNs sharing one JA4, scaled by `scale`
for stress), an agentic cohort (shared JA4, casual volume, self-consistent), a proxy rotator (one
canvas+fp_id across ASNs -> must stitch into one campaign), and a VM/headless cohort (SwiftShader +
synthetic behavior). Every routable population uses PUBLIC source IPs on purpose, because the
consistency engine only trusts the TCP/IP OS layer for public clients — so a Windows-UA-vs-Linux-SYN
contradiction is only asserted for publicly-routed crawlers (which is what real crawlers are). This
is the shared fixture most feature tests build on.

--------------------------------------------------------------------------------
 8.4  testsuite/tests/test_honeypot_canary.py  — the canary mechanism (representative test file)
--------------------------------------------------------------------------------
Because server.py opens a Postgres connection at import (not import-safe), this file re-implements
update_page's documented contract in-memory (HoneypotModel) while calling the REAL generators +
parser. It:
  - _make_faker builds the SAME Faker (en_US + faker_edu + faker_food) server.py uses;
    _varlist_lines reads the REAL website/varLists/scraperN.txt; _gen_set evals each expression with
    `fake` in scope exactly like gen_vars.
  - test_every_scraper_varlist_yields_ten_nonempty_canaries: every flavor's varList evaluates to 10
    non-empty (non-"Null") values.
  - test_canary_sets_are_high_entropy_across_many_visitors: 400 generated sets are >=97% unique and
    no slot collapses to a constant (the keying premise).
  - test_user_agent_parser_identifies_browsers_bots_and_mobile: the REAL parse_user_agent classifies
    Chrome/Windows, Safari/macOS, iOS-mobile, Android-mobile, a GPTBot (non-browser), and a None UA
    (degrades to all-None — the guard server.py relies on).
  - HoneypotModel mirrors update_page: every request logged with parsed identity; a new (UA, ASN)
    gets a fresh DE-DUPLICATED set; a returning visitor reuses its set + bumps view_count; nogen serves
    all-"Null" and stores nothing. The tests assert stability-per-visitor, uniqueness-across-visitors
    (incl. a new ASN for a seen UA = a new visitor), and the nogen contract.
  The other 11 test files follow the same philosophy (drive the REAL modules, stub only the external
  seams): test_fingerprinting (the consistency engine + browser/TCP layers), test_clustering +
  test_clustering_gnn (the campaign pipeline + the real GraphSAGE on synthetic traffic), test_querying_
  detection (scrape->probe->extract->match with mock providers), test_provenance (timeline/membership/
  RAG), test_proxy_logging (the collectors via DummyConn), test_analytics_service (the SQL builders +
  graceful degradation), test_sites_service (config read/write/merge + the deploy shim), test_template_
  generator (the install logic), test_web_app (the FastAPI routes/exports/redirects), test_static_
  contracts (cross-component wiring — e.g. fp.js field names match the fp-collector schema, the nginx/
  Ansible templates reference consistent names).

--------------------------------------------------------------------------------
 8.5  testsuite/app_tests/*  — a second, app-focused tier
--------------------------------------------------------------------------------
A parallel directory (run via run_app_tests.py) with its own conftest/seed/simulate and per-feature
tests (test_app_honeypot/logging/fingerprinting/clustering/graph/querying/provenance/webapp). Same

--------------------------------------------------------------------------------
 9.1  Makefile  — every workflow has a target

================================================================================
 PART 10 — DEEP DIVE: ONE BOT REQUEST, TRACED THROUGH EVERY LINE IT TOUCHES
================================================================================

Scenario: a crawler at public IP 203.0.113.45 makes ONE HTTPS GET to
https://site-001.dukecodeplus.example/ . It is a real browser-engine UA (so it will
run JS), arriving from source TCP port 51514. Follow it.

STEP 1 — TCP SYN (Layer 2, passive)
  The SYN packet hits the host on :443. The Zeek sidecar shares nginx's network
  namespace, so it sees the packet on nginx's interface. tcp-fingerprint.zeek's
  connection_SYN_packet fires:
    - pkt$is_orig is true (client SYN) -> not skipped.
    - c$id$resp_p == 443/tcp -> not skipped (it's a served port).
    - It writes a tcp_syn.log JSON line: orig_h=203.0.113.45, orig_p=51514,
      resp_p=443, ttl=<observed>, win_size, win_scale, mss, sack_ok, df.
  Asynchronously, the tls-shipper's tcp-shipper thread tails tcp_syn.log, calls
  infer_os(ttl, win, wscale, mss) -> e.g. "Windows" (if ttl normalizes to 128) and
  build_ja4t(...) -> "win_mss_wscale_flags", and INSERTs into logdb.tcp_fingerprints
  keyed by (src_ip=203.0.113.45, src_port=51514, ts).

STEP 2 — TLS ClientHello (Layer 2, passive)
  The bot sends a ClientHello with SNI = site-001.dukecodeplus.example. Zeek's SSL
  analyzer (+ the JA3/JA4 package) sees the RAW ClientHello BEFORE nginx terminates
  TLS, and writes an ssl.log line with id.orig_h/p, server_name, ja3, ja4. nginx
  selects the wildcard cert by SNI (the cert covers *.dukecodeplus.example) and
  completes the handshake. The tls-shipper's tls thread INSERTs into
  logdb.tls_handshakes keyed by (203.0.113.45, 51514, ts).

STEP 3 — nginx routing (proxy/nginx.conf + conf.d/site-001.conf)
  The decrypted request carries Host: site-001.dukecodeplus.example. nginx matches it
  against the server_name in conf.d/site-001.conf (NOT the catch-all _). The request
  enters that per-site block. set $site_name site-001.dukecodeplus.example;.
  The path is "/" -> location / (the __fpbeacon exact-match doesn't apply).

STEP 4a — the mirror (proxy/snippets/mirror.conf -> collector -> logdb.all_visits)
  location / runs `mirror /_mirror; mirror_request_body off;`. nginx issues an
  internal subrequest to /_mirror, which proxy_passes to collector:8000 with headers:
    X-Site = $site_name = site-001.dukecodeplus.example  (the CANONICAL name)
    X-Real-IP = $remote_addr = 203.0.113.45
    X-Client-Port = $remote_port = 51514
    X-Forwarded-For = $remote_addr = 203.0.113.45  (OVERWRITE)
  The collector's collect() reads those headers + the UA + the URI + ALL headers, and
  INSERTs into all_visits (site, client_ip, client_port=51514, user_agent, method=GET,
  uri='/', headers jsonb). It returns 204. If anything fails, it's swallowed (204
  anyway) — the mirror can never stall the real response. (The mirror has 200ms/500ms
  timeouts + proxy_next_upstream off, so even a hung collector doesn't matter.)

STEP 4b — the proxy_pass (-> the Flask honeypot)
  In parallel, location / does `set $upstream site-001-web; proxy_pass
  http://$upstream:8080$request_uri;` with Host/X-Real-IP/X-Forwarded-For($remote_addr)/
  X-Forwarded-Proto($scheme). $upstream is resolved at REQUEST time via the
  resolver 127.0.0.11, so a reload never failed even if the site container had been
  momentarily down. The request reaches the site-001 stack's web container on :8080.

STEP 5 — Flask server.py:update_page
  index() sees genmode=True (the container wasn't started with nogen). It opens a
  Session and calls update_page(session, True).
    - user_agent = the bot's UA. client_ip = get_client_ip() = the FIRST X-Forwarded-For
      entry = 203.0.113.45 (trustworthy ONLY because nginx overwrote XFF).
    - hashed_ip = sha256("203.0.113.45"). ip_netaddr = "203.0.113" (the /24).
    - IPWhois("203.0.113.45").lookup_rdap() -> asn = e.g. "64500".
    - parse_user_agent(ua) -> browser_family/os_family/etc.
    - A new_visits row is ALWAYS inserted + committed (the raw visit log; provenance
      later reads its min(timestamp) for this (UA, ASN) as the mint time).
    - session.query(UserAgent).filter_by(user_agent=ua, asn="64500").first():
        If this (UA, ASN) is NEW: set_vars(session) reads varLists/scraper1.txt's 10
          expressions, gen_vars evals them with `fake` -> a candidate 10-tuple, checks
          new_agents_vars for an exact-tuple collision, regenerates until UNIQUE, then a
          new UserAgent row is stored with var1..var10, view_count=1.
        If SEEN BEFORE: the stored var1..var10 are reused, view_count += 1, last_visited
          refreshed. (Stability per visitor.)
    - render_template("scraper1.html", var1=..., ..., var10=...). The 10 canary values
      are substituted into the Jinja slots in the biography prose.
  The HTML response flows back through nginx to the bot.

STEP 6 — Layer-1 fingerprint beacon (only if the bot runs JS)
  The returned HTML contains <script src="/js/fp.js" defer>. nginx served fp.js from
  the site's static dir (static_url_path='' makes /js/fp.js resolve). If the visitor is
  a real browser / agentic browser, fp.js runs: after a 1200ms settle it computes the
  canvas/webgl/audio/font hashes, the automation tells, navigator/screen, the composite
  fp_id, and POSTs the JSON to /__fpbeacon. nginx matches `location = /__fpbeacon`
  (exact) and proxy_passes to fp-collector:8000 with X-Site/X-Real-IP(203.0.113.45)/
  X-Client-Port. fp-collector's collect() json.loads the body (<=64KB), maps the fields,
  and INSERTs into logdb.browser_fingerprints with client_ip=203.0.113.45 and the SAME
  User-Agent header the page GET carried. (THIS is why the analytics join can match the
  request to its own fingerprint on (client_ip, user_agent).)
  If the visitor is a NON-JS scraper, fp.js never runs, no beacon is sent, and
  browser_fingerprints has no row for this IP — and the analytics layer reads that
  ABSENCE as a bot signal ("browser UA fetched the page but never ran JS").

STEP 7 — what the analytics page now shows for this request
  When you open /logs, request_log.fetch_requests runs the enriched SQL (PART 11). For
  this request it LEFT JOIN LATERALs the browser_fingerprints row with the same IP AND
  the same UA (from STEP 6), nearest in time, and the latest tcp_fingerprints OS for the
  IP (from STEP 1). fingerprint_service.verdict_for builds an endpoint-shaped record and
  runs consistency.score_endpoint: it compares the UA-claimed OS, the JS navigator.platform,
  and the TCP-OS (trusted because 203.0.113.45 is PUBLIC). If they agree -> "consistent".
  If, say, the UA claims Windows but the SYN says Linux -> a +3 contradiction and an
  "INCONSISTENT" pill. When you click "Analyze traffic", run_intel aggregates this IP into
  an endpoint, joins all four layers, and the campaign analysis decides whether this IP is
  part of a disguised/agentic/VM campaign.

That is the complete journey: ONE request produced (potentially) FOUR fingerprint records
(SYN, TLS, mirror/all_visits, JS beacon) plus a per-site visit row and a canary assignment,
all joinable by IP and 4-tuple.


================================================================================
 PART 11 — DEEP DIVE: THE ANALYTICS SQL, CLAUSE BY CLAUSE
================================================================================

The /logs request table is produced by request_log._enriched_sql. Here is the query it
generates (with_tcp=True), annotated. Remember: it is executed by shelling
`docker compose -f docker-compose.proxy.yml exec -T logdb psql -X -q -t -A
-v ON_ERROR_STOP=1 -U logger -d site_logs -c "<sql>"` and the WHOLE result is ONE JSON
value (json_build_object), which Python json.loads. The -t -A flags make psql emit just
the unaligned tuple (the JSON), no header/footer.

  WITH filtered AS (
    SELECT a.id, a.ts, a.site, a.client_ip, a.user_agent, a.method, a.uri, a.headers,
           b.fp_id, b.canvas_hash, b.webgl_hash, b.webgl_vendor, b.webgl_renderer,
           b.audio_hash, b.font_hash, b.navigator, b.automation, b.behavior,
           b.phase, b.user_agent AS fp_user_agent, t.tcp_os, t.ja4t
    FROM all_visits a
    LEFT JOIN LATERAL (
        SELECT bf0.raw ->> 'pv_id' AS pv_id
        FROM browser_fingerprints bf0
        WHERE bf0.client_ip = a.client_ip AND bf0.user_agent = a.user_agent
          AND bf0.raw ->> 'pv_id' IS NOT NULL
          AND bf0.ts BETWEEN a.ts - INTERVAL '30 minutes' AND a.ts + INTERVAL '30 minutes'
        ORDER BY (bf0.ts >= a.ts) DESC,
                 abs(extract(epoch FROM (bf0.ts - a.ts))) ASC
        LIMIT 1
    ) pv ON TRUE
    LEFT JOIN LATERAL (
        SELECT user_agent, fp_id, canvas_hash, webgl_hash, webgl_vendor, webgl_renderer,
               audio_hash, font_hash, navigator, automation, behavior, phase
        FROM browser_fingerprints bf
        WHERE bf.client_ip = a.client_ip AND bf.user_agent = a.user_agent
          AND bf.ts BETWEEN a.ts - INTERVAL '30 minutes' AND a.ts + INTERVAL '30 minutes'
        ORDER BY COALESCE(bf.raw ->> 'pv_id' = pv.pv_id, FALSE) DESC,
                 (bf.phase = 'unload') DESC,
                 CASE WHEN bf.raw ->> 'pv_id' = pv.pv_id THEN bf.ts END DESC,
                 abs(extract(epoch FROM (bf.ts - a.ts))) ASC, bf.ts DESC
        LIMIT 1
    ) b ON TRUE
    LEFT JOIN LATERAL (
        SELECT os_guess AS tcp_os, ja4t FROM tcp_fingerprints tf
        WHERE tf.src_ip = a.client_ip ORDER BY tf.ts DESC LIMIT 1
    ) t ON TRUE
    WHERE <where_clause>
  ),
  page_rows AS (
    SELECT * FROM filtered ORDER BY ts DESC, id DESC LIMIT <page_size> OFFSET <offset>
  )
  SELECT json_build_object(
    'total',        (SELECT COUNT(*) FROM filtered),
    'last_24h',     (SELECT COUNT(*) FROM filtered WHERE ts >= NOW() - INTERVAL '24 hours'),
    'unique_sites', (SELECT COUNT(DISTINCT site) FROM filtered),
    'latest_ts',    (SELECT MAX(ts) FROM filtered),
    'rows',         (SELECT COALESCE(json_agg(row_to_json(page_rows)
                       ORDER BY ts DESC, id DESC), '[]'::json) FROM page_rows)
  );

CLAUSE BY CLAUSE:
  WITH filtered AS (...)  — a CTE: every all_visits row (aliased `a`) that matches the
    filters, enriched with its fingerprints. all_visits is aliased `a` and
    browser_fingerprints `b` so the columns never collide.
  LEFT JOIN LATERAL (... bf0.raw ->> 'pv_id' ...) pv ON TRUE  — PAGEVIEW IDENTIFICATION.
    fp.js stamps every beacon of one page load with a shared random pv_id (it rides in
    the collector's `raw` jsonb — no dedicated column, so pre-pv_id rows just yield
    NULL). This lateral finds the pv_id of the request's OWN pageview: the nearest
    pv-carrying beacon AT/AFTER the request first ((bf0.ts >= a.ts) DESC) because a
    pageview's beacons always FOLLOW its page GET — plain nearest-in-time could grab
    the PREVIOUS page's unload beacon, which fires the instant that page is left,
    milliseconds before the new GET.
  LEFT JOIN LATERAL (... browser_fingerprints ...) b ON TRUE  — THE crucial join. LATERAL
    means the subquery can reference the OUTER row `a`. For EACH request it finds the one
    fingerprint with:
       WHERE bf.client_ip = a.client_ip AND bf.user_agent = a.user_agent
         -> SAME IP and SAME exact User-Agent. The UA equality is what ties a request to
            its OWN device. fp.js sends the same User-Agent header as the page GET, so
            (client_ip, user_agent) is the correct device key. Without the UA match,
            keying on client_ip alone glued one device's fingerprint onto EVERY request
            sharing that IP — and behind a NAT / the local Docker hop, many distinct
            visitors collapse onto one address, so curl and declared bots that never ran
            JS inherited the operator browser's verdict and lit up as spurious
            VM/AUTO/INCONSISTENT. With the UA match they correctly show "No JS".
         AND bf.ts BETWEEN a.ts +/- 30 min (FP_JOIN_WINDOW_MIN)
         -> a TIME BOUND, so a request can't inherit an unrelated session's device from
            hours/days away behind the shared hop.
       ORDER BY COALESCE(bf.raw ->> 'pv_id' = pv.pv_id, FALSE) DESC,
                (bf.phase = 'unload') DESC,
                CASE WHEN bf.raw ->> 'pv_id' = pv.pv_id THEN bf.ts END DESC,
                abs(extract(epoch FROM (bf.ts - a.ts))) ASC, bf.ts DESC
         -> the request's OWN pageview's beacons first; among them PREFER `unload`
            (the `load` beacon fired ~1.2s in has zero behavior — nearest-time alone
            always picked it, which is why biometrics once read as 0 clicks); among
            the pageview's unload beacons take the LATEST — fp.js re-arms the unload
            beacon with cumulative totals (tab away -> back -> more interaction ->
            updated beacon), so the newest is the fullest interaction record. This is
            what keeps a request's biometrics CURRENT instead of frozen at the first
            tab-away. Rows without pv context fall back to the legacy
            unload-then-nearest ordering (COALESCE makes the NULL comparison sort
            with FALSE, not above TRUE).
       LIMIT 1 -> exactly one fingerprint (or none -> the LEFT JOIN keeps the request with
            NULL fingerprint columns -> fp_present=False in Python; the verdict is still
            computed, so a browser UA with no beacon surfaces the browser_no_js signal).
    LEFT (not INNER) is essential: a non-JS request has no fingerprint but must still appear.
  LEFT JOIN LATERAL (... tcp_fingerprints ...) t ON TRUE  — the per-IP latest SYN OS guess.
    Keyed by IP ALONE (a SYN has no User-Agent, and the value is only trusted for public IPs
    by the consistency engine anyway).
  WHERE <where_clause>  — built by _conditions: optional `a.site = '...'`, `a.method = '...'`,
    and the search POSITION(...) check (case-insensitive substring over the request columns
    AND, because include_fp=True here, b.fp_id/b.canvas_hash/b.webgl_renderer — so you can
    search by a device fingerprint and surface the requests it made). All user strings pass
    through _sql_literal (single quotes doubled) — the only user input that reaches the SQL.
  page_rows AS (...)  — orders newest-first (ts DESC, id DESC as a stable tiebreak) and
    applies LIMIT page_size OFFSET (page-1)*page_size. Pagination is done IN SQL, not in Python.
  The final json_build_object computes, OVER THE FILTERED SET (not just the page):
    total (the count used for page_count = ceil(total/page_size)),
    last_24h (NOW() - INTERVAL '24 hours'),
    unique_sites, latest_ts, and rows = json_agg(row_to_json(page_rows)) (COALESCE to '[]'
    so an empty page is a valid empty array, not NULL).
  The entire result is that single JSON object -> json.loads in Python.

GRACEFUL DEGRADATION (fetch_requests):
  - It first runs with_tcp=True. If psql errors with 'relation "tcp_fingerprints" does not
    exist', it retries the SAME query with with_tcp=False (the tcp columns become NULL).
  - If it errors with 'relation "browser_fingerprints" does not exist', it falls back to
    _plain_sql entirely (no fingerprint enrichment at all).
  - So the page works on a brand-new stack where the fp-collector/Zeek-shipper haven't created
    their tables yet, and progressively lights up as those tables appear.

THE CSV EXPORT uses _plain_sql (enrich=False) — just _BASE_COLS, no joins — because the export
is the raw request log, and json-encoding the headers column.

OTHER QUERIES IN THE FILE:
  fetch_filter_options: one json_build_object with two scalar subqueries selecting DISTINCT
    non-empty site / method values (the dropdowns).
  total_request_count: SELECT json_build_object('n', COUNT(*)) FROM all_visits (None on error).
  fingerprint_service._select_sql is the analogous query for browser_fingerprints, adding
    unique_devices = COUNT(DISTINCT fp_id) and the per-IP tcp join.


================================================================================
 PART 12 — DEEP DIVE: THE FOUR FINGERPRINT LAYERS FUSED INTO ONE GRAPH
================================================================================

This is the conceptual core of crawler_graph. The platform observes a visitor at four
independent layers, each captured differently, then FUSES them.

THE FOUR LAYERS (where each is captured, what it reveals, how it's keyed):
  Layer 1 — Browser JS (fp.js -> /__fpbeacon -> browser_fingerprints).
    Captured: only if the visitor RUNS JS. Reveals: canvas/WebGL/audio/font hashes (the
    GPU+driver+OS rasterization + audio stack), the composite fp_id, navigator.platform,
    automation tells, behavioral biometrics. Keyed to requests by (client_ip, user_agent)
    nearest-in-time (the beacon arrives on a separate connection, so NOT 4-tuple-joined).
    The device hashes are the STRONGEST cross-session keys (fp_id weight 7, canvas/webgl 6):
    a shared canvas hash means the SAME physical machine across IP changes, cleared cookies,
    and proxy rotation.
  Layer 2a — TLS ClientHello (Zeek ssl.log -> tls_handshakes).
    Captured: passively, BEFORE TLS termination (Zeek in nginx's netns). Reveals: JA3/JA4 —
    the TLS client stack (library + version + cipher ordering). Keyed to requests by the
    (client_ip, client_port) 4-tuple (one ClientHello -> the many requests its connection
    carried). Weight 5.
  Layer 2b — TCP/IP SYN (Zeek tcp_syn.log -> tcp_fingerprints).
    Captured: passively, the client SYN. Reveals: an OS guess from TTL/window/scale (p0f-style)
    + a JA4T signature. SURVIVES proxies/VPNs (they only rewrite source IP, not the kernel-set
    TCP options) — "the kernel betrays the spoofed OS". Keyed by 4-tuple (with an IP fallback).
    Trusted ONLY for public client IPs (behind the local Docker NAT the SYN is the proxy's).
  Layer 2c — HTTP headers (JA4H, computed in enrich.compute_ja4h from the stored all_visits.headers).
    Captured: from data already in all_visits (no new capture). Reveals: the header set/count/
    accept-language/cookie+referer presence — python-requests/Go/curl send a tiny distinctive
    set vs a real browser. Weight 3.

THE FUSION (enrich -> graph -> communities -> campaigns):
  1. join_fingerprints / join_tcp_fingerprints attach Layer-2 fingerprints to each visit by
     4-tuple ("latest at or before" the request ts, handling port reuse + HTTP/2 multiplexing).
  2. aggregate_endpoints collapses visits to ONE record per client IP (the actor). It carries
     the SETS of every fingerprint value seen from that IP (ja3/ja4/ja4h/tcp_os/ja4t) + request/
     timing/diversity features.
  3. attach_browser_fingerprints folds Layer-1 onto endpoints by IP (canvas/webgl/audio/font/
     fpid sets, renderer, platform, automation, behavior).
  4. consistency.annotate runs the cross-layer engine: for each endpoint it cross-checks the
     CLAIMED identity (UA OS, JS platform) against the SPOOF-RESISTANT lower layers (TCP-OS,
     WebGL renderer, automation tells) and scores the contradictions.
  5. build_graph creates the bipartite IP+attr graph: each IP connects to an attr hub for each
     fingerprint value it shares with >=2 other IPs, weighted by EDGE_WEIGHTS (device hashes
     strongest, ASN weakest). project_to_ip_graph collapses it to a weighted IP-IP graph.
  6. detect_communities partitions the graph (Louvain/Leiden/greedy). Each community = a campaign.
  7. build_campaigns decides, per campaign, whether it's disguised/agentic/VM/contradicting,
     using the fused signals.

WHY FUSION BEATS ANY SINGLE LAYER — three worked examples (the selftest proves all three):
  - The PROXY ROTATOR: one machine on 4 IPs across 4 ASNs, each IP low-volume, distinct ASNs,
    no shared UA hub. Nothing at the IP/ASN/UA level ties them together. But all 4 share ONE
    canvas hash + fp_id (Layer 1). The shared device hub (weight 6-7) pulls them into a SINGLE
    campaign, and shared_device + multi_asn raises disguise_suspected. NO other layer catches this.
  - The STEALTH FLEET: browser UA + Win32 platform (so Layer-1 looks like Windows), across many
    ASNs, sharing one JA4 (Layer 2a) at crawl volume. The shared JA4 hub clusters them; shared_fp
    + multi_asn + no-declared-UA + systematic raises disguise. AND the SYN says Linux (Layer 2b),
    which CONTRADICTS the Windows UA/platform -> a +3 cross-layer contradiction. Two independent
    layers both indict it.
  - The AGENTIC BROWSER: shared JA4, many ASNs, but CASUAL volume and FULLY self-consistent
    (Apple UA + MacIntel platform + Apple SYN, unique device fp per IP). shared_fp clusters it,
    but it's NOT systematic, has no contradictions, and no shared device hash -> agentic_suspected,
    NOT disguise. The volume + consistency signals correctly DOWNGRADE it from "threat" to "expected".

THE KEY INSIGHT: a single fingerprint is evidence of identity; CONTRADICTIONS BETWEEN fingerprints
are evidence of DISGUISE. A genuine device is self-consistent across all four layers; a bot wearing
a costume betrays itself where two layers it didn't think to align disagree.


================================================================================
 PART 13 — CROSS-CUTTING INVARIANTS YOU MUST NEVER BREAK
================================================================================

These are the load-bearing decisions. Breaking any one silently corrupts detection or
security. Memorize them.

 1. SCRAPER_VERSION is read from the env var, NEVER a hardcoded literal. The Ansible
    configure role rewrites server.py to enforce this, so a hardcoded value is silently
    reverted. It selects varList + template + DB name in lockstep.

 2. nginx OVERWRITES X-Forwarded-For with $remote_addr (never $proxy_add_x_forwarded_for).
    server.py:get_client_ip trusts the FIRST XFF entry for ASN lookup + canary keying. If
    nginx appended, a bot could prepend a fake IP the honeypot would believe.

 3. The default catch-all server (server_name _; return 444) must stay default_server on
    BOTH :80 and :443, and must NEITHER proxy NOR mirror. It keeps scan noise out of the
    honeypots (no canaries assigned to scanners) and out of all_visits, and guarantees
    all_visits.site is always a real configured site. Never mark a per-site block default_server.

 4. The mirror's X-Site = $site_name (the CANONICAL hostname) is what makes all_visits.site
    trustworthy even for requests arriving via the *.localhost alias.

 5. Canary sets are GLOBALLY UNIQUE (set_vars retries until no exact-tuple collision) and
    STABLE per visitor — keyed by the device cookie (__abd_fp / fp_id) when the visitor
    ran fp.js, else by (user_agent, asn). The device key is what keeps ONE physical
    machine on ONE canary set even as it rotates UA/IP/ASN (a browser VPN switch), which
    is what makes "one canary set under several identities" a DISGUISE signal and what
    makes a leaked set attribute to one device instead of N fragments. Uniqueness is
    best-effort application logic: there is no database UNIQUE constraint, concurrent
    check/insert can race, and the max-attempt fallback is unchecked. Non-JS clients
    (which never set the cookie) keep the pure (user_agent, asn) keying, unchanged.

 6. The analytics fingerprint join is on (client_ip, user_agent) within a +/-30-min window,
    pageview-aware (pv_id from the collector's raw jsonb) and preferring the pageview's
    LATEST cumulative `unload` beacon — NOT client_ip alone, NOT the 4-tuple, NOT unbounded
    nearest-time. IP-only keying bleeds one device's verdict onto every IP-sharing request
    behind NAT/the Docker hop; the window stops inheriting an unrelated session's device;
    preferring `unload` surfaces the real behavioral biometrics (the `load` beacon is
    empty); the pageview match stops a request grabbing the PREVIOUS page's unload beacon
    (nearest-in-time at navigation) and keeps the row current as fp.js's re-armed unload
    beacons report continued interaction after tab-away-and-return.

 7. The TCP/IP OS layer is DISTRUSTED for private/loopback client IPs (TRUST_TCP_FROM_PRIVATE=0).
    Behind the local Docker userland proxy the SYN is the proxy host's kernel, so every visitor
    reads as "Linux" — trusting it would flag your own browser as an OS spoof. Real crawlers
    arrive from public IPs where the SYN genuinely is the client's.

 8. The four fingerprint layers fuse into ONE weighted identity graph, with device fingerprints
    (fp_id 7, canvas/webgl 6) outweighing TLS (5) outweighing UA/net (3) outweighing ASN (1).
    This ordering is the intelligence model — a fleet rotating IPs/ASNs but reusing one machine
    or one TLS stack still clusters.

 9. The GraphSAGE GNN needs >=2 declared-provider classes to train. A single-class model is
    degenerate (predicts that provider for everyone at ~1.0 confidence) and would spray bogus
    disguise flags — it is deliberately skipped with a reason.

10. Detection (querying/) and intelligence (crawler_graph/) are INDEPENDENT subsystems. One
    answers "did a model ingest my page?" (Jaccard of LLM answers vs canaries); the other answers
    "who is crawling me and are they hiding?" (campaign clustering). Don't conflate them.

11. Everything degrades gracefully. Every logdb read tolerates a missing column/table; every
    renderer/optional-dep/model-provider path is wrapped so a missing piece never crashes the whole.
    The mock providers + the synthetic selftest make the entire system demonstrable with no Docker,
    no DB, and no API keys.

12. Distinguish authored configuration from rendered/runtime artifacts. Do not hand-edit
    website/varLists/*.txt, website/sites/*/docker-compose.yml, proxy/conf.d/*.conf,
    proxy/certs/*, configs/history/*, querying/runs/*, querying/provenance/*.json, or
    crawler_graph/output/*; regenerate them from their source. configs/sites/*.yaml are
    per-site SOURCE overrides (normally written by the UI, but legitimate to review/edit
    deliberately). To change the global canary expressions, edit canary_tokens in all.yml
    and re-run the playbook.

13. Per-site website.port and database.host_port must be UNIQUE. The playbook validates this
    against every other site config and aborts on a collision — the #1 deploy failure.

14. DB credentials are baked at Postgres volume-init time. Changing db_user/db_password on an
    existing site requires recreating the volume (reset_db / the UI checkbox), which WIPES that
    site's stored visits and canaries.

15. Keep the template-generator boundary precise. Its standalone scripts write their
    dataset/model/generated output under template_generator/ (or an explicit --out), but
    app/services/template_gen.py is the authorized integration point that copies generated
    HTML into website/templates/ and appends generation history under configs/history/.
    It never overwrites an existing scraperN.html; it selects the lowest free version.

 PART 14 — SENIOR-ENGINEER MODEL: OWNERSHIP, STATE, TRUST, AND FAILURE
================================================================================

The earlier parts explain the happy-path behavior. This part gives the model a senior
engineer should use in design review: who owns each piece of state, which boundaries are
trusted, what is atomic, and which failures are intentionally hidden from the visitor.

14.1  STATE OWNERSHIP — THERE ARE SIX DIFFERENT KINDS OF PERSISTENCE
-------------------------------------------------------------------
  1. Per-site Postgres volume (site-<id>_pgdata): new_visits and new_agents_vars.
     This is the authoritative record of visits to that particular honeypot and the
     visitor-to-canary assignment. reset_db destroys this evidence.

  2. Central proxy Postgres volume (proxy_logdata): all_visits,
     browser_fingerprints, tls_handshakes, tcp_fingerprints. This is cross-site
     telemetry, not the source of assigned var1..var10 values.

  3. Authored deployment configuration: ansible/group_vars/all.yml and
     configs/sites/*.yaml. Global defaults are shallow-merged with nested website,
     database, and proxy overrides. These files describe desired state.

  4. Rendered deployment state: website/sites/<id>/docker-compose.yml,
     proxy/conf.d/<id>.conf, website/varLists/scraperN.txt, and the generated cert.
     These are reproducible from authored configuration/templates and can drift if
     someone hand-edits them.

  5. File-based analysis results: querying/runs/*.json, querying/provenance/*.json,
     crawler_graph/output/*, configs/history/*.jsonl. They support the UI and audit
     history but are not transactionally tied to either database.

  6. Process-local transient state: app.main's _LAST_DEPLOY, _LAST_INTEL,
     _LAST_PROV, and _LAST_GEN dictionaries; parser._NLP; collector DB connections;
     crawler_graph's in-memory ASN cache. A process restart loses this state. Multiple
     uvicorn workers would each own a different copy.

When debugging stale UI data, first identify which of these six stores the page reads.
For example, campaign cards come from persisted campaigns.json, not a live query on every
GET /logs. The request table is live SQL. The deploy banner is only process memory.

14.2  TRUST BOUNDARIES
----------------------
  Internet visitor -> nginx:
    Completely untrusted. nginx chooses the site from its own server block and replaces
    X-Forwarded-For. A visitor-supplied X-Site/X-Real-IP/XFF must never become identity.

  nginx -> collectors / Flask:
    Trusted only because the collectors are not host-published and Flask's debug port is
    loopback-bound. If these services were exposed directly, callers could forge X-Site,
    X-Real-IP, X-Client-Port, and XFF and poison attribution.

  operator -> FastAPI web app:
    This is treated as a trusted local administrative boundary. There is currently no
    authentication, authorization, session isolation, or CSRF protection. The app can
    mount the Docker socket, run Ansible, query databases, and write configuration, so
    exposing :8000 beyond a trusted machine would expose host-level administrative power.

  all.yml canary expressions -> eval():
    Fully trusted code, not mere data. gen_vars evaluates Python expressions with module
    globals available. An attacker who can edit canary_tokens already has a code-execution
    path when the honeypot handles a new visitor.

  model/provider responses -> extractor -> matcher:
    Untrusted text. The real extractor is instructed to return JSON and its result is parsed;
    on failure it falls back to the heuristic. The matcher only consumes list-valued fields,
    normalizes them to strings, and compares exact values. It does not execute model output.

  browser fingerprint beacon -> fp-collector:
    Untrusted and self-reported. The collector caps the body at 64 KiB and type-coerces numeric
    fields, but it does not authenticate the payload. A bot can forge JS-layer fields. That is
    why the system values cross-layer agreement and passive TLS/TCP evidence over one beacon.

14.3  ATOMICITY AND PARTIAL-FAILURE SEMANTICS
---------------------------------------------
The request path is deliberately NOT one distributed transaction:

  - nginx mirror logging and proxying happen independently. The collector can fail while the
    visitor still gets the honeypot page. This preserves availability at the cost of missing
    central telemetry.
  - server.py commits new_visits before it looks up or inserts new_agents_vars. If canary
    generation or the later commit fails, the visit may exist without an assignment.
  - browser beaconing is a later asynchronous request. Page delivery can succeed with no
    browser_fingerprints row because JS is disabled, navigation ends early, the collector is
    unavailable, or the browser blocks the request.
  - Zeek shipping is asynchronous and starts tailing at EOF on first startup. Old lines already
    present before a shipper starts are intentionally not backfilled. A just-written all_visits
    row may therefore have no TLS/TCP partner yet—or ever.
  - report JSON/PNG/HTML writes are independent. A recompute may update campaigns.json while a
    renderer fails, leaving an older visualization beside a newer report.

Never infer “request did not happen” from absence in one secondary store. Correlate the per-site
DB, all_visits, nginx access log, fingerprint tables, and container logs according to the failure
you are investigating.

14.4  CONCURRENCY MODEL AND RACES
---------------------------------
  - FastAPI `def` route handlers run in Starlette's worker thread pool. Long synchronous
    subprocesses do not block the event loop itself, but deploy, generation, GNN training, and
    provider calls can occupy worker capacity for a long time.
  - _LAST_* dictionaries are global mutable state with no lock and no user/session key. Two
    operators can overwrite each other's banner/result, and multiple workers will disagree.
  - collector and fp-collector each cache one autocommit psycopg2 connection. They reset it on
    any insertion exception. This is simple and adequate for the small research deployment,
    but it is not a connection pool.
  - tls-shipper correctly creates one Shipper—and therefore one psycopg2 connection—per tailing
    thread. Sharing one psycopg2 connection between those threads would be unsafe.
  - set_vars performs “SELECT to prove tuple absent, then INSERT” without a database UNIQUE
    constraint over var1..var10. Two simultaneous first-time visitors can both observe absence
    and insert the same tuple. Faker's large space makes this unlikely, but “globally unique” is
    an application intention, not a database-enforced invariant.
  - UserAgent lookup is `.first()` on (user_agent, asn), also without a declared composite unique
    constraint. A race can create duplicate identity rows; later requests update whichever row
    `.first()` returns.

14.5  INPUT VALIDATION AND SECURITY DEBT
----------------------------------------
These are current facts to be able to explain, not claims that the research build is production-ready:

  - POST /sites/deploy only checks that site_id and ports are non-empty. site_id is not constrained
    to a safe slug before it is used in a filename and passed to Ansible. A production version must
    reject path separators and enforce a pattern such as `[a-z0-9][a-z0-9-]{0,62}`.
  - Port strings are written first and converted by Ansible later. The playbook validates collisions,
    but the web route does not validate numeric range or reserve privileged ports.
  - GET /sites/template/{version} is safe from arbitrary path traversal because FastAPI parses
    version as an integer and the service constructs `scraper{version}.html`.
  - SQL filters are escaped by doubling apostrophes in _sql_literal, and the SQL receives only
    clamped integer page values. Parameterized queries would still be the better general design;
    the current escaping must be preserved if this shell-to-psql architecture remains.
  - The proxy DB and default site DB credentials are development defaults. The generated TLS
    certificate is self-signed. Neither is an Internet production posture.
  - Hashed IP is unsalted SHA-256. It removes the literal address but is pseudonymization, not
    strong anonymization: the bounded IP space can be guessed and rehashed.
  - RDAP runs synchronously in server.py for every request before the identity lookup. Network
    latency/failure directly affects the page path. crawler_graph improves on this with an on-disk
    cache; the Flask service does not share that cache.

14.6  FLASK/SQLALCHEMY LIFECYCLE DETAILS
----------------------------------------
  - engine, Session, and Base.metadata.create_all execute at module import. A database outage can prevent
    the web process from importing at all. Compose mitigates this by waiting for the DB healthcheck.
  - create_all creates missing tables but is not schema migration. It does not add/change columns on an
    existing table; unlike all_visits, the per-site schema has no explicit ALTER migration path.
  - The password/user are interpolated into a URL string rather than SQLAlchemy URL.create. Reserved URI
    characters in credentials can corrupt parsing unless percent-encoded.
  - The Cloud SQL instance socket string is hardcoded to scraper1-proj/us-central1/template-db even when
    SCRAPER_VERSION changes; only the database name is versioned. That branch needs deployment-specific
    review before nonlocal use.
  - A Session is created per route call and closed only on the normal update_page path, not in finally.
    Exceptions during RDAP-adjacent processing, eval, query, commit, or render can leave cleanup to
    SQLAlchemy/GC. Multiple commits intentionally make the visit durable before assignment, but preclude
    one atomic rollback.
  - is_mobile/is_tablet/is_pc booleans are converted to strings because the ORM columns are String. Values
    are therefore "True", "False", and even "None", not SQL booleans/null after successful parsing.
  - set_vars reads at most ten non-filtered lines. Ansible asserts at least ten configured expressions,
    but a manually short file causes gen_vars's remaining positional defaults to fill missing slots; extra
    lines are ignored. Blank/malformed expressions can fail eval.

 PART 15 — EXACT DATA CONTRACTS AND JOIN SEMANTICS
================================================================================

15.1  THE FOUR CENTRAL LOGDB TABLES
-----------------------------------
all_visits (created/migrated by proxy/collector/app.py)
  id serial PK; ts timestamptz default now(); site text; client_ip text;
  client_port int; user_agent text; method text; uri text; headers jsonb.
  client_port is an additive migration because CREATE TABLE IF NOT EXISTS does not
  retrofit an old table. The collector executes both CREATE_TABLE and MIGRATE.

browser_fingerprints (created by proxy/fp-collector/app.py)
  Identity/time: id, ts, site, client_ip, client_port, user_agent, phase, fp_id.
  Render surfaces: canvas_hash/winding; webgl_hash/vendor/renderer/shader_ms;
  audio_hash/sample; font_hash/fonts; screen; navigator; webgpu.
  Detection: automation, behavior. Preservation: raw stores the full submitted payload.
  Indexes support (client_ip, client_port, ts) correlation and fp_id stitching.

tls_handshakes (created by proxy/tls-shipper/app.py)
  id, ts, uid, source/destination IP+port, TLS version/cipher, server_name/sni,
  ja3/ja3s/ja4/ja4s. tls_row_from writes Zeek server_name into both server_name and
  sni for compatibility.

tcp_fingerprints (also created by tls-shipper)
  id, ts, uid, source/destination IP+port, ttl, win_size, win_scale, mss, sack_ok,
  df, os_guess, ja4t. ja4t here is “JA4T-style”: window_MSS_scale_flags. It omits
  TCP option ordering because the Zeek event used by this project does not expose it.

15.2  WHY THERE ARE MULTIPLE JOIN STRATEGIES
--------------------------------------------
Connection-level forensic join in crawler_graph:
  all_visits.client_ip/client_port matches tls_handshakes.src_ip/src_port or
  tcp_fingerprints.src_ip/src_port. For a request timestamp, select the latest
  candidate at or before it. This maps one handshake/SYN onto multiple requests over
  keep-alive or HTTP/2. Source-port reuse and clock skew remain practical limits.

UI request-to-browser join in request_log:
  Match exact (client_ip, user_agent) within a +/-30-min window; identify the request's
  own pageview first (nearest pv_id-carrying beacon at/after the request — beacons follow
  their page GET) and take that pageview's LATEST `unload` beacon (cumulative counters =
  fullest record); rows without pv context fall back to unload-then-nearest. A beacon is a
  separate HTTP connection and its source port need not equal the original document
  request, so the 4-tuple is too strict here. Exact UA prevents a browser behind one NAT
  from donating its fingerprint to curl/bot traffic; the window bounds cross-session
  bleed; preferring `unload` (over the empty `load` beacon) is what makes the behavioral
  biometrics — clicks/scroll/keystrokes — actually show up on the request, and taking the
  pageview's latest one is what keeps them UPDATING when the visitor tabs away, returns,
  and keeps interacting (fp.js re-arms its unload beacon per interaction burst).

Intelligence browser-to-endpoint join:
  crawler_graph ultimately aggregates by client_ip and attaches browser fingerprints to
  that endpoint. This intentionally supports campaign/device stitching, but a single NAT
  can represent several real devices. The endpoint record preserves sets/counters and the
  consistency engine refuses ambiguous multi-OS TCP evidence to reduce false accusations.

Canary identity join:
  Per-site new_agents_vars uses (full exact User-Agent string, ASN), not IP. A rotating IP
  in one ASN retains canaries. The same UA crossing ASNs receives new canaries. If RDAP
  fails, ASN=None means unrelated clients with the same UA can collapse to one assignment.

15.3  CANARY MATCHING IS EXACT-SET JACCARD
------------------------------------------
matcher.flatten_extractor:
  iterate every extractor value; only list fields count; str/strip/lower; deduplicate to set E.
matcher.flatten_row:
  read only var1..var10; accept nonempty strings except case-insensitive `null`; normalize to set C.
compare_row:
  score = |E intersection C| / |E union C|, or 0 for an empty union.

Consequences a senior engineer should state explicitly:
  - It is case/outer-whitespace insensitive, but not fuzzy, substring, stemming, or semantic matching.
  - Extra entities in an answer enlarge the union and LOWER the score. This favors precise
    regurgitation and can miss a verbose model that leaks several canaries among much unrelated text.
  - Repeated canaries do not add weight because both sides are sets.
  - A threshold of 0.3 is configured, not a statistical proof by itself. Calibration against controls
    and extraction quality matters.
  - The pipeline combines all answers from one model before extraction and reports only the best
    row. It does not expose which individual question caused that best score.

15.4  THE GNN NUMERIC CONTRACT
------------------------------
features.FEATURE_NAMES fixes the 22-column order consumed by GraphSAGE:
  log request/site/path counts; path/UA/hour entropy; UA count; TLS fingerprint presence;
  browser/automation flags; burstiness; log timing/span; browser-fingerprint presence;
  log device-key count; automation score; inconsistency score; VM flag; one-hot presence
  of Windows/Apple/Linux TCP guesses; synthetic-behavior flag.

build_arrays assigns labels only when an endpoint has exactly one declared provider. -1 means
unlabeled. Every undirected NetworkX edge becomes two directed edge_index entries. The current
GraphSAGE forward pass does not consume edge_weight; topology and node features drive learning,
even though the projected graph retains summed weights. This distinction matters: edge weights
influence community detection and graph construction, but not SAGEConv here.

_to_tensors standardizes every feature column with the current graph's mean/std and clamps std
to 1e-6. A persisted model stores those training statistics. Loading it on new arrays assumes the
same feature order and dimensionality; changing FEATURE_NAMES invalidates old checkpoints unless
migration/versioning is added.

================================================================================
 PART 18 — LIMITATIONS, FALSE-POSITIVE CONTROLS, AND SAFE EVOLUTION
================================================================================

18.1  WHAT THE EVIDENCE CAN AND CANNOT PROVE
--------------------------------------------
Canary overlap proves that the tested output contains values assigned by this system, subject to the
uniqueness, extraction, and ground-truth assumptions. It does not by itself prove training ingestion:
the model might browse live, receive the values through a third party, or be deliberately prompted with
them. RAG disambiguation and access-log correlation narrow those alternatives; they do not provide a
cryptographic chain of custody.

UA attribution is a claim. Published IP-range validation strengthens it. TLS/device similarity supports
same-stack/same-device inference but common software images create collisions. GNN output is a learned
hypothesis seeded from declared UAs, not ground truth. Its UI confidence is coarse, and campaign code
currently uses a provider vote without enforcing a minimum per-node GNN confidence.

No-JS is weak evidence: privacy extensions, CSP, network failures, and non-browser clients all explain it.
It has weight 1 and cannot alone cross the default inconsistency threshold 3. Likewise private-address
TCP OS is observed but deliberately untrusted unless explicitly enabled.

18.2  KNOWN DATA-MODEL LIMITATIONS
----------------------------------
  - server.py's netblock derivation is string truncation, not ipaddress network normalization. IPv4 is
    a /24-like prefix without `/24`; IPv6 handling drops only the final textual hextet and differs from
    crawler_graph.netblock's first-four-hextet /64-like form. Do not assume perfect cross-store equality.
  - (UA, ASN) is a coarse visitor key: NAT/shared UAs merge people; ASN changes split one actor; missing
    ASN merges same-UA traffic; UA spoofing controls half of the key.
  - all_visits stores every mirrored method/path but the Flask app only defines GET /. A POST can be
    centrally logged even when Flask returns 405.
  - browser payload authenticity is not verifiable. fp_id is correlation evidence, not a secret ID.
  - exact Jaccard can miss morphological/paraphrased leaks and penalizes verbose extraction.
  - community results depend on the analyzed time window and hub cap. A campaign ID is reassigned after
    sorting every recompute and is not a durable actor identifier.
  - report timestamps and database timestamps are UTC-aware in most new code, while legacy per-site
    Visits.timestamp uses datetime.utcnow (naive). Comparisons must normalize timezone assumptions.

18.3  CHANGE-IMPACT MATRIX
--------------------------
If you change fp.js payload keys:
  update fp-collector columns/INSERT, enrich.attach_browser_fingerprints, UI services/templates, synthetic
  fixtures, and static/fingerprinting tests. Preserve raw payload during migration.

If you change nginx identity headers:
  update site.conf.j2, mirror.conf, collectors, Flask trust logic, tests, and redeploy every site. Rendered
  conf files will not change until Ansible runs and nginx reloads.

If you change central table columns:
  add an idempotent migration; update collector inserts, db ingest SELECT/fallback logic, app SQL, seeders,
  and tests. CREATE TABLE IF NOT EXISTS is not a migration.

If you change canary count:
  this is a wide cross-cutting migration: ORM columns, templates, varLists/Jinja template, Ansible length
  assertion, ground-truth SELECT/CSV, matcher VAR_COLUMNS, generator slot logic, and tests all assume ten.

If you change scraper version behavior:
  preserve the triple lockstep of HTML, varList, and DB name. Existing Postgres volumes were initialized
  with a particular database name; changing version on an existing site may require reset/migration.

If you add a model provider:
  define identifier routing and HTTP/auth/error handling in llm_client, expose configuration/status,
  decide browsing semantics for RAG, add timeline metadata if applicable, and test per-question failure
  isolation. A dropdown entry alone is not provider support.

If you change FEATURE_NAMES or the GNN architecture:
  invalidate/version gnn_model.pt, update feature tests and persistence metadata, and retrain. Saved tensor
  normalization and state_dict dimensions are coupled to the old contract.

If you add an app worker or multi-user deployment:
  replace _LAST_* globals with request/user-keyed durable state, serialize long jobs through a job system,
  add auth/CSRF/permissions, and stop granting an exposed web process unrestricted Docker-socket power.

18.4  A PRACTICAL DEBUG ORDER
------------------------------
Site returns nothing:
  resolve Host -> inspect proxy-nginx route -> verify site container/network alias -> verify Flask/DB health.
Site renders Null:
  inspect rendered compose command and website.genmode -> verify varList and SCRAPER_VERSION.
No all_visits row:
  confirm request matched a site block -> mirror location/Docker DNS -> collector logs -> all_visits table.
No browser fingerprint:
  confirm template loads /js/fp.js -> browser console/network -> exact /__fpbeacon route -> fp-collector logs.
No TLS/TCP fingerprint:
  confirm tls-capture shares nginx netns/capabilities/interface -> Zeek logs -> shipper tail/start time/table.
Wrong request verdict:
  verify exact IP+UA browser join, beacon timestamp, public/private TCP trust, navigator/renderer/automation.
Unexpected campaign:
  inspect endpoint aggregates -> attribute hubs/weights/cap -> community method -> campaign rule reasons.
Detection miss:
  inspect scraped subject -> questions -> raw answers -> extractor lists -> each row's intersection/union.
Provenance ambiguity:
  inspect crawl time availability and timeline cutoffs; distinguish a bounded window from an exact date.

 PART 19 — CONFIGURATION AND ENVIRONMENT-VARIABLE PRECEDENCE
================================================================================

19.1  FOUR DIFFERENT CONFIGURATION MECHANISMS
---------------------------------------------
Do not say “the config file” as if there were one. The project has four mechanisms:

  A. Docker Compose interpolation
     `${PWD}`, `${OPENROUTER_API_KEY:-}`, and similar expressions are expanded by
     the host Docker Compose process before the container starts. Only variables
     explicitly listed under `environment:` enter the app container. A variable
     exported in the host shell is not automatically available in the container.

  B. Python import-time environment reads
     Most config modules evaluate os.environ while importing. Changing an env var
     after `querying.config` or `crawler_graph.config` is imported does not update
     its module constants. Restart/reload the process, or deliberately monkeypatch
     the constant in a test.

  C. Ansible desired-state variables
     group_vars/all.yml supplies defaults. site.yml include_vars loads a site's
     YAML into `site_cfg`; set_fact replaces scraper_version and shallow-combines
     the website/database/proxy nested dicts. Extra vars supply site_id/reset_db.

  D. CLI/form arguments
     A CLI flag or submitted form value is converted into a function argument and
     usually overrides module defaults for that invocation. Examples: --limit,
     --since-hours, --gnn, max_questions, seed, and page_size.

19.2  QUERYING CONFIGURATION PRECEDENCE
---------------------------------------
querying/config.py first derives PROJECT_ROOT, then attempts to read querying/.env
followed by root .env. It fills a key only if the current environment value is empty
or absent. Therefore precedence is:

  nonempty process/container environment
       > querying/.env
       > root .env
       > code default.

The custom loader is deliberate because Compose explicitly inserts empty API-key
variables; ordinary python-dotenv override=False would treat the empty value as set
and ignore the .env secret. Later files only fill still-empty keys, so querying/.env
wins over root .env.

Important querying variables:
  PROJECT_ROOT ................ package parent by default; locates runs/data/configs.
  QUERY_MAX_PROBES ............ default 3; pipeline default question count.
  QUERY_HIGH_RISK_THRESHOLD ... default 0.3; exact Jaccard leak threshold.
  QUERY_TARGET_PROVIDER ....... mock; fallback for bare model identifiers.
  QUERY_EXTRACTOR_PROVIDER .... mock; mock/openai/anthropic extraction.
  OPENROUTER_API_KEY/BASE_URL . target-provider credentials/endpoint.
  ANTHROPIC_API_KEY/MODEL ..... Anthropic target/extractor settings; code default model
                                is the literal `claude-fable-5`, whose provider validity
                                is not checked until a request is made.
  OPENAI_API_KEY/API_BASE ..... extractor and membership Completions backend.
  QUERY_EXTRACTOR_MODEL ....... default gpt-4.1.
  QUERY_MEMBERSHIP_BACKEND .... mock, hf, or openai.
  QUERY_MEMBERSHIP_MODEL ...... default gpt2.
  QUERY_MEMBERSHIP_K .......... default 0.2.
  QUERY_MEMBERSHIP_ALPHA ...... default 0.01.
  QUERY_MODEL_TIMELINE ........ explicit override-file path (and currently the reliable
                                way around the default lookup bug documented in 5.12).

docker-compose.app.yml explicitly passes provider names and API keys but not every
QUERY_* tuning variable. Values not listed can still come from the bind-mounted
querying/.env because querying.config reads that file inside the container.

19.4  PROXY AND HONEYPOT ENVIRONMENT
------------------------------------
Collectors/shipper use DB_HOST/USER/PASS/NAME, supplied by proxy compose. The
fp-collector additionally reads FP_MAX_BODY (bytes, default 65536). tls-shipper reads
SSL_LOG, TCP_LOG, and POLL_SECONDS. proxy compose supplies SSL_LOG but relies on the
default TCP_LOG and poll interval.

The Flask honeypot reads DB_USER, DB_PASS, DB_HOST, SCRAPER_VERSION. Presence of PORT
selects its Cloud SQL Unix-socket DSN branch; the numeric value of PORT is not used to
choose app.run's port, which remains 8080. In per-site Compose PORT is absent, so the
normal Docker hostname branch is selected.

CAPTURE_IFACE controls Zeek's interface. If empty, entrypoint.sh discovers an interface.
BASE_DOMAIN and LOCAL_BASE_DOMAIN reach certgen from proxy compose, not automatically
from all.yml. Keep those duplicated values synchronized.

19.5  APP/GENERATOR ENVIRONMENT
-------------------------------
PROJECT_ROOT is the central path anchor. PROXY_HTTP_ENTRY defaults to loopback on a host
and is set to `http://proxy-nginx` in the app container. TEMPLATE_GEN_PYTHON selects the
executable used for the generation subprocess; if unset it is python3, which is correct
inside the built app image.

HF_HOME=/opt/hf-cache redirects Hugging Face base-model downloads into a named volume.
The adapter is in the bind-mounted repository, while the large base-model cache survives
container replacement in hf-cache. Docker GPU reservation is a deployment prerequisite,
not a Python variable; removing the compose deploy block allows CPU fallback.

19.6  PATH MIRRORING, AND WHY `${PWD}` MATTERS
----------------------------------------------
The app container mounts `${PWD}:${PWD}` and sets working_dir/PROJECT_ROOT to `${PWD}`.
When it asks the host Docker daemon to build `../..` from a rendered compose file, the
host daemon sees the same absolute path the inner process supplied. If Compose is invoked
from the wrong directory, PWD points at the wrong tree and path mirroring breaks. This is
also why moving the repository while containers are running can invalidate inner paths.


================================================================================
 PART 20 — ALGORITHM NOTEBOOK: FROM RAW SIGNAL TO VERDICT
================================================================================

20.1  BROWSER FINGERPRINT CONSTRUCTION
--------------------------------------
fp.js uses cyrb53, a deterministic 53-bit non-cryptographic hash. It is suitable for
compact equality keys, not tamper proofing or collision-resistant security. The 14-hex
rendering is padded, but the effective state is about 53 bits.

Surface-by-surface:
  Canvas draws text, Unicode, shapes, gradients, and compositing, then hashes dataURL.
  WebGL records vendor/renderer, capabilities, extension set, and a shader timing sample;
    its stable hash excludes timing and hashes vendor+renderer+params+extensions.
  WebGPU is best-effort with a 600 ms completion guard.
  Audio renders a fixed oscillator/compressor graph offline and hashes samples.
  Fonts measure a candidate set against generic baselines and hash detected fonts.
  Screen captures dimensions, available area, color depth, DPR, and viewport geometry.
  Navigator captures platform/languages/hardware/timezone, UA client hints when supported.
  Automation collects webdriver/headless/CDP/plugin/language/Chrome/software-renderer and
    hardware anomalies, then scoreAutomation counts true tells.

Composite fp_id hashes canvas, WebGL, audio, font hash, platform, CPU/memory, timezone,
screen dimensions/DPR, and languages. It is a browser/device-configuration signature—not
a permanent physical serial number. Changing display, locale, browser privacy settings,
driver, or hardware can change it; cloned VMs can share it.

20.2  MULTI-PHASE BEACONING (load + re-armable cumulative unloads)
------------------------------------------------------------------
buildStatic waits for four async groups: Audio, WebGPU, UA-CH, and permission anomaly.
After completion, a load beacon is scheduled 1.2 seconds later via fetch keepalive. On
each visibility-hidden or pagehide event, an unload beacon is sent through sendBeacon
containing the accumulated (cumulative) behavior — but only when the interaction total
changed since the last unload beacon (`flushedAt` guard). So: tab away -> beacon; come
back and interact -> next tab-away/close sends an UPDATED beacon; tab in/out idle ->
nothing. All beacons of one page load share the same random `pv_id`. Behavioral timing
distributions exclude idle gaps > IDLE_GAP_MS (2s): a reading pause or a hidden-tab
stretch would otherwise inject one giant inter-event interval and corrupt the
regularity statistics (moveIntervalCv, meanFlight) the synthetic-humanization check
reads.

One page view can therefore create SEVERAL browser_fingerprints rows with the same
fp_id/pv_id but different phase/behavior; behavior counters are cumulative, so the
newest unload row of a pv_id is that pageview's fullest interaction record (which is
exactly what the request-log join now picks). `summary_counts.fingerprints` is
beacon-row count, whereas `unique_devices` is COUNT(DISTINCT fp_id). A fast navigation
before STATIC completes can produce no beacon; “no JS” is therefore a useful weak
signal, not proof JS was disabled.

Behavior math:
  - mouse distance is Euclidean distance summed over moves;
  - angle entropy bins movement direction into 16 bins and computes Shannon entropy;
  - interval/dwell coefficient of variation = standard deviation / mean;
  - synthetic becomes true after >25 moves with move CV < .05, or >6 key dwells with
    dwell CV < .04. These are heuristics, not trained classifiers.

20.3  JA4H-STYLE HEADER SIGNATURE
---------------------------------
compute_ja4h removes proxy-added names, uses the first two lowercase method characters,
encodes header count, cookie/referer presence, a four-character primary language token,
and the first 12 hex characters of SHA-256 over remaining header names.

This is not canonical JA4H. nginx normalizes headers and the collector stores them in
Postgres jsonb, which does not preserve original wire ordering. The resulting iteration
order is a database-decoded order, not trustworthy client order. Treat it as a stable-ish
header-set fingerprint that distinguishes sparse libraries from browsers.

20.4  TEMPORAL JOINS
--------------------
TLS join indexes by (src_ip, string(src_port)), sorts candidates by string timestamp, then
walks until timestamp > request timestamp. If no candidate is at/before the request, it
uses the first candidate anyway. TCP join does the same exact-tuple lookup and then falls
back to most recent candidate for the IP alone.

This gives useful resilience but has edge cases:
  - timestamps are compared lexicographically, which assumes consistent ISO formatting;
  - the first “future” record can attach under clock skew or missing history;
  - IP-only TCP fallback can borrow a sibling connection from another device behind NAT;
  - source ports can be reused over a long analysis window.

Browser fingerprints are attached to intelligence endpoints by IP with no timestamp limit
inside the selected analysis window. All browser rows for that IP contribute sets/max/OR
flags. This is intentional aggregation, but shared/NAT IPs can merge devices.

20.5  ENDPOINT FEATURE MATH
--------------------------
aggregate_endpoints groups by nonempty client_ip. For each IP:
  Counters: exact UAs, URIs, sites, hour-of-day.
  Shannon entropy: H = -sum(p_i * log2(p_i)). Zero for an empty/single-valued counter.
  Interarrival gaps: sorted parsed timestamps; arithmetic mean and population stddev.
  Burstiness: B = (std_gap - mean_gap) / (std_gap + mean_gap).
    B approaches -1 for metronomic gaps, 0 when std≈mean (Poisson-like), +1 when
    variability greatly exceeds the mean. With fewer than two timestamps it is None.
  first_ts/last_ts are min/max of timestamp STRINGS, relying again on consistent format.
  UA provider/browser/automation flags are OR/set aggregations across all visits.

20.6  IDENTITY GRAPH CONSTRUCTION
---------------------------------
Pass 1 adds every IP node and builds attribute membership sets. JA4 is preferred; JA3 is
used only when that endpoint has no JA4. UA/netblock/ASN and each browser/JA4H key become
typed IDs such as `fpid::<value>` so equal text in different namespaces cannot collide.

Pass 2 materializes an attribute hub only when 2 <= member count <= ATTR_HUB_CAP. Each IP
gets a weighted edge to the hub. Singleton IP nodes remain in the graph but unique attributes
do not add hubs. Oversized shared attributes disappear entirely as likely noise.

The bipartite representation avoids constructing all IP pairs during the primary build.
Community detection runs on this FULL weighted bipartite graph. project_to_ip_graph later
expands each hub into every IP pair and sums weights; that projection is O(k²) per hub, which
is why the 400-member cap is also a computational guard. The projected graph is used for GNN
and visualization, not for the original community partition.

20.7  COMMUNITY ALGORITHMS
--------------------------
auto tries Louvain, then Leiden, then greedy modularity, swallowing optional-dependency
failures. Explicit `--method` re-raises that algorithm's failure. Louvain and Leiden use
seed 42; greedy is deterministic for a stable graph ordering.

Modularity compares within-community edge weight to expectation under a degree-preserving
null model. Higher is generally more separated, but it is not accuracy and suffers a
resolution limit. A “campaign” is a graph community hypothesis, not a verified organization.

community_id is the raw detector label. build_campaigns then sorts communities by
(n_requests, n_ips) descending and assigns a new sequential campaign_id. campaign_id can
change after every recompute and must not be used as a durable actor primary key.

20.8  EXACT CAMPAIGN RULE TREE
------------------------------
For a community:
  shared_fp = it has JA4/JA3 values and distinct count <= max(1, round(.25*n_ips)).
  multi_asn = more than one nonempty ASN.
  systematic = total requests / n_ips >= 8 by default.
  shared_device applies the same .25*n_ips cohesion independently to canvas, WebGL hash,
    or fp_id; combining types would incorrectly count one device several times.

Disguise reasons are appended for:
  1. declared crawler UA outside a configured provider range;
  2. shared TLS fingerprint + multiple ASNs + no declared provider +
     (systematic OR at least one automated endpoint);
  3. any non-unknown GNN provider vote + no declared provider + browser/automation;
  4. shared device + multiple ASNs;
  5. at least one inconsistent endpoint.

Agentic requires NO disguise reasons, >=50% browser endpoints, shared TLS fingerprint,
no declared provider, zero automated endpoints, and non-systematic volume. Disguise takes
precedence. Label confidence is high only for clean declared campaigns; disguise/agentic is
medium; pure GNN/unattributed is low.

20.9  GRAPHSAGE TRAINING DETAILS
--------------------------------
The 22 numeric features are standardized over the current graph. Declared-UA endpoints with
exactly one provider become labels; ambiguous/missing providers are -1. Classes with at least
three labeled nodes contribute floor(30%) to validation while retaining at least one train
node. Smaller classes have no validation member. There is no independent test set.

Architecture: SAGEConv(input, hidden=32) -> ReLU -> dropout(.3) -> SAGEConv(hidden,hidden)
-> ReLU -> linear class head. Adam lr=.01, weight decay 5e-4, 200 epochs, cross entropy.
The best validation checkpoint is kept; without validation the final model is used. This is
transductive learning: validation/unlabeled nodes remain in graph message-passing topology even
when their labels are withheld.

Current limitations to state during review:
  - projected edge_weight is constructed but not passed to SAGEConv;
  - no class weighting, early stopping, calibration, or confidence threshold in campaign votes;
  - every endpoint prediction votes equally, and campaign summary chooses plurality provider;
  - train/validation accuracy on a small synthetic/declared set is not external attribution proof.

20.10  MIN-K% AND MIN-K%++
--------------------------
For N valid token log-probabilities and fraction k, Min-K selects
max(1, floor(N*k)) lowest log-probabilities and averages them. “Higher” means less negative:
even the model's least-comfortable tokens were relatively expected, a membership clue.

Min-K++ standardizes each chosen-token log-probability against the full vocabulary distribution
at that position: z=(chosen_lp-mu)/sigma, then averages the lowest k fraction. Only LocalHFScorer
and the mock provide mu/sigma. OpenAI-compatible Completions returns chosen-token logprobs and
therefore falls back to plain Min-K.

AUC is the fraction of all served/control pairs where served > control, with ties worth 0.5.
Mann-Whitney tests the one-sided alternative served > control. `is_member` requires BOTH p<.01
by default and AUC>0.5. The mock deliberately separates distributions; it validates plumbing,
not membership of any real model.

20.11  PROVENANCE WINDOW MATH
-----------------------------
For each serialized canary identity key:
  leaking = models whose score crosses threshold;
  non_leaking = completed models without a crossing;
  latest bound = earliest real (non-Mock) leaking cutoff;
  candidate lower bound = latest non-leaking real cutoff earlier than latest bound;
  stored earliest = max(crawl date, candidate lower bound), when available;
  latency upper bound = earliest leaking cutoff - crawl date.

Cutoff strings with only YYYY-MM become the first day of that month, so month precision is
displayed like day precision. The conceptual interval after a non-leaking cutoff should be open,
but JSON stores only date strings and no inclusive/exclusive marker. The code does not reject a
negative latency if inconsistent metadata places the model cutoff before the crawl.

Canary keys are serialized as `user_agent|asn` and split on the first `|`; an unusual UA containing
that character would corrupt reconstruction. A model refusal expressed as normal answer text with
no extracted canary is counted as non-leaking, so non-leak conflates ignorance, alignment refusal,
and extraction failure unless the raw answer is separately reviewed.


================================================================================
 PART 21 — UI, ROUTE, AND SERVICE CONTRACTS
================================================================================

21.1  ROUTE EXECUTION MODEL
---------------------------
FastAPI `def` handlers are synchronous and run in Starlette's thread pool. The long operations are
performed inside the HTTP request:
  deploy up to 900 seconds; template generation up to 1800 seconds; provider probing and GNN
  recompute also run synchronously. There is no job queue, progress endpoint, cancellation record,
  or idempotency token. Refresh/re-submit can start duplicate work.

303 redirects after POST tell the browser to GET the destination. The compatibility routes use 307,
which preserves method; they are GET-only in normal use, so preservation is harmless. File/report
detail routes return an ordinary rendered 200 with a “not found” message rather than HTTP 404.

21.2  SITE STATUS MEANS FILE STATUS, NOT HEALTH
----------------------------------------------
Site Configurator labels:
  Live ...... canonical hostname appears in a proxy/conf.d/*.conf file.
  Deployed .. rendered website/sites/<id>/docker-compose.yml exists.
  Config only neither condition.

“Live” does not ping nginx, inspect container health, or prove DNS/routing. “Deployed” does not mean
`docker compose ps` is running. These are desired/rendered-state indicators.

Submitting deploy writes configs/sites/<id>.yaml BEFORE Ansible runs. A failed deployment therefore
leaves a configured site. The playbook handler runs nginx -t and reload with failed_when:false; site
deployment can be reported successful even when the proxy is absent or reload validation failed.
This is intentional first-deploy tolerance but weakens the meaning of success.

21.3  TEMPLATE PREVIEW BEHAVIOR
------------------------------
/sites/template/{version} returns raw HTML as text/plain. JavaScript fetches it, assigns iframe.srcdoc,
and also uses textContent for safe source display. The iframe has no sandbox attribute.

Relative `/js/fp.js` in srcdoc resolves against the app origin (localhost:8000), where FastAPI has no
/js/fp.js route, so current previews normally receive a 404 and do not beacon into the proxy. This is
useful because previewing should not create honeypot evidence, but it is incidental rather than an
explicit preview mode. Unescaped model-authored HTML installed into a template could execute in this
same-origin unsandboxed preview; generated prose is passed into HTML without escaping.

21.4  ANALYTICS PAGE QUERY COST AND PAGINATION
----------------------------------------------
One GET /logs can spawn several separate `docker compose exec ... psql` processes: filter options,
request page, browser/TCP summary queries, plus file reads for graph state. There is no request-level
DB connection reuse or cache. The landing page's 10-second stats polling likewise shells out for
request and fingerprint counts. This is simple but expensive at scale.

request_log clamps page >=1 and page_size to 25..500. main.logs_page calculates page_count using the
unclamped incoming page_size. A crafted `?page_size=0` can divide by zero even though the service would
have clamped it; negative/custom sizes can make UI pagination disagree with returned rows. The normal
select offers only 50/100/250/500 and avoids this.

CSV export exports only the selected page, not the whole filtered dataset, and intentionally disables
fingerprint enrichment. On query failure it returns HTTP 200 with a CSV-like `error,<message>` line;
clients must inspect content rather than rely on status.

21.5  EXACT LANDING METRIC SEMANTICS
------------------------------------
  sites_live ............ number of rendered canonical proxy routes, not healthy sites.
  sites_configured ...... number of configs/sites/*.yaml files.
  llm_models ............ length of DEFAULT_TARGET_MODELS, not number with valid credentials.
  query_runs ............ number of readable JSON files, including failed runs.
  queries_completed ..... non-error PER-MODEL result count across detection runs—not questions.
  matches_found ......... leaked per-model result count across all saved detection runs.
  best_score ............ maximum saved best-row Jaccard across those results.
  requests_logged ....... current all_visits row count, None if query unavailable.
  device_fingerprints ... browser_fingerprints row/beacon count, potentially two per page view.
  unique_devices ........ distinct fp_id count; null fp_id does not count as a device.
  campaigns/disguised/contradictions ... values from the last campaigns.json, possibly stale
                                        relative to live traffic.

21.6  MODEL PICKER AND PROVIDER ROUTING
--------------------------------------
_forensics_models unions DEFAULT_TARGET_MODELS with timeline entries by ID. An entry may appear
available in the timeline and still lack a key; `available` is metadata, while provider_status checks
keys. Mock entries are prechecked. If no checkbox is submitted, detection defaults to the two mocks;
provenance defaults to every timeline entry marked available.

Prefix routing is exact:
  mock/... -> offline; openrouter/... strips prefix; anthropic/... strips prefix; bare ID uses
  QUERY_TARGET_PROVIDER. Browsing=True only changes Anthropic requests. OpenRouter ignores browsing,
  and mocks do not simulate a real live fetch. Review this before interpreting a cross-provider RAG run.

Each model/question call catches its own exception in llm_responses, so later questions/models proceed.
The pipeline then combines successful answers. A model with one success and two errors is represented
as a normal result; the errors are not persisted in that successful result.

21.7  RUN/REPORT FILE SEMANTICS
------------------------------
Detection run starts as status=running in memory but is saved only once at the end, completed or failed.
There is no on-disk running heartbeat. A process crash before save leaves no run; a crash during JSON
write can leave malformed JSON, which list_runs silently skips.

save_run/save_report write directly to the final path, not temp+atomic rename. list functions skip corrupt
files. IDs combine second-resolution UTC timestamp with two random bytes (four hex characters), making
collision unlikely but not impossible. load functions interpolate caller-supplied run_id into a Path
without an allowlist; the local-only trust boundary currently carries that risk.

21.8  RAG “PAGE REMOVED” AND LIVE-FETCH CORRELATION
--------------------------------------------------
page_removed is a form/CLI assertion. The code does not stop the site or verify absence. In fact it still
calls parser first; if unavailable it substitutes “the requested subject” and continues only because the
ground truth can be read from DB/CSV.

_live_fetches counts every non-probe all_visits request for the site since the browsing-off phase began.
It does not prove the request belongs to the tested provider; an unrelated visitor during the window is
a false correlation. It also queries after both browsing-off and browsing-on calls, so timing is broad.
The strongest current RAG evidence is therefore leak only with browsing on PLUS a plausibly attributed
concurrent fetch, reviewed in raw logs—not the boolean alone.

22.3  STANDALONE GNN COMMAND IS NOT THE SAME AS `build --gnn`
------------------------------------------------------------
pipeline.run_intel joins TLS, TCP, browser fingerprints, runs consistency, then builds all 22 features.
cli.cmd_gnn_train currently fetches visits+TLS only; it does not fetch/join TCP or browser fingerprints
and does not call consistency.annotate. Newer feature columns therefore become zeros/defaults in the
standalone training path. Prefer `python -m crawler_graph build --gnn` for full-layer training unless the
standalone command is brought into parity.

22.3A  TRAINING-LOOP SUBTLETIES
-------------------------------
  - build_example truncates full_ids and labels to seq_len after masking the prompt. If the prompt itself
    consumes the whole budget, the example can contain no supervised assistant labels. There is no
    explicit “at least one non--100 label” validation.
  - Optimizer stepping occurs only when the GLOBAL micro counter is exactly divisible by grad_accum.
    Leftover gradients at the very end are never stepped. Because micro is not reset per epoch, leftovers
    can carry into the next epoch, but final leftovers are discarded. steps_per_epoch uses ceil, so the
    scheduler's calculated total can exceed actual optimizer steps for non-divisible data.
  - warmup_steps is at least 10 even if total_steps is below 10. Very short demo runs can spend their entire
    life in warmup instead of the intended warmup-then-cosine schedule.
  - Validation is the first n_val records after a deterministic shuffle; DataLoader then shuffles training.
    No early stopping uses validation loss. Checkpointing is periodic plus final, not best-validation.
  - float16 keeps trainable LoRA parameters in fp32 but the base weights remain float16. No GradScaler is
    used. This is a deliberate memory/stability compromise, not mixed-precision automation.

22.3B  GENERATOR REPRODUCIBILITY AND INSTALL RACES
--------------------------------------------------
  - run_generate seeds torch only under `if args.seed`. Seed 0—the CLI default and a valid UI submission—
    is falsey, so model sampling is not explicitly seeded. Assembly still uses Random(0+i), producing a
    deterministic structure around potentially nondeterministic prose. A nonzero seed is the reliable path.
  - _install_generated computes the set of taken versions once and copies with shutil.copyfile. Two
    simultaneous generation requests can both choose the same “next free” slot and overwrite each other;
    “never overwrite” holds only without concurrent installers.
  - Installation validates filename pattern only. It does not parse Jinja, enforce var1..var10 bounds,
    require fp.js, reject script tags, or verify that every referenced slot has an appropriate expression.
  - app/services/template_gen.py's module docstring says the ML stack is deliberately not baked into the
    app, but app/Dockerfile now does bake torch/transformers/peft. The executable behavior and Dockerfile
    supersede that stale comment.

22.4  HEURISTICS NAMED MORE STRONGLY THAN THEIR EVIDENCE
-------------------------------------------------------
  - Web comments call shared canvas/WebGL “the SAME physical machine.” In reality collisions, cloned
    images, privacy defenses, and software renderers make it strong correlation, not identity proof.
  - infer_os maps every unresolved TTL<=64 Unix-like shape to Linux unless the narrow Apple signature
    matches. OS guess is coarse evidence.
  - campaign `confidence` is a rule label, not a calibrated probability.
  - “live fetch detected” is temporal/site correlation, not provider attribution.
  - provenance “latest” is an approximate knowledge cutoff, not a confirmed training-data cutoff.
  - membership “statistical proof” depends on model access, controls, independence, calibration, and
    multiple-testing assumptions beyond the demo.

A senior explanation preserves the useful signal while avoiding categorical overclaiming.

22.5  ADDITIONAL PRODUCTION RISKS
--------------------------------
  - Custom URL probing is server-side request functionality with no scheme/host allowlist; on an exposed
    app it is an SSRF primitive into networks reachable by the container.
  - Generated model prose is embedded into HTML without escaping/sanitization and previewed in an
    unsandboxed same-origin iframe. Treat adapters/model output as trusted only in this local workflow.
  - No retention policies exist for visits, fingerprints, reports, caches, or model outputs.
  - No DB indexes support all common analytics filters (site/method/text/timestamp), so tables will scan
    as they grow. all_visits only has its primary key unless manually extended.
  - No schema migration framework/version table exists; collectors opportunistically CREATE/ALTER.
  - No application authentication/audit identity ties an action to an operator.
  - Long jobs and append-only JSONL writes lack locks; multi-worker/multi-user behavior is undefined.
  - API/provider requests can contain canary evidence and prompts; data-governance review is required
    before sending institutional evidence to external providers.


================================================================================
 PART 23 — WORKED INCIDENT AND CODE-REVIEW SCENARIOS
================================================================================

23.1  “A BROWSER ROW SAYS NO JS, BUT I SAW THE PAGE”
---------------------------------------------------
Trace in order:
  1. Confirm that exact scraperN.html includes /js/fp.js; do not assume generated templates do.
  2. Browser devtools: did GET /js/fp.js return 200 from Flask? In a preview iframe it normally will not.
  3. Did POST /__fpbeacon occur after ~1.2 s or on pagehide?
  4. Did Host match a per-site nginx block with exact beacon location?
  5. Check fp-collector body size/JSON and DB logs.
  6. Compare beacon and request exact user_agent strings. request_log deliberately refuses IP-only match.
  7. Check timestamps and NAT. The UI chooses nearest exact IP+UA beacon, while graph aggregation is IP-only.

Conclusion vocabulary: “No matching beacon was observed,” not “the user definitely disabled JavaScript.”

23.2  “THE SAME BOT GOT DIFFERENT CANARIES”
-------------------------------------------
Inspect (UA, ASN), not hashed IP. UA version/string changes split identity. ASN changes split identity.
RDAP failure can change a known ASN to None and select a different row. Site/scraper version means a
different per-site database. A reset destroys history. Concurrent duplicate rows can make `.first()`
unstable. Only after checking these should you suspect set_vars stability.

23.3  “A LEAK SCORE DROPPED WHEN THE MODEL REVEALED MORE”
-------------------------------------------------------
Let ground truth C have ten values. Answer A extracts three correct values and nothing else:
intersection=3, union=10, Jaccard=.3 -> threshold crossing. Answer B extracts those same three plus ten
unrelated values: intersection=3, union=20, Jaccard=.15 -> no crossing. Exact-set Jaccard penalizes extra
evidence. Review matched tokens and raw extraction, not only headline score.

23.4  “ONE DEVICE BECAME FOUR IPs IN ONE CAMPAIGN”
-------------------------------------------------
Each IP aggregates its requests. Identical fp_id creates an fpid hub of weight 7. All four IPs attach;
community detection groups them even if ASN/netblock differs. If multiple ASNs and one cohesive fp_id,
shared_device_fingerprint adds a disguise reason. This is a correlation hypothesis; verify timestamps,
renderer/canvas, UA, and whether a cloned automation image could explain it.

23.5  “WINDOW SAYS INGESTED BEFORE THE PAGE EXISTED”
---------------------------------------------------
Check crawl_first_seen timezone/date conversion, model cutoff metadata, and whether the detected canary
row actually maps to the crawler key. The code permits negative latency and month cutoffs become day 1.
Mock cutoffs are excluded. Correct interpretation may be bad metadata, live retrieval, natural collision,
or faulty extraction—not time travel.

23.6  “DEPLOY SAID SUCCESS, HOSTNAME FAILS”
------------------------------------------
Success may mean compose up succeeded while nginx reload failed silently. Check:
  rendered proxy conf -> nginx container exists -> `nginx -t` -> reload -> proxy_net membership ->
  site-NNN-web alias -> container health -> browser Host/DNS. The UI “Live” badge only sees the conf file.

23.7  “GNN ATTRIBUTED EVERYTHING TO ONE PROVIDER”
------------------------------------------------
Current trainer should skip exactly one declared class. If two classes technically exist, inspect extreme
imbalance, labeled counts per class, validation size, feature scaling, graph hubs, and confidence. Campaigns
do not threshold confidence. Compare community-only output (`build` without --gnn) and declared/range
evidence before accepting the attribution.

23.8  CODE REVIEW CHECKLIST FOR A NEW FEATURE
--------------------------------------------
  - Which store is authoritative? What is generated vs source?
  - What exact key joins the new data, and what happens behind NAT/clock skew?
  - Is the value trusted, self-reported, inferred, or learned?
  - Does absence mean negative evidence or collection failure?
  - Is write atomic? What partial state remains after failure?
  - What happens under two requests/workers?
  - Which import-time configuration must restart to change?
  - Does local-only trust become dangerous if :8000 is exposed?
  - Which offline test proves logic, and which live test proves wiring?
  - What old artifact/schema/checkpoint becomes incompatible?


================================================================================
 PART 24 — MASTERY QUESTIONS WITH CONCISE ANSWERS
================================================================================

Q: Why are there two databases per architecture, not one?
A: Each site DB owns canary assignments/raw site visits; central logdb owns cross-site proxy and
   fingerprint telemetry. They have different isolation and query purposes.

Q: Why key canaries by UA+ASN instead of IP?
A: It survives IP rotation within provider infrastructure, but trades off NAT/UA collision and ASN-change
   splits. It is a heuristic identity key.

Q: Why mirror at nginx if Flask already logs visits?
A: Central logging observes all matched methods/paths across sites independently of app success and adds
   source-port/header context needed for fingerprint joins.

Q: Why overwrite XFF?
A: Flask trusts its first value for identity. Appending an attacker-controlled header would enable spoofing.

Q: Why can collector failure be invisible to visitors?
A: The mirror is deliberately best-effort; telemetry availability must not block honeypot content delivery.

Q: Why use client source port?
A: IP+port links HTTP request to the TLS ClientHello/TCP SYN connection; IP alone is ambiguous.

Q: Why not join the browser beacon by source port?
A: It is a separate HTTP connection. UI uses exact IP+UA plus nearest time; graph uses IP aggregation.

Q: What is the strongest graph key?
A: Composite fp_id weight 7 by configuration, followed by canvas/WebGL weight 6. Evidence strength is still
   empirical, not cryptographic.

Q: Why discard giant attribute hubs?
A: A huge ASN/common UA links unrelated actors and makes both clustering and O(k²) projection noisy/costly.

Q: Why are declared crawler UAs useful if UAs are spoofable?
A: They are high-precision seeds when corroborated, and published range checks can expose impersonation.

Q: When is TCP OS ignored?
A: For private/loopback/link-local/unspecified/reserved sources unless INTEL_TRUST_PRIVATE_TCP=1, because
   local Docker/NAT often exposes the proxy host kernel rather than remote client.

Q: What makes an endpoint inconsistent?
A: Weighted reasons sum to >=3 by default; one trusted UA-vs-TCP contradiction alone reaches 3, while no-JS
   alone contributes only 1.

Q: Does GraphSAGE discover campaign communities?
A: No in the main path. Community algorithms partition the bipartite identity graph; GraphSAGE predicts
   provider labels on the projected IP graph.

Q: Why require two GNN classes?
A: A one-class softmax trivially predicts that provider for every node and creates meaningless confidence.

Q: Does the GNN use edge weights?
A: Not currently. Weights affect graph/community construction, but SAGEConv receives edge_index only.

Q: Why can one page view create two fingerprint rows?
A: fp.js sends a load snapshot and one unload behavioral snapshot.

Q: What does a 0.3 leak threshold mean?
A: At least configured exact-set Jaccard 0.3 against the best ground-truth row; it is a policy threshold,
   not automatically a p-value or probability.

Q: Why scrape before loading local ground truth?
A: The probe visit itself causes the honeypot to mint/store its canary row; loading afterward includes it.

Q: Why prefer the probe UA's ground-truth row for mocks?
A: It makes the simulated leaked values correspond to the actual row created by that scrape.

Q: Can a clean answer prove no ingestion?
A: No. The model may refuse, paraphrase, not retrieve, or evade exact extraction. It is “no observed leak.”

Q: What separates memorization from RAG here?
A: Leakage with browsing disabled supports memory; browsing-only leakage plus a correlated live fetch
   supports retrieval. Correlation and provider tool support must be reviewed.

Q: What is Min-K measuring?
A: Whether the model assigns unusually high probability even to the text's least-likely tokens, compared
   between served and control documents.

Q: Why are knowledge cutoffs only bounds?
A: They are approximate model metadata, not exact scrape/training boundaries, and release pipelines vary.

Q: What survives `reset_db=true`?
A: Central logdb and file reports survive; that site's pgdata—new_visits and canary assignments—is removed.

Q: What does “Live” in Sites actually prove?
A: Only that a rendered proxy route file names the site, not that nginx/container/network is healthy.

Q: Why is path mirroring necessary?
A: Docker commands run inside the app but target the host daemon; identical absolute paths keep build
   contexts and rendered compose references meaningful to both.

Q: Why is the app not safe to expose publicly?
A: No auth/CSRF, Docker socket/Ansible authority, config writes, SSRF-capable custom URLs, and long jobs.

Q: What two generator integration gaps matter most?
A: Generated HTML currently omits fp.js, and its typed varList is not installed; Ansible replaces it with
   global expressions.

Q: Which command runs full-layer GNN analysis?
A: `python -m crawler_graph build --gnn` (or UI recompute with GNN), not the currently incomplete standalone
   `gnn-train` feature path.

Q: What is the first question when a metric looks wrong?
A: “Which store and timestamp produced it?” Live SQL, per-site DB, process cache, and persisted report can
   all show different but internally valid snapshots.


================================================================================
 PART 25 — DOCKER NETWORKING, PACKET IDENTITY, AND PORT EXPOSURE
================================================================================

25.1  NETWORK MEMBERSHIP MATRIX
-------------------------------
Proxy Compose default network:
  nginx, collector, fp-collector, tls-shipper, logdb (and certgen's default attachment).
  Service DNS names such as collector, fp-collector, and logdb resolve here.

External proxy_net:
  proxy nginx, unified app, and every per-site web service. Per-site web uses the unique
  alias `<site_id>-web`; bare `web` would collide across projects.

Each site's private default network:
  only that site's web and db. The web can resolve `db`; nginx/app cannot directly reach
  the site's database. DB queries go through Docker exec, not TCP across proxy_net.

App Compose default network:
  only the app unless extended. The app is dual-homed onto its private default and proxy_net.

tls-capture:
  network_mode=service:nginx means it shares nginx's network namespace/interfaces and cannot
  declare its own networks. NET_RAW/NET_ADMIN let Zeek capture there.

Important correction to comments in crawler_graph/config.py: current logdb is NOT attached to
proxy_net, so setting LOGDB_HOST=logdb in the app container will not resolve with the checked-in
compose topology. The normal Docker-exec path works. Direct TCP requires attaching logdb to a
network shared with the caller (and considering credential/exposure policy).

25.2  HOST PORTS
----------------
  nginx ............... 80:80 and 443:443, all host interfaces by default.
  unified app ......... 8000:8000, all host interfaces by default.
  each site web ....... 127.0.0.1:<unique>:8080, intentionally loopback only.
  each site Postgres .. <unique>:5432 with no host-IP prefix, therefore typically all host
                         interfaces. This is a wider exposure than the web debug binding and
                         should be restricted/firewalled in any nonlocal deployment.
  central logdb ....... no published host port.
  collectors/shipper .. no published host port.

Container `expose` documentation is not an access-control boundary; network membership and published
ports determine reachability.

25.3  DNS AND LATE RESOLUTION
-----------------------------
nginx uses Docker DNS 127.0.0.11 with valid=10s. A literal hostname in proxy_pass is normally resolved
when nginx loads configuration and can make reload fail if the target is absent. The templates assign
the hostname to a variable (`set $upstream ...`) and then use variable proxy_pass, deferring lookup to
request time. The same technique protects collector/fp-collector reloads.

Explicit `$request_uri` preserves path+query when variable proxy_pass is used. Without careful URI
construction, nginx's variable/literal proxy_pass URI replacement rules can unexpectedly strip or
duplicate path segments.

25.4  THREE DIFFERENT “SITE” VALUES
-----------------------------------
  nginx access-log `site` = `$host`, the normalized incoming Host. It can be canonical `.example`
    or browser alias `.localhost`.
  central all_visits.site = `$site_name`, the canonical value rendered into the server block.
  per-site DB has no site column because the database itself defines site ownership.

This is why access-log and all_visits site strings can differ for the same request without either being
wrong. Analytics uses the canonical central value.

25.5  TLS SNI, HTTP HOST, AND UNMATCHED TRAFFIC
----------------------------------------------
TLS SNI selects a certificate/server context before encrypted HTTP exists. The certificate is global,
so all site blocks inherit it. After decryption nginx uses Host for virtual hosting. SNI and Host can
differ; Zeek stores SNI while all_visits reflects the Host-matched canonical route. That disagreement
can itself be forensic context, though no current consistency rule scores it.

The default HTTPS server still completes TLS before returning 444. Therefore Zeek can store TLS and TCP
fingerprints for unmatched scanners even though nginx intentionally creates no all_visits row. TCPFP
captures inbound SYNs to both 80 and 443, not only TLS. Crawler_graph starts from all_visits and only
attaches matching fingerprints, so orphan scan fingerprints do not become endpoints/campaigns.

25.6  WHAT SOURCE IP/PORT MEANS THROUGH DOCKER
----------------------------------------------
On native Linux iptables DNAT often preserves the remote source into nginx. Docker Desktop/userland
forwarders may replace it with an internal hop. nginx `$remote_addr/$remote_port`, Zeek orig_h/orig_p,
and Flask XFF are only true remote identity when the topology preserves them.

Verification procedure:
  compare nginx JSON client_ip/client_port -> all_visits -> Zeek ssl/tcp tuple for one controlled HTTPS
  request. If addresses differ, 4-tuple joins cannot work reliably. Move capture to the host/source-
  preserving edge or carry trusted proxy metadata. Never “fix” the mismatch by trusting arbitrary client
  headers.

25.7  MIRROR VS MAIN REQUEST
----------------------------
`mirror /_mirror` creates an internal subrequest. mirror_request_body off prevents buffering/replaying the
client body. The snippet does not explicitly force GET; collector supports and records every listed HTTP
method. The main upstream request and mirror are independent: mirror timeouts/errors do not determine the
Flask response. `/__fpbeacon` has its own exact location and is intentionally neither mirrored nor sent to
Flask, preventing beacon recursion/noise in all_visits.


================================================================================
 PART 26 — FRONTEND RENDERING, CSS, DEPENDENCIES, AND ACCESSIBILITY
================================================================================

26.1  SERVER RENDERING AND ESCAPING
-----------------------------------
Jinja autoescaping protects ordinary variables such as model answers, Ansible output, UAs, and report
strings when inserted into HTML. `tojson` safely serializes structured values for display. Source previews
use textContent for the code block, which does not interpret markup.

The separate iframe.srcdoc path intentionally interprets the fetched template as HTML. That bypasses the
safe source-display behavior and is why generated HTML must be treated as executable content. No Content
Security Policy or iframe sandbox is configured.

26.2  CSS/THEMING LAYERS
------------------------
Layout utilities come from the Tailwind Play CDN configured inline in base.html. Branded reusable
components and semantic tokens come from local app/static/css/app.css. There is no build-time Tailwind
purge/bundle. If the CDN is unavailable, local cards/buttons/colors remain, but many grid/flex/spacing/
responsive utility classes stop working.

Source Sans 3 also comes from Google Fonts. Failure falls back to system-ui and does not break function.
Both external resources have privacy/offline/CSP implications.

app.css defines literal brand primitives and themeable semantics:
  --surface, --heading, --link plus neutral background/text/border tokens change in dark mode;
  Duke navy/royal and status accents stay fixed. Components consume semantic tokens so the same class
  works in both modes. A few inline colors/rgba values in templates bypass this abstraction and require
  manual dark-mode review.

26.3  THEME BOOT ORDER
----------------------
An inline head script reads localStorage or prefers-color-scheme before paint and sets data-theme. This
avoids a light-to-dark flash. Failures (private storage/security exceptions) are caught; CSS defaults to
light. The footer script toggles the attribute and best-effort persists it. There is no listener for a
system theme change after initial load.

26.4  RESPONSIVE AND TABLE BEHAVIOR
-----------------------------------
`.wrap` caps content at 1180 px. Tailwind responsive grid classes rearrange forms/cards by breakpoint.
`.table-wrap` scrolls overflowing tables; sticky headers stay visible inside that scroll context. Truncate
classes preserve compact rows and rely on title attributes/details expansions for full evidence.

Campaign graph HTML is a complete generated document served into an iframe. It uses an SVG viewBox,
precomputed coordinates, per-campaign colors, DOM hover handlers, and an HTML tooltip/rundown. It does
not query the server after load; recompute must regenerate the file, and the iframe query timestamp is a
cache-buster.

26.5  ACCESSIBILITY STATE
-------------------------
Positive details:
  semantic headings/tables/forms are widely used; theme button has aria-label/title; graph iframe has a
  title; status is usually accompanied by text, not color alone; buttons are real button elements.

Gaps to know before claiming accessibility compliance:
  preview iframes lack sandbox and explicit title; many labels are visually adjacent but lack `for`/id
  association; custom segmented controls do not expose tab/aria-selected semantics; expandable table
  details and SVG graph interactions are mouse-oriented; external color/inline styles need contrast audit;
  no skip link or automated WCAG test is present. The project has useful semantics but no demonstrated
  conformance level.

26.6  CLIENT-SIDE JAVASCRIPT SCOPE
----------------------------------
The administrative UI intentionally has little JS: theme toggle, 10-second stats polling, local/custom
form toggle, template fetch/preview, and graph hover. There is no client application state framework.
Business decisions remain server-side, which simplifies debugging: inspect the form request, route, service,
and rendered context. fp.js is separate visitor-side instrumentation and should not be confused with admin
UI JavaScript.


================================================================================
 APPENDIX B — HOW TO EXPLAIN ANY BLOCK OF CODE
================================================================================

For any block, answer these seven questions in order:
  1. INPUT: What exact values/types enter, and who controls them?
  2. OUTPUT: What exact value/state/side effect leaves?
  3. INVARIANT: What must remain true for downstream code?
  4. OWNER: Which module/database/file is authoritative for that state?
  5. FAILURE: Is the failure raised, returned, persisted, logged, retried, or swallowed?
  6. CONCURRENCY: Can two requests/jobs execute it together, and is the operation atomic?
  7. EVIDENCE: Which test proves the behavior, and what real integration does that test omit?

Example — request_log's browser LATERAL join:
  INPUT is one all_visits row. OUTPUT is at most one nearest browser_fingerprints row. The invariant is
  exact same client_ip AND exact same user_agent. logdb owns both rows. Missing tables trigger staged
  fallback; query failures otherwise raise RequestLogError and the page displays it. SQL handles many
  rows consistently, though a beacon equally near in time is tie-broken by newest timestamp. Offline
  analytics tests prove SQL/fallback/verdict plumbing; live fingerprint tests prove actual persistence.

Example — set_vars:
  INPUT is ten trusted expression strings and a DB session. OUTPUT is a ten-string candidate tuple. The
  invariant is intended global tuple uniqueness. new_agents_vars owns observed assignments. eval or DB
  errors propagate and can leave the earlier visit commit intact. Check-then-insert is race-prone because
  no database UNIQUE constraint completes the invariant. Honeypot tests prove sequential uniqueness, not
  concurrent serializability.

Example — consistency.score_endpoint:
  INPUT is one aggregated endpoint with claimed UA, JS, TCP, renderer, automation, and behavior signals.
  OUTPUT is reasons, weighted score, flags, and normalized OS fields; it does not mutate until annotate
  assigns the result. The invariant is conservative TCP trust and threshold-based inconsistency. Bad or
  missing signals normally degrade to None/false, not exceptions. It is pure per endpoint and parallel-safe.
  Fingerprinting tests prove representative contradictions and controls; deployment topology determines
  whether the TCP evidence truly describes the remote client.

If you can answer all seven without vague phrases such as “it handles the data,” you understand the block
at the level expected in a senior code review.
